## 开发者使用方式

首次由管理员配置内网授权环境及本地运行程序。之后开发者登录本地 Demo，点击顶栏「更新演示数据」，不再手动执行 worker、下载、解压或导入。默认获取截至昨天的最近 7 个自然日，管理员可配置 1—31 天。范围仍由内网环境和客户端授权限定。

程序自动提交内网任务、等待快照、下载并检查 ZIP、克隆干净的本地模板库、执行迁移及 dry-run/事务导入、启动并检查新后端，成功后保存数据库指针并刷新页面。更新期间经本地入口的业务写入暂停；切换阶段短暂暂停全部业务请求。失败保留原库；「回滚演示数据」可切回上一工作库。旧库手工测试修改不会合并进新库。

## 一次性内网配置

继续使用 config.settings.demo_sync_service、独立 saas_collab_sync_ 管理库、批准的只读客户端、私有快照目录和 HTTPS。不得把阿里云原业务实例的数据库切换为管理库。内网服务以受监督进程启动：

```sh
python manage.py work_demo_snapshots --poll-seconds 5
```

该命令默认不能运行：必须显式开启同步与 worker，且处于内网服务角色；只处理 queued，不自动重试失败任务。支持 --once 处理最多一个任务。并行进程抢占同批时只有一个能够执行；初期配置一个 worker 控制源负载。进程异常由既有服务管理器重启，超过心跳租约的任务沿用页面重试入口，不自动跳过错误。

为开发者创建其负责的内网环境并授予原 view/run/download 权限；本地运行程序使用该开发者在内网服务的 JWT，不使用生产只读 client 密钥。凭据撤销、过期或权限不足会明确失败，不降级为假数据。

## 一次性本地配置

此程序只用于个人电脑上的单用户可丢弃 Demo，不替代生产/共享环境部署。依赖同提交 Python 后端、Node 构建产物和本机 MySQL；安装 backend/requirements.txt。MySQL 工具 mysql/mysqldump 需在 PATH；若使用本机 Docker MySQL，可在配置中指定 mysql_tools_container 为该容器名。

管理员先建立两个独立本地库：initial_database 为当前 Demo；template_database 为经过审核的干净初始化模板。模板应包含本地租户、开发者账号及其最小权限，不能含业务快照、同步环境/任务、平台配置或业务同步任务。程序检查这些关键表为空再复制；其他业务模块也须由模板制作人确认仅有初始化数据，禁止从生产库复制模板。模板与初始库使用相同的 tenant_id、actor_id 和本地登录信息；不能直接把有测试数据的旧工作库当作模板。

本地数据库账号仅授予所需 saas_collab_demo_ 库的建库、迁移、读写权限，不使用生产账号。配置文件不含密码，参考 runtime.example.json。state_directory 和日志/模板转储/快照仅允许本机开发者访问（Linux 0700；Windows 使用该用户私有目录 ACL）。磁盘不足会在建库前停止，不会自动删除旧库。

通过既有秘密注入方式设置 DB_ENGINE=django.db.backends.mysql、DB_HOST=127.0.0.1、DB_PORT、DB_USER、DB_PASSWORD、固定的 DJANGO_SECRET_KEY、DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1，以及 DEMO_INTRANET_REFRESH_TOKEN（优先）或短期 DEMO_INTRANET_ACCESS_TOKEN。JWT 只留在本地进程环境，不写配置或前端。过期失效后由开发者按既有登录流程重新取得授权，不持久保存明文账号密码。

构建与启动：

```sh
# frontend 目录：必须同源，API 地址为空，真实 API 模式
VITE_API_BASE_URL='' VITE_USE_MOCK=false npm run build
# 项目根：配置文件由管理员按本机实际路径保存
python tools/demo_local_runtime.py --config /private/runtime.json
```

浏览器访问 http://127.0.0.1:5182/（以实际 port 为准），不要继续使用独立 Vite 入口或直接访问 backend_port。运行程序仅监听 127.0.0.1，限制 Host/Origin，更新接口仍需登录和 run/download 权限，并绑定配置的本地开发者及租户。程序管理自己的单个 Django runserver --noreload 子进程；不启动业务 Celery/beat，不修改项目 .env、生产 Compose 或系统数据库服务。程序拒绝已占用的后端端口，不终止未知进程。

## 恢复与限制

active.json 仅在新后端的数据库和启动身份健康检查通过后原子写入；普通启动/导入失败恢复旧库。正常退出会停止其管理的后端。断电、强杀或操作系统崩溃时仍保留工作库；若存在残留子进程，重启会因端口占用停止，管理员核对所属进程后清理再启动，不自动杀未知进程。进程不提供跨机器高可用或断电自动续跑。

更新失败的候选库、旧库、下载和日志保留供诊断；管理员按保留策略清理，必须避开 active.json 的 active/previous 和模板库。没有自动删库。内网请求等待最多 30 分钟，页面轮询最多约 40 分钟；超时不代表服务端任务已取消，先核对任务状态再重试。

## 验证证据

本机 MySQL 8.4.11 / 合成源 HTTPS 实测自动任务、10 行快照、2 单订单、新库启用与回滚成功，见 local-runtime-validation.json；写暂停 503、重复更新 409、跨源请求 403 见 local-http-safety.json。没有真实生产数据流入本地。

自动化检查：原 demo_sync 加自动 worker 32 项、本地授权 3 项、本地运行程序 16 项、前端相关 16 项；前端构建、Django check 和迁移漂移检查通过。16 项本地测试包含 ZIP 路径拒绝、失败不切换、激活失败恢复、代理隔离及端口冲突。生产正常角色界面、真实内网证书/授权和大数据量性能仍需部署后验收。

本轮重复测试曾耗尽旧合成 MySQL 容器的 768MiB tmpfs，候选导入停止且 active 指针未切换。仅对该测试容器扩容至 1536MiB tmpfs / 3GiB 内存后继续验证；没有扩容或修改其他容器。产品新增容器 MySQL 存储预检（低于 256MiB 时在建库前拒绝），非 Docker 本机实例可配置 mysql_data_directory 检查独立数据盘；仍须预留足够存储并管理旧库保留周期。数据库服务自身磁盘耗尽可能影响所有工作库的可用性，保留原库不等于底层数据库故障时仍可正常读写。

业务写入暂停期间保留登录/令牌续期入口，避免长任务超过本地 JWT 有效期后无法继续跟踪。对应 HTTP 回归已验证。内网等待采用 30 分钟时钟上限，最后一个网络请求可能增加其连接/读取超时时间。
