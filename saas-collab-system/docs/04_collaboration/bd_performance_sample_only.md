# BD 绩效：仅以送样记录归属

## 业务口径

建联任务用于管理分工、目标和进度，不参与 BD 绩效计算。报表不再按任务主负责人、任务创建时间或任务删除状态统计建联任务数量。

绩效归属链路为：联盟订单 -> 匹配送样归因快照 -> 送样快照中的 BD 负责人。

- 送样记录数：当前租户、送样记录未删除、快照 `sampled_at` 在查询日期范围内的记录数。关联任务与独立送样一视同仁。
- 投入：上述送样快照的冻结成本 `cost_amount`，按业务日期换算到展示币种后求和。缺失成本不推算。
- 有效订单：在查询日期范围内、已完成且非整单退款、成功归因到未删除送样记录的联盟订单，按既有订单去重规则计数。
- GMV：上述订单去重后的付款金额，按订单业务日期换算到展示币种后求和。
- ROI：查询期间 GMV / 查询期间送样投入。投入为 0 时返回空值，不做除零计算。
- BD 成员：有上述送样或订单事实的负责人；只有建联任务、没有送样和已归因订单的人员不进入报表。

保留原有严格匹配“达人 + 店铺 + 商品”和宽松匹配“达人 + 店铺”规则。订单仍匹配订单时间之前最近一次符合条件的送样记录；允许历史月份送样贡献本月订单，因此本月送样数为 0 不代表本月 GMV 必须为 0。

建联任务完成、取消、删除、改派负责人或创建时间不在查询范围内，都不应排除已存在的有效送样快照及其订单。送样记录本身被删除仍须排除，租户隔离仍须保留。

## 接口与界面变更

- `build_bd_performance` 移除任务聚合查询，归因刷新和送样快照补建也不再按建联任务删除状态筛选。
- BD 绩效接口行与汇总不再返回 `task_count`、`outreach_tasks`、`linked_count`。
- 核心/完整指标视图及前后端 CSV 移除“建联任务”“已建联”列。
- 建联任务管理、送样创建规则、菜单和权限不变；不删除任务或送样业务数据，不需要数据库结构迁移。

## 上线注意

前后端须一起更新；仍依赖上述移除字段的外部调用方应同步调整。

本次代码修改不会自动补写服务器业务数据。若历史归因曾因任务删除被排除，部署后需由运维在确认备份、数据范围和变更规模后补建缺失送样快照、刷新订单归因，再验收报表。归因刷新可能清理旧的派生归因记录，不能未经确认直接执行大范围重算。
