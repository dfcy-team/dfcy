# 同线路多报价与分批集货

采购可在同一运输渠道分别维护按方、20GP、40HQ 等方案。每个方案独立取已生效的最新版本；新版本到期后不会恢复旧价格。创建批次时明确选择方案，保存后冻结该版本的价格、柜型和税点，后续报价维护不会改写已有批次。

创建或调整尚未开船的集货批次时，按发货单商品行填写本批数量。页面显示原发货量、已分配量、剩余量和本批量。零数量行不加入批次，每张选中的发货单至少保留一个正数商品行。减少数量、移除发货单或取消批次后，数量重新可供其他批次选择。开船后数量冻结。

例如发货 100 件，第一批选择 60 件，第二批最多选择 40 件。第一批到仓生成 60 件应收的入库单，第二批独立跟踪物流并生成 40 件应收的入库单。供应商仍只能看到自己发货单的商品和数量，可以查看这些货物各批次的运输节点；批次详情继续按完整批次的数据范围鉴权。

采购货值按本批数量计算。发货单国内费用先按既有体积/重量规则分摊到商品，再按商品分批数量分配；累计舍入保留尾差，全部批次加未分配部分的费用总额等于原商品费用。批次运费、入库清货费按各自数量分摊。改价、改费用或调整分配后，旧成本标记待重算，历史结果保留。整张发货单的到仓账期须等全部数量到仓，以最后到仓时间起算。

## 接口与数据

- 渠道返回 `current_quotes`，每个计费方式/柜型一个当前版本。`current_quote` 仅在唯一方案时返回值；多个方案不隐式代选。
- 创建批次及调整成员接口增加 `allocations: [{shipment_line_id, quantity}]`；调整仍使用 `POST .../members/`，携带批次、发货单版本和调整原因。
- 发货单商品行增加 `allocated_quantity`、`remaining_quantity`。批次商品行 `quantity` 为本批数量，`source_quantity` 为原发货数量，`available_quantity` 为编辑时可分配上限。批次发货单的 `allocation_lines` 提供本单全部商品及 `current_batch_quantity`，编辑器无需依赖候选首页即可追加该单余量，未入本批的商品默认 0。
- 发货单增加 `dispatch_allocations`，按批次给出本单分配数量、商品行和运输节点。部分/多批发运的汇总状态为 `split`，不再任选一个批次覆盖整张发货单状态。
- `DispatchMembership` 保留批次与发货单关系及历史；新增 `DispatchAllocation` 保留商品行数量。有效分配总量在租户事务锁下校验，防止并发重复占用。

## 升级与验收

迁移 `0026_dispatch_line_allocations` 将原整单集货关系按原有效商品行数量回填，单据编号、原发货量和历史关系不变。该迁移不提供逆向删除数量分配；已产生分批数据后不得退回仅支持整单独占的旧应用。部署前按受控发布流程备份，恢复方案需覆盖应用与数据库的一致性。

验收覆盖多报价并存及独立更新、选中报价落库、100 件拆为 60/40 件、超分配和非法商品拒绝、减少/取消释放数量、分批入库、费用守恒、历史关系回填与供应商只查看本单分配行。实际部署、版本登记和生产数据库并发验证应以发布回执为准。
