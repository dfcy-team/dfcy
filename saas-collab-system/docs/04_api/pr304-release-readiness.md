# PR304 发布就绪与回退

本补丁修复增量归因在租户写锁内遍历所有历史归因键的问题。订单业务身份按
shop/site/order/SKU 的 strip + casefold 结果生成 SHA-256 摘要；只检索当前批次摘要，
再比较完整业务键。摘要不进入原始事实哈希，不修改订单/送样负责人。

## 新增迁移与派生索引准备

新增 `0038_affiliate_business_identity`，本批未登记迁移由 9 个变为 10 个。
迁移仅增加 nullable 摘要列和 `(tenant_id, business_identity_digest)` 索引；
不在迁移内执行整库回填。索引 DDL 仍需在与生产规模相当的隔离恢复库验证锁等待、
耗时和空间，不能仅凭单元测试放行。

受控升级时应先完成结构迁移，再对批准租户运行派生索引回填，最后切换/启用新归因工作者。
应用实例和后台工作者需统一候选版本。旧实例产生的 NULL 摘要必须在启用前检查并补齐；
新代码发现 NULL 会拒绝刷新，绝不静默漏过历史重复记录。

只读预览（示例 tenant 123 必须替换为实际批准租户）：

```text
python manage.py backfill_affiliate_business_identity --tenant-id 123 --batch-size 500
```

获准后添加 `--apply`，每次最多 1000 条、单批事务；每批输出 passed/partial 和条数。
partial 时由操作者按资源观察继续下一批；没有内置无限循环。已有摘要不会重写，活跃导入租约
期间拒绝应用。保留全部输出作为证据；该工具不是金融字段补齐工具。

## 历史报表门槛

逐月、逐种归因方式做只读检查，区间最长 31 天：

```text
python manage.py check_bd_release_readiness --tenant-id 123 --start-date 2026-08-01 --end-date 2026-08-31 --mode strict
python manage.py check_bd_release_readiness --tenant-id 123 --start-date 2026-08-01 --end-date 2026-08-31 --mode fallback
```

结果只输出聚合计数，不输出人员、账号或原始订单。缺失结算/退款状态、金额、任一佣金、
成本或汇率、未匹配有效订单及未完成派生索引都会使结果 blocked。空月份不会被当成“完整零值”。
这里 passed 仅表示这些覆盖指标齐全，不等于已经通过跨版本金额对账或生产发布准入。

blocked 时先核对原始来源及批准导入范围；禁止将未知结算猜成已结算、NULL 佣金猜成 0。
金融事实补齐使用受审计导入流程，并保留同时间戳冲突策略；再按批准月份执行
`refresh_bd_order_attributions`，核对刷新前后有效订单、归属、各成本、本币及换算金额。
未批准的历史月份和范围外记录不修改。

## 制品和回退

正式通道须重新核对实际父版本、完整迁移树摘要、候选文件清单及前后端固定制品。
现有 production_build_only 的批准摘要保持不变；本补丁不能借用 PR305 的无 DDL 发布凭证。

推荐应用回退保留新增 nullable 字段及派生索引，回到事先验证的旧镜像；其后重新启用新版本前
补齐旧实例新增的 NULL 摘要。保留旧 v1 归因快照和现有汇率/配置历史，不能用删表回退。
0033 无反向函数，0035/0037 反向为 noop，故不承诺整批 migrate backwards。
若需数据库结构/配置回退，必须单独评审并验证完整恢复；完整恢复不得覆盖备份之后的生产业务写入。

## 验证边界

隔离测试覆盖 Unicode/空白等价身份、范围外保护、摘要部分更新、批量写入禁令、幂等分批回填、
回填不改变业务哈希/更新时间、只读就绪输出、MySQL 0033 三种列状态和 50001 条历史归因的单条刷新。
MySQL 测试使用当前模型合成库和指定操作探针，不是生产现有库全迁移链证明。
源数据覆盖、生产规模 DDL、完整备份恢复及精确候选制品证明由正式发布通道收齐后执行最终验收。
