# 平台商品映射确认历史

本次变更记录人工确认映射时的旧 SKU、新 SKU、确认生效时间与操作人。生效时间为服务端确认时刻，代表系统绑定的切换时刻，不代表运营实际换款时刻。

## 处理原则

- 同一商品只是修改平台 SKU 文本时，应保留原内部 SKU，不因文字变化创建或替换商品。
- 确认换成其他商品时，通过现有人工确认接口替换绑定，同时提交旧内部 SKU ID，避免并发覆盖。
- 确认前的订单已有内部 SKU 时，继续保留该归属。历史未绑定订单仍需核对，不能直接按最新映射回填。
- 没有历史记录不代表从未换款，也不能以平台更新时间、同步时间推断真实换款时间。

## 本次范围

详情界面按需读取映射确认历史，列表加载不额外查询历史。确认事务内保存历史，失败时与映射变更一并回滚。

这是人工确认的历史记录能力，尚不是覆盖自动映射、停用与全部订单导入链路的时间区间归集机制。当前不按这些事件自动回填历史订单，不批量修改线上冲突记录。

## 发布与验收

先应用新增数据库迁移，再发布后端和前端。核验首次确认、旧 SKU 替换、重复确认、并发旧值不匹配与事务失败；核验查看历史沿用租户和数据范围权限。正式发布前保留线上已有热修内容，不能用旧镜像覆盖。

本地验证（2026-10-31）：映射流程 14 项、平台同步 15 项、前端映射流程 20 项测试通过；前端构建、Django system check 和迁移一致性检查通过。后端业务测试使用 `--nomigrations` 直接建表；全项目历史迁移初始化未跑完，正式环境数据库升级仍需在发布预演中验证。本次未部署或修改线上绑定。
