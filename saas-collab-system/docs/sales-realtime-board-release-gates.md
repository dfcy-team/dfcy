## 候选范围

基于 V2.44.272（3e304ff4e717c520049431236c81b1b0e3aa4f0c）开发。销售管理新增「实时数据大屏」，路由 `/sales-management/realtime-board`，位于销售工作台之后；新增菜单权限 `menu.sales_management.sales_management_realtime_board.view`，沿用 `sales_management.view` 操作及销售/库存资源范围，广告另用 `analytics.view`。

新增只读接口 `/api/internal/commerce/realtime-board/`，共享URL配置还提供 `/api/internal/sales-management/realtime-board/`。没有新增业务写接口、同步任务、平台调用或第三方依赖。

界面支持销售/订单趋势、店铺销售额/订单量/销售额占比、商品销售额/销量切换、当前共享库存及授权明细下钻。广告费率当前仅在符合条件的Shopee历史日报上返回参考值；当日、缺失或跨平台口径不齐时不计算。共享仓库存不代表店铺独占；库存覆盖天数、小时趋势和昨日同刻比较未启用。

## 架构员执行顺序

1. 核对目标版本与候选基线差异；若目标已经更新，先隔离整合并重跑对应闸门，不能直接覆盖新版本。
2. 审阅候选完整文件清单、菜单/路由/权限顺序及说明，确认角色菜单分配方案。
3. 隔离库迁移预演和真实数据、浏览器性能验收通过后，按现有受控发布流程构建及部署。
4. 数据迁移仅 `permissions/0053_register_sales_realtime_board_menu.py`，登记菜单权限；该迁移不自行授予角色权限、不更改数据范围。既有 `sync_permissions` 命令有兼容授权行为，执行前按系统既有规则审阅其影响。
5. 普通运营角色只分配经审阅的新菜单权限；销售、库存和广告范围沿用既有授权，禁止以看板可见为由扩展业务范围。

没有修改Dockerfile、Compose、镜像标签或应用版本号；镜像与受控发布版本由架构员在验收通过后确定。

## 回退

恢复发布前应用镜像及菜单登记快照。新增菜单迁移的反向操作为noop，保留权限记录；回退后按既有权限生命周期流程将不再登记的菜单退役，保留角色历史，避免直接删除权限及授权关系。没有业务表结构或业务事实变更需要回滚。

## 对账要求

销售采用非取消订单总金额，退款未另扣；订单总量榜含取消，商品榜排除取消。不同币种不相加。销售额占比分母为整币种组销售额，而非Top10合计。共享库存须是已授权、已映射、数量字段明确、最近24小时的成功WMS快照；失映射、歧义和异常不显示为零。预览数据不得写入正式表。
