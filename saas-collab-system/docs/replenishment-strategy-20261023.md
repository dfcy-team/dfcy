# 销售与补货参考改造验收说明

日期：2026-10-23。该文档描述本次实施口径；验证结果和暂未实施项以文末交付记录为准。

## 业务口径

同一国家、普通商品 SKU 统一计算，平台只分析贡献。组合销量按销售时有效构成折算组件，虚拟商品不参与；历史计算快照保留，不批量重算历史业务单据。

新建议使用 `weighted_days_v1`（需求依据 `weighted_replenishment_v1`），不继续使用库存销售比作为新建议参数。HTTP 运营预览拒绝旧算法新增请求；旧域服务保留用于历史快照验证。日均使用截至昨日的完整自然日，数据缺失不补零。默认 7/15/30 天日均按 50%/30%/20% 加权；普通日均模型采用近30天。趋势 `(A7-A30)/A30` 仅展示，分母为零不计算。

人工参数：国家、策略名称、订货间隔 R、预计到仓 L、安全天数 S、销量模型及权重；活动模式填写活动日期和系数。10/45/35 天是飞书迁移候选，需要人工保存确认，不能静默给所有国家启用。库存和供应件数由系统取数。

提醒期 `H1=L+S`，目标期 `H2=L+R+S`。需求为期间每日预测量之和；活动日期乘活动系数，其余日期系数1。采购供应按覆盖期内 ETA 累加，同一采购供应各生命周期不重复。未来预计结余按到货日逐日核对。

`采购落实缺口=max(0,目标需求-可用库存-按期有效采购供应)`。

`新增订货建议=ceil(max(0,目标需求-可用库存-按期有效采购供应-尚未转采购的已提交运营需求-草稿预留))`。

草稿为防重复而预留，单独展示，不能称为已提交需求；编辑草稿排除自身预留，采购落实缺口不减尚未落实的运营需求或草稿。生产、发货、集货、运输、到仓不能重复扣减；拆批必须按分配量计算。已经收货但 WMS 尚未确认归属的供应不直接加为可用库存。

## 页面与权限

供应链设置维护策略；驾驶舱采购角色查看缺口、供应和待处理需求；运营订货选择常规或活动建议，再选品、核对、保存草稿。所有写入均需明确点击，重新计算不直接覆盖人工数量。纯采购角色读取参考不得要求额外运营维护权限，也不得绕过销售、库存数据权限。

主表展示图片、新旧 SKU、预测日销量、库存、有效供应、开放需求、最近 ETA、覆盖天数、建议量、风险。详情展示权重窗口、代入公式、库存时间、供应依据和阻断原因。零销量和缺失分开，无 9999 天兜底，无负采购量。

## 验收关卡

- 策略租户隔离、国家范围、权限、版本冲突和参数范围校验。
- 加权计算、活动边界、0销量、无数据、期外或未知 ETA、分批部分入库与供应去重。
- 已转采购运营需求只扣一次；保存时依据变化会阻止旧建议继续落单。
- 切换账号/租户后清除参考和带入草稿，过期响应不回填。
- 预览和查询不创建采购或运营业务单；操作数量覆盖须显式应用。
- 候选查询有批次上限，界面诚实显示已扫描数，不能将本批正数过滤伪装为全国家正数分页。
- 针对改动运行后端/前端测试、迁移检查、权限清单检查、前端构建及本地页面验证。

## 交付记录

已完成本地开发与验收，基于主分支 `7378871b`（V2.44.287）整合；此前281变更已经在主分支，不重复带入旧提交。尚未部署到虚拟机或正式系统。

入口与接口：

- 供应链设置新增“补货策略”页签，每个国家维护一份有效默认策略，带版本冲突保护；10/45/35候选值必须人工保存。
- 驾驶舱采购参考使用 `/api/internal/supply-chain/v2/replenishment-references/`，采购读取权限与销售/库存数据范围分别校验。
- 策略配置使用同命名空间 `replenishment-strategies/` GET/PUT；运营订货继续使用原 `operating-orders/preview/`，传入策略ID，查询与预览不会创建业务单。
- 运营选品后重新计算，变化的数量需要显式选择应用；偏离建议量时必须在备注填写原因，快照记录原因和人工数量。
- 开放需求按需求日期与覆盖期重叠筛选；无日期需求保守计入并在依据注明。单据编辑排除自身草稿预留。
- 供应按实际分配量拆批，已提交但未分配批次的发货量归入待集货/发运；本地收货未衔接WMS时阻断可靠建议。

最终验证：

- 后端相关11个测试文件：89项通过，包含加权/活动、时间线、需求期间、拆批收货守恒、新API预览→建草稿→同token修改→提交、重复提单阻止、库存和策略变动失效、采购角色访问、历史组合折算回归。
- 前端相关7个测试文件：34项通过，覆盖100个SKU上限、分批查询、组织切换、策略冲突、空截止日处理、平台贡献、显式应用数量及未知风险展示。
- 前端生产构建通过；Django系统检查、迁移差异检查、后端权限清单、前端418项权限引用及118菜单/152路由清单检查通过。
- 独立本地SQLite数据库完整迁移成功（含0029），未对服务器执行迁移。MySQL并发行为和正式数据规模耗时尚未压测。
- 本地Edge合成数据验收：策略设置、采购参考、桌面/390px移动端依据弹窗、运营选品预览；检查未自动创建订单。证据及测试日志在工作区 `审计产物/补货策略改造验收_20261023/`，不包含正式业务数据。

性能边界：当前每次最多20个候选、选中复核最多100个SKU，按候选偏移继续查找；正数过滤仅作用于已扫描批次，不宣称是全部国家商品的正数结果分页。本轮没有增加全国商品异步物化清单、销售预聚合任务或跨用户共享计算缓存。采购入口提供参考与前往现有采购协同处理，不自动生成自主采购订单；策略暂为每国一份，运输方式多策略和SKU例外规则未扩展。
