# 事件跟踪使用与验收说明

## 使用流程
1. 管理员在事项跟踪配置中启用业务菜单，设置允许的处理部门、默认期限和催办间隔。
2. 为管辖人指定部门、是否包含下级、有效期和独立操作权限。
3. 用户在右上角“个人设置 → 事件跟踪”或业务页面悬浮入口发起事项，指定一个主处理人和要求完成时间。
4. 需要截图时主动截屏或选图，裁剪、圈选和遮挡后确认截图，再提交事项。
5. 主处理人反馈办理进展，完成后提交确认；协办人可以补充反馈。
6. 发起人或获授权管辖人确认关闭，或填写原因退回；取消、无需继续也需记录关闭原因。
7. 重开、改派、改期和部门移交必须保留操作说明与历史。

## 验收场景
| 场景 | 预期 |
|---|---|
| 非参与者且无部门管辖授权 | 不能读取详情、附件、通知或操作事项 |
| 跨租户访问 | 不能读取或更改 |
| 主处理人提交完成 | 转为待确认，不直接关闭 |
| 协办人关闭事项 | 拒绝 |
| 发起人退回 | 恢复办理并保留完成说明和退回原因 |
| 超期后完成 | 保留办理逾期记录，待确认时间单独计算 |
| 改派处理人 | 事项归属部门不隐式变化 |
| 跨部门移交 | 校验移出和接收范围，记录原部门与新部门 |
| 管辖授权过期或撤销 | 新请求立即按最新权限拒绝 |
| 重复催办 | 冷却期内拒绝，关闭事项不再催办 |
| 截图遮挡 | 上传扁平化图片，不携带原始未遮挡文件 |
| 关联业务单据 | 单据访问仍经业务权限校验 |
| 关闭跟踪事项 | 不改变关联业务状态 |
| 很久以前发起且未关闭 | 默认列表仍可检索 |

## 回退准备
上线前备份数据库和私有附件存储。优先通过权限收回与菜单规则停用入口，保留历史事项及审计数据；应用回退应与迁移版本兼容。禁止直接删除有业务数据的事项表。

## 本地启动与正式迁移准备
本地验收使用仓库根目录 `python tools/issue_tracking_local.py --init` 初始化独立测试数据库，再执行 `python tools/issue_tracking_local.py --serve`，服务只监听 127.0.0.1:8018。测试账号凭据保存在被忽略的 `.codex-work/issue-tracking-local/credentials.json`。此工具跳过迁移历史，仅供可丢弃验收数据库使用，不得用于正式业务数据库。

前端在 frontend 目录设置 VITE_USE_MOCK=false、VITE_API_BASE_URL=http://127.0.0.1:8018，再执行 `npm run dev -- --host 127.0.0.1 --port 5178`。

正式环境应按现有发布流程备份并执行 `python manage.py migrate`、`python manage.py sync_permissions`，为管理人员授予 issue_tracking.configure，再配置菜单规则和部门管辖授权。普通内部用户从个人设置访问本人跟踪事项。未配置启用规则的业务页面不显示悬浮入口。

正式回退优先停用菜单规则、撤回配置权限并回退兼容的应用制品；保留新增数据库表，避免历史数据丢失。本地已验证新增迁移可从空库执行，尚未执行任何外部发布。
