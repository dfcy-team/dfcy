# 悬浮发起流程调整验收

2026-11-28 用户截图确认右下角事件跟踪与运营订货草稿重叠。

验收目标：
1. 默认入口移至右侧中部，保留拖动和边界约束，避免底部草稿及其他侧栏主操作。
2. 从当前业务页直接进入同一侧栏的两步流程：截图或明细预览，然后选择办理人并发起。
3. 页面截图不调用系统窗口选择，不要求另开窗口；允许预览、圈选和遮挡后确认。
4. 页面明细仅采集当前可见业务区域及已授权单据上下文，排除导航、隐藏内容、密码和令牌，不上传原始DOM。
5. 第二步复用既有办理人和归属部门、截止时间及后端权限校验；不通过前端采集扩大业务访问权限。
6. 截图失败明确提示，并允许选择明细或本地图片继续，不将空白图误判为成功。
7. 多人正在同一工作区增加到货待办等功能，本次不得覆盖其改动。

实现已完成：CaptureFlow.vue提供同一抽屉两步流程；capture.js采用html2canvas1.4.1采集当前可见区域并过滤敏感和隐藏节点；IssueForm承接明细和确认截图；ScreenshotEditor在该流程隐藏系统选屏按钮。

默认right48px、bottom约半屏，拖动保留底部140px避让区域；其他业务弹窗可见或自身抽屉打开时隐藏悬浮入口。返回采集步骤保留预览，办理人加载失败可重试。

验证：5项采集流程、3项隐私、4项截图、3项表单及3项原交互测试共18项通过；VITE_USE_MOCK=false npm run build通过（17.05秒），git diff --check通过。

限制：跨域图片可能无法显示，流程提示提交前检查预览。未做正式系统部署；浏览器真实页面视觉验收尚待手动更新后的实际环境确认。
