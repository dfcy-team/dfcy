# 内部系统共用登录接入（授权码方式）

其他系统只复用本系统的用户身份验证，不获取密码、密码哈希、角色或权限。本接口不是用户密码验证接口，也不是完整 OpenID Connect 实现；调用方需自行创建会话并维护自己的权限。

## 管理员配置

在“API 数据接入 → 内部系统数据接口 → 调用系统配置”中，新增或编辑调用方，开启“共用登录”，填写调用系统的精确 HTTPS 回调地址（须包含路径，不得有查询参数或片段）。可不勾选数据块；此时调用方只有共用登录能力、无数据读取权。仍需配置调用方服务器的来源 IP/CIDR。配置创建或修改后，需要由非创建/修改人审核，再启用。调用方密钥仅创建时显示一次，保存在调用方服务端，不得放在浏览器中。

## 调用流程

1. 调用方服务端生成随机 `state`（16–256 位 URL 安全字符）和 PKCE `code_verifier`（43–128 位），保存到自身短期登录会话。计算 `code_challenge = BASE64URL(SHA256(code_verifier))`，去掉填充。
2. 浏览器跳转至本系统 `/sso/authorize?client_id=...&redirect_uri=...&state=...&code_challenge=...`。未登录用户进入本系统登录页，密码仅提交到本系统。
3. 本系统校验当前用户、租户、调用方审批和启用状态及精确回调地址，生成有效期 90 秒的一次性授权码。浏览器跳转至已登记的回调地址，携带 `code` 和原 `state`。
4. 调用方先比较 `state` 与本地会话中保存值，再由服务端向 `POST /api/internal-readonly/v1/auth/token/` 提交 `code`、原 `redirect_uri` 和 `code_verifier`；使用 HTTP Basic 的 `client_id:client_secret` 身份验证。请求来源必须在登记的 CIDR 中。
5. 成功响应 `data` 仅有 `user_id`、`username`、`full_name`、`tenant_id`。调用方将身份映射到本地用户并建立本地会话；角色和权限完全由调用方管理。授权码只可兑换一次，且只对原调用方、原回调地址和原 PKCE 验证器有效。

关闭调用方、使其审批失效、移除回调地址、用户失活或凭据租期失效均拒绝后续兑换。对外请求必须使用 HTTPS，浏览器端不得存储调用方密钥。旧的业务只读 API 授权与共用登录开关互相独立。
