# 关联达人档案共享联系渠道

## 业务范围

- 仅显式关联到同一组的达人档案共享联系渠道，不根据昵称、电话或邮箱自动关联达人。
- 平台账号、数字 ID、主页、送样、建联、BD 归属、黑名单和停用状态仍独立保存。
- 编辑表单、详情和联系方式接口读取同一共享清单。新建关联档案后，已有联系渠道自动可见，无需复制。
- 新建关联档案时填写的联系方式加入共享清单，不会清空已有渠道。
- 保存已有档案的联系方式是替换共享清单。删除使用停用标记，不硬删除历史联系方式。

## 历史数据

本次不新增数据库字段、不运行回填，也不修改业务数据。读取时按“联系渠道＋值”合并展示已有同组有效联系方式。

同值的旧联系方式有不同备注时，表单列出备注差异；同组存在多个主渠道时也会提示。只读查询不修改原始记录。用户明确保存联系方式后，才将选定内容应用到共享清单并停用重复或已移除的旧记录。

仅修改达人备注、粉丝数等非联系方式字段时，前端不重复提交未改变的联系清单，避免误覆盖。

## 权限与并发

- 读取严格限定当前租户及对应查看/管理权限的国家范围，不展示隐藏关联档案的联系方式或备注冲突。
- 显式替换共享联系方式，要求对整组档案均有 `influencers.manage` 权限，否则拒绝整个操作。
- 原有联系方式接口与聚合编辑接口共用保存流程，并保留 `If-Match` 校验。联系方式接口要求显式提供 `contacts` 数组，清空须明确提交 `[]`。
- 联系方式修改成功时，推进同组档案的 `updated_at` 及关联组版本；其他旧编辑窗口保存时返回 409，须重新加载。
- 版本推进不调用平台身份同步逻辑。关联组审计仅记录版本和成员 ID，不写入明文联系方式。

## 验收

1. 从 TikTok 档案新增联系方式，Facebook 关联档案重新加载后显示相同清单。
2. 在任一关联档案修改备注、删除渠道或更换主渠道，其他关联档案重新加载后同步更新。
3. 无关联达人及其他租户不受影响。受限国家账号看不到隐藏档案的联系资料，也不能间接清除它们。
4. 不同历史主渠道或同值备注冲突不会在读取时自动改写，须人工确认。
5. 保留另一编辑窗口的旧版本，修改共享清单后，旧版本提交应返回 409。
6. 新建关联档案不复制或合并平台身份，不改历史送样、任务和成本。
