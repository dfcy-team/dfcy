# TK 销售诊断数据

销售工作台仅在打开商品排查弹窗时请求 `evidence=1`。列表查询不读取视频、库存、价格或商品流量快照。弹窗关闭、查询范围变化或组件卸载时取消请求，旧响应不能覆盖新商品。

## 数据口径

- 视频：按租户、授权店铺、商品 ID 的已解析关联查询；展示关联视频整体表现。多商品视频的曝光、点击不能视作单个商品流量。视频和达人数量是已入库关联数量，不是查询期间新增数量。
- 视频日指标：读取有效及降级记录的已知值，未知字段保留空值；点击率仅用曝光和点击均已知的同组记录计算。覆盖日期与缺失数据需结合提示阅读。
- 商品整体流量：精确匹配查询起止日期的官方商品接口快照；不将每日去重人数相加。曝光人数、点击人数与预估购买客户数使用各自原口径，不统称商品访客。
- 渠道：商品卡、卖家视频、直播、达人及 Shop Tab 的数据按平台字段分别展示，父子渠道可能重叠，不合计成总量。
- GMV Max：所属店铺的广告辅助数据，包含平台定义的自然和付费归因，不分摊到当前商品。
- 库存、价格：沿用各变体与内部 SKU 的匹配及权限；当前价格不能证明历史价格变动。

## 商品流量采集入口

新增 `influencers.0046_tiktok_product_performance` 迁移和 `sync_tiktok_product_performance` 管理命令。部署时先应用迁移。命令复用现有 TikTok 运行审批、凭据托管、店铺绑定及权限校验，不绕过网络闸门。

```powershell
python manage.py sync_tiktok_product_performance --actor-id <用户ID> --tenant-id <租户ID> --store-id <店铺ID> --start-date 2026-11-22 --end-date 2026-11-23
```

默认只读试取；确认采集摘要后，同样参数增加 `--apply` 写入。结束日期不包含在内，按店铺时区，只允许已经结束的 1–31 天窗口。查询昨日、近7天、近15天、近30天分别需要对应的完整周期快照。

只有全部分页通过校验后才原子替换该周期快照；失败保留旧快照。没有为全店铺自动启用定时采集，避免无计划增加 API 与服务器开销。未采集的周期在弹窗明确显示暂无快照。
