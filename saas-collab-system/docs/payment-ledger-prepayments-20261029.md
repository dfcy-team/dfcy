# 逐笔付款与采购预付款调整（2026-10-29）

基于本地 V2.44.324 收款账户候选开发。本次未部署、未操作虚拟机或正式系统业务数据。

## 操作入口

1. 采购协同：打开已确认采购单，在采购预付款面板登记本次金额、付款日期、收款账户和选填备注；保存后在对应付款记录上传凭证。
2. 费用与结算 / 供应商发货单：逐笔登记货款；选择该发货单关联采购单的预付款，填写本次抵扣金额和日期。
3. 费用与结算 / 集货发运批次：逐笔登记货运付款。
4. 供应商档案 / 货运公司：收款账户入口维护账户性质、户名、银行、账号和启用状态。付款现场也可维护账户。

所有付款只登记已发生转账，不执行真实支付。凭证沿用 PDF/JPG/PNG；历史结算凭证保留原位置。

## 金额口径

- 历史已付：旧结算最后一个累计版本作为期初；旧版本之间不相加。
- 新增已付：有效逐笔付款之和；冲销行和被冲销行不再计入。
- 供应商发货剩余应付 = max(应付货款 - 历史期初 - 新增实付 - 有效预付抵扣, 0)。
- 货运剩余应付 = max(应付运费 - 历史期初 - 新增实付, 0)。
- 采购预付余额 = 有效采购预付款 - 有效抵扣；抵扣不再产生一笔付款。
- 采购未付金额 = max(采购总额 - 有效预付款, 0)，仅表示本采购预付款面板口径；后续发货付款在发货单查看。
- 收款账户性质和内容保存为付款时快照；对公/对私可追溯，不由账户性质自动修改商品价格或成本。

## 更正与兼容

原记录不可删除或覆写。新增付款可填写原因冲销；预付款已用于抵扣时，必须先撤销相应抵扣。冲销记录和原因保留。
旧累计接口在单据启用逐笔付款/抵扣后不得继续覆盖累计金额。历史期初不拆成猜测的逐笔付款；历史金额本身如有错误需专项核对，不能通过伪造新付款抵消。

## 性能和权限

付款面板仅在单据详情打开后加载；账户下拉和管理窗口按需加载。切换单据丢弃旧请求响应，防止串单。写入有幂等键和版本控制，金额使用四位小数精度；抵扣受采购单归属和余额约束。

## 发布注意

本地候选后端和前端必须配套发布，包含新增付款/抵扣/凭证关联迁移。当前分支源于旧 V324 基线，发布前须与最新累计分支集成并解决迁移编号冲突。验收应覆盖采购预付→分批抵扣→后续付款→凭证→冲销，并核对费用列表及商品成本台账。
