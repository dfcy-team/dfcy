# 实时数据大屏：隔离MySQL迁移预演

2026-10-22。目标是验证虚拟机当前已应用0052的状态到本候选0053的实际迁移及重跑，不是从空库安装全系统。

源虚拟机仍为V278（b84040488e3391996142103fb9df76c08f5d7113）。源连接设置并验证SESSION TRANSACTION READ ONLY，仅复制341张表的结构和2096条迁移/权限元数据；没有复制销售、库存、广告等业务事实，也没有向源库写入。

临时MySQL 8.4.10使用独立内部Docker网络、内存临时数据目录、独立凭据及资源限制，不发布端口。独立后端进程使用测试设置，只连接临时MySQL。通过Django MigrationExecutor加载候选0053及现有迁移图，检查初始计划仅有0053，再执行实际迁移并重新读取已应用记录，重跑计划为空。

结果：

- 新增实时数据大屏菜单权限恰好1条，名称、权限类型和路由正确。
- 原有权限记录、角色授权和数据范围等8张保护表的行数及规范化SHA256保持不变；比较权限表时只排除本次目标菜单代码。
- 源库预演前后权限/迁移元数据一致，没有执行源库迁移、授予角色或切换服务。
- 临时MySQL、后端容器和专用网络全部清理，未挂载现有数据库数据卷。

首轮探针的问题属于验收脚本：MigrationExecutor执行后需要重新读取迁移记录再计算重跑计划；修正后通过。此前在只读连接创建临时表的失败方案没有继续，也没有降低源连接只读保护。

聚合证据保存在交付目录 `开发交付/实时数据大屏_20261022/isolated-migration-result.json`，脚本为 `isolated_migration_rehearsal.py`。证据仅含聚合数量、状态和迁移源码SHA256，不包含复制行或凭据。哈希对应实际执行文件字节，可能与Git规范化换行后的blob哈希不同。

剩余闸门是本候选CI、候选专属受控发布记录、VM服务部署后的完整HTTP/浏览器验收和有代表性的业务数据对账/性能测试。现有V279发布控制绑定其他候选，不能用于本次大屏发布。正式系统不在本次验收范围。
