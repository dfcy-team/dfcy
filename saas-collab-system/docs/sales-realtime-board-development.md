# 实时数据大屏开发候选（2026-10-22）

基线：正式 V2.44.272，提交 `3e304ff4e717c520049431236c81b1b0e3aa4f0c`。
隔离分支：`codex/sales-realtime-board-20261022`。未合并、未部署、未操作生产数据。

## 已实现

- 销售管理新增「实时数据大屏」，路由 `/sales-management/realtime-board`，置于销售工作台之后。
- 深色布局、全屏、平台/店铺/日期筛选、分币种切换；销售额、订单总量、非取消订单、销量、广告费率。
- 日粒度销售/订单趋势切换，店铺及商品销售额前10名；有订单权限时可携带筛选条件下钻。
- 新接口 `GET /api/internal/commerce/realtime-board/`；仅查询落库事实，不调用平台、不启动同步。
- 沿用 `sales_management.view` 及其数据范围。广告另校验 `analytics.view` 及范围交集。普通角色的菜单授权需在发布流程中显式分配；菜单迁移不自动扩展角色授权。
- 正常界面隐藏同步时间；读取失败时明确提示。连续3次刷新失败清除旧结果。

## 性能控制与证据

- 路由动态导入，大屏组件不进入菜单初始化路径；无新图表依赖，使用SVG。
- 构建大屏独立资源 JS 约13KB、CSS约8KB（未压缩），不是全站包体积。
- 进入页面发起1次大屏请求及1次筛选目录请求；之后成功或失败结束60秒后再刷新，不重叠请求。
- 切离路由取消请求并清除计时器；浏览器隐藏时暂停，恢复后刷新。
- 单次最多31天，数据库聚合与窗口函数限定Top10；前端不分页拉取完整订单或广告明细。
- 后端定向测试对12笔订单的一次完整响应校验SQL总数不超过24；这不是正式库延迟或并发容量测量。

## 指标与当前边界

销售额采用非取消订单的 `order_total_amount`；不是净利润，未另扣退款。销量为非取消订单明细数量。商品分类尚无可靠统一标记，因此首版标明全部商品，不将零金额直接视作赠品，不宣称已完成主商品/赠品/辅料分类。

广告费率 = 同范围同币种广告消耗 / 非取消销售额 ×100%。目前接入Shopee `shop_daily` 落库事实。历史日期的预计店铺-日记录齐全、销售和广告权限范围满足条件且销售币种组不混入其他平台时，可返回 `reference_unverified` 参考值。日报覆盖不等于来源完整证明，后续补采可能调整。当前日期、广告缺数、权限缺失或跨平台口径不一致时返回null及业务原因，不以零替代。TikTok等其他广告源尚未纳入本接口。

趋势按日展示，尚未实现小时趋势与昨日同刻比较。未实现销售骤降检测、独立异常处理列表、完整利润、销售目标、库存风险及履约风险。

## 第二轮：排行指标切换

店铺支持销售额、订单总量（含取消）和销售额占比；商品支持销售额和销量。后端在原有两条排行聚合查询中分别计算两个窗口排名，返回各指标真正的Top10，不在销售额榜单的10条中重新排序。前端本地切换不增加网络请求；占比以当前币种组全部非取消销售额为分母，分母为零显示不可计算。订单量榜下钻保留取消订单，销售额榜及商品榜下钻排除取消。新增全数据排名和无额外请求切换回归。
