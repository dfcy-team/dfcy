# 旧新供应链数据映射与迁移边界

第一阶段只新增schema与只读预检，不自动复制旧业务数据。原模块仍可读取历史单据；旧表、装箱来源及其他模块引用均保留。

| 旧对象 | 新对象 | 可以映射的内容 | 必须核对的缺口 |
| --- | --- | --- | --- |
| purchasing.PurchaseOrder（单行） | supply_chain.PurchaseOrder / PurchaseLine | 企业、单号、商品、数量、单价、创建人、日期 | supplier_id与SKU字符串须解析为本企业主数据；国家、来源方式、实际下单状态不能推断 |
| purchasing.SupplyPurchaseOrder及lines | PurchaseOrder / PurchaseLine | 企业、供应商FK、SKU FK、主明细、价格和日期 | 旧source_system/table/record_id是历史迁移元数据，不能直接认定为运营来源；国家和状态需明确映射 |
| suppliers.SupplierShipment | SupplierShipment / ShipmentLine | 企业、单号、SKU、实际数量、附件线索 | 没有可靠采购明细FK，须人工或确定性规则核定来源；旧received不能直接认定为目的仓已入库 |
| packing.PackingBox及相关分配 | 历史记录保留、必要时归档箱号附件 | 可保留箱号文件和原分配追溯 | 不直接删除箱实体；新版集货不得依赖供应商逐箱填写 |
| consolidation旧集货记录 | DispatchBatch / DispatchMembership | 运单、目的地及成员的已核定关系 | 箱消费关系不能无校验变成完整发货单关系；国家、有效成员及阶段逐项核对 |
| shipping旧国际发运 | DispatchBatch物流事件 | 已确认物流事实、发生时间和来源证据 | 按新三状态及实际事实映射，不用旧完成状态推断库存入库 |
| 旧仓储、结算和成本 | 保留权威来源，后续接收接口引用 | 外部仓库、应付付款及原金额版本 | 先确认权威收货写入接口，历史导入不能重复增加库存或重记付款 |

备注单号可重复且可修改，不作为去重键。历史导入应以`来源系统 + 对象类型 + 旧主键`形成稳定映射及导入幂等键，并记录映射文件版本与审阅结果。没有可信映射的历史单据保持只读，不填虚构国家、仓库或采购关系。

正式导入前执行结构、类型、各对象行数、主键覆盖、空值、唯一性、引用完整性等低成本校验；这些检查失败时才定位有限异常样本。源与目标比较前统一字段顺序、NULL、编码、时区、日期、小数精度，不直接比较不同数据库的原生哈希。大数据比对使用本地确定性流式脚本或SQL聚合，不逐行交给模型。

每个映射批次保留规范化校验结果、版本、导入幂等键及失败行定位。预检只统计问题，不证明历史数据已经迁移。后续迁移还须增加稳定旧新ID映射、分块哈希及受控导入器，并在隔离还原库验证。

回退时先回到旧应用入口和已核定代码，保留已经产生的新表记录；不在有业务数据的库上直接反向运行新增表迁移。原库存、付款及历史单据不因候选模块回退而清空。
