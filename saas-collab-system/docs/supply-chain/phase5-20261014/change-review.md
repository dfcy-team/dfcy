# 第五阶段代码与验收口径

新增 FeeRecord/FeeRevision、CostVersion/CostEntry/CostAdjustment、SettlementRecord/SettlementRevision。费用、成本和结算历史追加保存，当前费用及结算指针通过事务服务更新；继承租户约束、领域写保护和禁止历史删除。所有写入复用采购权限、来源范围、租户锁、单据版本和幂等事件。

每个发货单、集货批次或入库单各有一个本环节总费用槽，新费用版本替换有效值；不重复累计历史版本。金额精度4位、计量6位、单件成本8位。体积/重量/混合权重以 Decimal 高精度计算，按最大小数余数、来源行ID稳定分配最小金额单位，分摊和严格等于总费用。金额零可在计量缺失时明确保存，正数费用使用的全部计量必须有效。人工实测总量和商品计量来源随分摊冻结。

成本以发货行保留来源，不回写商品档案采购参考价或采购行原始价。成本输入指纹包括货值、费用版本、收货数量及收货流水标识；结算登记不会使成本失效。批次版本之外的发货价格、到仓费用变更，也会使旧成本待重算，并阻止使用过期指纹计算。相同幂等键只能重放同一内容。

已集货发货单允许带原因调价；供应商仍无权读写价格。已确认入库后产生金额调整，前一金额未知时不会假设为零来生成差额。缺费用的成本分量及相关总额为NULL，保留明确零与未知的区别。未核对数量不会被解释为零，清货分摊数量变化后须重新维护费用。

内部API前缀 `/api/internal/supply-chain/v2/`：

| 方法与路径 | 作用 |
| --- | --- |
| GET cost-targets/?kind=shipment或batch或inbound&search=单号 | 按可访问单据选择费用对象 |
| GET costs/{kind}/{id}/ | 单据版本、计量、费用历史、当前与历史成本、结算登记 |
| PUT costs/{kind}/{id}/fee/ | 带 source/fee 版本、原因、分摊方式、比例和可选实测总量维护费用 |
| POST costs/{kind}/{id}/calculate/ | 按 source 版本和输入指纹计算成本；已集货按批次调用 |
| GET costs/{kind}/{id}/versions/{sequence}/ | 读取冻结历史明细 |
| POST costs/{shipment或batch}/{id}/settlement/ | 累计结算来源登记，与付款和成本确认分开 |

kind仅接受shipment、batch、inbound。读取要求supply.v2.view，写入要求supply.v2.manage，均应用租户和供应商范围；混合供应商批次连历史成员也受范围校验。仅可看其中一家供应商的采购员不能借发货上下文取得整批成本或指纹。供应商门户、匿名访问、小程序专用渠道不能使用内部成本API。

部署新增迁移0012–0014，0013注册费用菜单。导出的前端菜单、权限引用及后端API清单与代码同步。未改动依赖和锁文件；候选包不包含本地数据库、认证会话、真实凭证或node_modules。

目标MySQL的并发锁与真实数据迁移需要在预发环境验收；本地验证采用独立SQLite测试库及纯测试单据。既有旧模块的数据切换、支付集成、第三方库存写入和真实外部群通知均不在本次执行范围。
