# 第五阶段：费用与商品成本

本阶段在前四阶段的采购、发货、集货和入库数据上增加费用维护、成本版本和结算来源登记。采购在内部工作台操作；供应商继续填写发货数量和上传箱号附件，无法查看内部费用、采购价格及成本。

## 采购如何操作

可从“供应链协同 → 费用与成本”按单号查询，也可在供应商发货单、集货批次、入库单的详情内操作。

| 环节 | 可维护内容 | 何时开放 |
| --- | --- | --- |
| 供应商发货单 | 有效采购单价、到集货点费用、供应商货值结算登记 | 单价可再次调整；到集货点费用须先提交发货并标记到仓 |
| 集货发运批次 | 整批货运费、计费方数、货运结算登记 | 批次标记开船后可维护货运费 |
| 第三方仓入库单 | 清货费、清货方数 | 每行实收数量核对后可维护，入库确认后仍可更正费用 |

费用填写金额、暂估或已确认状态、分摊方式和本次原因。按体积、按重量或体积与重量混合分摊；混合时填写体积占比，重量占比为其余部分，支持0–100%。无费用时请明确保存金额0并确认，留空代表未知。

默认读取商品明细已有的体积和重量。商品重量由克换成千克，体积使用立方米；体积缺失且长宽高齐全时可换算。页面显示本行全部数量的总体积、总重量，可填写本次实测总量。正数费用使用的计量必须齐全且大于零，系统会提示缺失项。计费方数单独记录，不自动替代商品体积，也不自动乘费率生成费用金额。

## 如何看商品成本价

未集货发货单可查看发货阶段暂估成本；已集货的货物按整个发运批次统一计算，也可从入库详情进入。明细保留每张发货单的来源行，同一SKU的不同采购价格不会被提前混为一个价格。

货值取实际发货数量乘发货单有效单价，包含超采购数量及采购单外商品。到集货点费用和货运费参与发货阶段成本；入库后按实收数量比例结转货值及前段费用，再加入按实收分摊的清货费。短收部分金额保留在“待处理”，不自动转嫁给已经收到的商品。超收额外货值需采购核对，成本保持暂估。

页面提供发货、实收总成本和对应单件成本。缺少价格或适用费用时，受影响的金额显示未知，并列出原因；费用仅暂估、数量未确认或超收时，成本保持暂估。全部必要价格、费用和入库数量确认后，可以得到已确认成本，供应商或货运费用尚未结算也不影响计算。

修改价格、费用金额、分摊比例或实测量后，旧成本显示待重算。再次计算会生成新版本，历史明细仍可查看。已入库且前后金额都明确时，系统生成入库金额差额；原有实收数量、库存和收货流水保持原事实。

## 结算登记

按供应商发货货值或集货批次货运费登记“累计已结算金额”、来源单号、日期和原因。累计额直接填写当前累计数，不是本次新增数；退款或纠正登记时也填写新的累计数。历史登记保留，页面显示尚未结算金额、超登记金额和自上次登记后产生的应结差额。

这是结算来源登记，不执行付款，也不替代财务系统的银行、发票或支付凭证。结算状态与费用确认、成本确认相互独立。本期金额沿用现有采购金额的同一计价口径，不增加币种、汇率或成本分摊规则档案菜单。

## 验收与交付范围

测试记录和实际页面证据见同目录 verification.json、测试XML、samples及screenshots。发布前需在目标数据库执行迁移、核对权限并走预发验收；新增“费用与成本”菜单只注册，不自动给已有角色扩权。

本阶段交付本地可审阅候选代码，未发布到正式系统。第三方仓库存仍以第三方回传为准。第六阶段的外部群高频自动投递仍待实际通道验证。

交付目录中的 supply-chain-phase5-candidate.zip 是基于原工程的累计变更覆盖包，并非包含全部依赖的独立工程。manifest.json 列明基础提交、前四阶段完善后的基线树和候选树；candidate-cumulative.patch 包含本轮全部阶段的累计变更，phase5-increment.patch 只包含相对前四阶段完善版本的本阶段变更。package-verification.json 记录两份补丁重建结果，SHA256SUMS.txt 用于核对文件。正式发布前应先在保留基础工程和数据备份的预发环境应用、迁移及验收。
