# 供应链协同第三阶段交付说明

第三阶段实现供应商独立登录、供应商分批发货、采购代录和私有箱号附件。采购与供应商操作同一张新版发货单；第一、二阶段的数据、单据和权限继续沿用。本交付为开发候选版，尚未发布到正式系统。

## 业务人员如何使用

1. 采购进入“采购协同 → 供应商档案”，点击对应供应商的“联系人账号”。创建供应商账号和初始密码，并自行告知联系人。一个供应商可创建多个联系人，也可停用或重置密码。
2. 供应商打开 `/supplier/login`，使用采购提供的账号登录。供应商只看本供应商已经下单的采购单；采购人员仍从 `/login` 进入原协同系统。
3. 供应商查看采购单，可以下载采购订单 Excel 和商品 SKU 标签 PDF。从采购单进入“登记发货”，选择本次实际发货的商品与数量。可分多次发货，也可超出采购数量或增加采购单外的 SKU。
4. 先保存发货草稿，再上传包含本次发货所有箱号信息的附件。支持 PDF、XLSX、UTF-8 CSV、PNG、JPG；单文件最多 10MB，每张单最多 20 个当前附件。页面没有箱号填写表。
5. 点击“提交发货”。提交后商品数量与附件冻结，供应商可继续查看和下载。草稿可编辑或作废；保存冲突时须刷新，不能覆盖其他人的修改。
6. 采购进入“供应商发货单”，可以代供应商执行相同的草稿、附件、提交流程，录入来源会标记为“采购代录”。采购可以再次调整发货单采购价格，并标记“集货到仓”。采购调价不会自动覆盖供应商价格档案。

提交时会按采购来源行累计核算已经提交的发货数量，显示“超采购数量”或“采购单外 SKU”。两种情况均允许提交。供应商不能填写或修改内部采购价格；采购单中已约定的采购价及总金额仍可查看。采购单外商品暂未定价时可以先提交发货，后续由采购补价。

“集货到仓”是供应商发货单的简单标识。“开船、到港、目的仓到仓”继续从集货发运批次派生，不能在供应商发货单单独编辑；这些批次操作和入库页面安排在第四阶段。

## 本阶段边界

新建联系人仅绑定当前租户及授权供应商，不能创建内部员工、管理员或授予内部权限。联系人身份复用系统 `CustomUser + ExternalUserProfile`；新增联系人记录保留采购维护的版本和操作历史。旧外部账号的人工梳理或批量接管不包含在本阶段。

供应商令牌使用 `supplier_web` 渠道。每次访问和刷新都会重新检查账号、租户、供应商和绑定状态。停用账号后既有令牌也不能继续访问；订单链接只定位订单，不能扩大供应商权限。同一个浏览器标签会话只保留一个当前身份，切换人员请先退出登录。

未集货草稿可以改商品及附件；已提交单据不能回改数量，已集货单据不能通过本阶段直接改价。后续费用、结算、成本重算与更正流程安排在第五阶段。供应商采购单无需运营订货单前置，第二阶段的手工创建、导入和备注单号继续可用。

自动外部群发送仍处于阻断状态，本阶段不会调用旧群发接口或发送真实消息。高频自动通知、群与工具账号绑定及真实外部群验收安排在后续通讯阶段。

## 文件、权限和审计

箱号文件以私有 `BoxFileContent` 保存受限大小的二进制内容，元数据仍复用 `AttachmentFile`；文件与发货版本、事件在同一数据库事务提交，没有公开媒体路径。仅通过登录后的专用下载接口取文件，下载会再次校验单据授权与 SHA-256，并设置附件下载、禁止缓存与 `nosniff` 响应头。

草稿修改保留历史商品行；附件“移除”取消当前绑定但保留历史文件。被移除文件仍可由该单据的有权人员通过历史标识下载，其他供应商仍不可下载。附件内容本阶段仅校验格式、尺寸和完整性，不声称已进行恶意文件扫描。附件随数据库备份；正式部署须检查数据库连接的单包大小能支持 10MB 文件及备份容量，后续可替换为私有对象存储适配器。

所有写操作使用租户事务锁、单据版本和幂等键；同内容重试不会重复创建发货单、文件或联系人。不同内容复用同一键会被拒绝。保存事件保留具体操作账号、版本和内部快照。账号密码仅交给系统密码哈希存储，审计事件仅使用服务器密钥生成的重试指纹，不存明文密码。

采购继续使用 `supply.v2.view / supply.v2.manage` 及 ALL/OWN/CUSTOM 数据范围。维护共享供应商联系人需要 ALL 或指定供应商的 CUSTOM 维护范围；OWN 只授权本人订单，不允许修改共享联系人。新增菜单为 `menu.supply.supply_chain_supplier_shipments.view`，迁移只登记菜单，不自动扩大任何现有角色的授权。

## 技术入口

| 功能 | 入口 |
|---|---|
| 采购发货单 | `/supply-chain/supplier-shipments` |
| 供应商登录 | `/supplier/login` |
| 供应商采购单与定向链接 | `/supplier/orders`、`/supplier/orders/{id}` |
| 供应商发货单 | `/supplier/shipments?order_id={id}` |
| 独立登录与刷新 | `/api/external/auth/login/`、`refresh/` |
| 供应商单据 API | `/api/external/supplier/supply-chain/v2/` |
| 采购单据 API | `/api/internal/supply-chain/v2/` |
| 联系人维护 | 内部 `suppliers/{id}/contacts/` |

第三阶段新增迁移 `0005`（历史行、附件内容、联系人版本）和 `0006`（发货单菜单），不导入或删除原模块业务数据。

## 验收记录

后端102项（供应链98项、供应商登录4项）及前端51项测试全部通过。最终结果记录在 `verification.json` 和三份测试 XML 中。后端供应链回归、供应商登录渠道回归、前端测试均须通过；完整前端构建、Django 检查、迁移漂移和权限清单检查均须通过。

真实浏览器已操作：采购创建联系人 → 供应商从订单链接登录返回目标订单 → 超量 2 件的发货草稿自动保存后上传箱号 CSV → 提交 → 下载文件与原文件哈希相同 → 采购读取同一张单、调价、到仓标记；另对采购单外 SKU 执行采购代录、上传及提交。窄屏检查宽度为 390px，商品表在自身容器横向滚动。

截图和纯测试文件见 `screenshots/`、`samples/`。独立审查发现的两个局部更新问题已经修复：仅改商品不再覆盖日期备注；仅重置密码不再恢复停用账号或清空姓名，并已加入回归测试。

## 部署交接

交付包提供累计改动覆盖包和以第二阶段索引树 `af279f5bca182d6821469ab558d0fe6f72daa0d0` 为基准的第三阶段增量补丁。先在测试环境备份数据库、应用代码和迁移，给采购角色按需授权新版发货单菜单，再复测供应商渠道和私有文件；正式发布需要另行确认。
