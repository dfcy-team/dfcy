# 本次完善的技术审阅要点

真实运营需求归销售管理所有，新增运营主单、明细及不可变建议快照；平台客户销售订单继续保留在原模块。供应链分配增加可空的原生运营明细引用，历史外部来源文本仍可读取。

提交需求、拆单及取消草稿在租户事务锁内检查版本、有效分配和幂等键。分配从服务端的运营明细建立，不能通过手工采购接口伪造。运营来源调价时服务端重建原分配，冻结国家、供应商、SKU及数量；取消采购草稿释放需求，同时推进运营单版本，旧价格及分配明细保留。

运营及采购来源采用现有角色页面可保存的 `site_ids` 国家维度。采购读取使用VIEW范围，拆单使用MANAGE范围，并另检查供应商范围。运营国家资源使用特定前缀，避免客户销售店铺的资源策略覆盖运营权限。实际角色权限更新接口的保存及拆单回归已覆盖。

建议销售口径使用店铺时区的创建日期窗口和期末前付款状态，不依赖历史 `business_date` 字段。库存按来源身份取最新有效事实，未映射或失败来源不会静默退回旧值。建议具有固定来源快照、两小时的生成单据有效期和操作者归属；相同请求重试返回原观察，不重新取数。已有生成单的审核数量与计算依据保留。

批次取消状态独立于开船、到港、到仓三个阶段。开船前可更换成员及取消；取消或移出以失效关联保留历史。批次授权覆盖历史关联，不能通过移出某供应商逃避全批次范围检查。日期更正仅修改已记录节点，必须有原因且保持时序，不倒退物流状态或重写收货流水。

前端同时覆盖运营需求页面、采购拆分页签和原采购详情。运营来源采购单隐藏增删SKU及数量入口；维护价格、日期和备注继续可用。独立拆分页签的采购保存和取消不再错误调用普通列表刷新，避免操作成功后显示降级。

日期维护只限采购草稿；已确认运营来源采购单的日期同样只读。确认页面清理原第二阶段的待开发提示，指向已完成的供应商发货单及集货发运入库入口，并明确外部群自动通知尚未启用。

迁移不切换生产入口、不导入旧业务数据、不隐式授予新运营权限。测试基于SQLite；MySQL行锁并发及正式切换需在目标环境验收。费用成本及自动消息通道仍保持未实现/待验证能力标识。
