# 供应链协同第六阶段交付

2026-10-14。本阶段完成系统功能和本地验收，尚未发布正式系统。WorkTool 机器人、发送账号及设备尚未就绪，真实供应商外部群的自动投递仍待联调；系统对外投递开关默认关闭。

## 采购与供应商现在可以做什么

采购在“供应商订单通知”维护发送通道、发送账号显示名和设备名称，在“采购协同 → 供应商档案 → 订单通知群”选择通道并登记完整群名或唯一群备注。采购无需手填企业微信 `chat_id` 或成员 `userid`；当前 WorkTool 通道按群名/群备注查找，群成员身份与目标唯一性采用人工核验，不伪装成自动拉群。

采购确认下单后，系统自动创建通知记录。后台准备并分别跟踪通知正文、Excel、PDF和供应商填写链接。正文包含采购单号、供应商、国家、总数量、总金额和有值时的备注单号。采购页面提供查看、准备文件、核对工具结果与异常处理，不设逐单“发送”按钮。

供应商点击的链接是 `/supplier/orders/订单ID`。未登录时进入独立的供应商登录页，登录后直接打开对应订单；内部协同系统与供应商入口保持区分。供应商只能查看本供应商的已确认采购订单，按原流程登记发货并上传包含所有箱号的装箱附件。

## 商品图片、详细资料和 PDF

订单商品明细显示商品图片、SKU、名称、采购数量和约定采购价，以及 SPU、品牌、分类、规格与规格属性、颜色、尺码、材质、单位、包装长宽高（cm）、重量（g）、体积（m³）、原产国、海关编码、商品形态、类型、卖点和说明。未维护的资料明确显示“未维护”。每个 SKU 都有“下载本商品 PDF 标签”，同时保留整单标签 PDF 和整单 Excel。

商品图片通过有订单归属校验的接口加载，页面无需访问公开媒体目录。图片和单商品 PDF 均验证登录身份、供应商和订单中的 SKU，不提供全商品库的匿名下载入口。

Excel 保留“采购单、发货数量填写、箱号信息填写”三张表及原 A–E 列，在采购单中增加内嵌商品图片和详细资料。没有图片或图片不可读时明确标注，其他商品资料继续导出。明细资料按文本写入，防止商品名称、备注等被 Excel 当成公式。

新订单在下单确认事件中保存商品描述资料和图片地址快照，不新建重复的商品 SKU 档案。历史订单缺少快照时，页面明确说明使用当前商品档案，不回写旧事件。通知文件准备后冻结文件字节和哈希；采购、供应商下载已准备的整单文件时使用同一份文件。图片源在文件准备前失效时显示不可用，已准备文件中的内嵌图片保留。示例文件均为本地测试数据，示例图片为测试占位图，不代表真实商品图片。

## 状态和异常处理

“接口已受理”“工具已执行”“群内已核实”分别记录。工具受理或成功回调不能证明外部成员已经在群里看到消息。群内核验用于验收与异常核对，不要求群主逐条确认发送，也不阻塞后续新订单。

正文、Excel、PDF和链接分别保留发送尝试、工具指令编号、回执与核验证据。只有明确失败的部件可单独重试；已核实送达的部件不会重发。超时、丢失回执或矛盾回执转为结果未知，暂停自动重发；确认未送达时需核对原群并确认旧指令已停止。迟到的成功回执会阻止危险重试。

发送端离线时保留任务并定期检查。所有租户共用 WorkTool 请求限速；配置不足的旧任务会延后处理，避免挤占新订单。后台 HTTP 发送不跨数据库事务，领取后按本次尝试对应的发送通道投递，防止变更绑定时串用机器人。

历史未绑定订单不会因新增通道就自动补发。采购需对尚无发送尝试的记录带原因刷新目标绑定。已经产生尝试的记录不能改投另一群。凭据、发送账号或目标变更会使旧核验/绑定失效，需重新核对。

## 权限与部署接入

新增“管理供应商外部群自动投递”独立权限 `supply.v2.notify`，需同时具有采购管理权限及对应订单/供应商数据范围。迁移只登记权限和新菜单，不为原角色自动提权。供应商和平台运营不获得此管理权限。

机器人凭据通过系统现有独立凭据托管服务保存引用，页面仅写入、不回显；生产环境不可使用测试文件托管。机器人 ID 不写入业务事件、日志或供应商链接。回调配置链接仅向已授权采购显示，凭据轮换后旧回调链接失效。

部署人员需要执行新增迁移 `0015–0017`，启用现有 Celery worker 和 beat。任务 `apps.supply_chain.tasks.dispatch_notifications` 每 5 秒调度；一次性检查可运行 `python manage.py dispatch_supply_notifications --dry-run`，不会生成材料或投递。正式入口通过 `SUPPLY_NOTIFICATION_PUBLIC_BASE_URL` 设置，默认 `https://xtsy.dingfengchuangyu.com`；`SUPPLY_NOTIFICATION_DELIVERY_ENABLED` 默认 `false`。

真实设备就绪后，先验证工具在线查询、文本、Excel、PDF、实际供应商链接和填写保存，再完成同一真实外部群两天每天至少 6 条、无需逐条确认的验收。通道验收登记与通道启用、系统发送开关分别控制。当前没有登记虚构的真实验收，没有向外部群发送消息，也未安装生产定时任务。

WorkTool 适配器依据[文本接口](https://worktool.apifox.cn/api-23520034)、[文件接口](https://worktool.apifox.cn/api-43191166)、[执行回调](https://worktool.apifox.cn/api-44952776)和[结果查询](https://worktool.apifox.cn/api-43575628)编写；实际账号版本、在线接口响应格式、安卓文件下载和真实群频率仍须实测。本模块不使用原企业群发任务或 `appchat/send` 作为兜底。

## 验证和可审阅交付

后端 243 项、前端 110 项测试全部通过。统计见 [verification.json](verification.json)，原始结果为 [backend-final-results.xml](backend-final-results.xml) 和 [frontend-final-results.xml](frontend-final-results.xml)。覆盖订单归属与权限隔离、凭据轮换、材料生成、回调乱序、迟到成功、分部件重试、下载授权、限流及图片读取。

页面验收使用真实本地 API，关闭 mock，只使用本地测试账号与数据。实际完成通道保存、停用群绑定保存、采购确认、四部件准备、采购与供应商文件下载、独立供应商登录和单品 PDF 下载。桌面与 390px 手机页面通过，最终页面控制台无错误、无框架覆盖层。测试中发现的旧图片路径 404 已改为鉴权接口；一次过期登录令牌已自动续期。

本系统原 27 件收货流水、第三方库存快照、费用与结算修订以及成本历史保持不变。未执行真实消息、付款、外部库存写入或正式切换。目标 MySQL 环境的迁移与多进程并发仍需部署前验证。

当前版本源码位于独立候选目录，代码和文件清单见 [change-review.md](change-review.md)。`supply-chain-phase6-candidate.zip` 是相对父版本的累计覆盖包，`phase6-increment.patch` 相对第五阶段候选树生成；包内不含数据库、真实凭据、依赖目录或本地辅助脚本。哈希和双补丁重建结果见 `package-verification.json` 与 `SHA256SUMS.txt`。
