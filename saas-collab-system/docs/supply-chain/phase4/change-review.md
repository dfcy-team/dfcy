# 第四阶段改动审查

独立只读审查未发现需要阻断的授权、幂等或事务缺陷。证据涵盖 `logistics.py` 的全批次 VIEW/MANAGE 查询、创建版本校验及确认事务，`services.py` 的租户锁/国家/有效归属校验，`models.py` 的一对一和不可变流水约束，以及回归中的失败回滚与外部快照不变断言。

仓库与库存能力审查确认 `commerce/models.py` 的快照及外部入库模型要求极风同步来源，`integrations/platform_capabilities.py` 只提供 `live_readonly`，故使用独立内部收货流水并保留外部库存来源。

集成验收修正了以下问题，并保留定向回归：

- 国家仓库选项必须在打开批次及入库时按目的国家重新加载，不能沿用空选项或其他国家的缓存。
- 入库确认结果未知时保留原版本与幂等键重试同一确认，不重新保存核对或重复记账。
- 开船前修改货运信息后，推进物流节点先保存修改并使用新版本。
- 发货单展示从批次派生的三状态和日期，已集货单据隐藏直接调价按钮，供应商仍看不到内部价格。
- 批次编号日期复用供应链北京时间规则；空实收不当作零，短收、超收和零实收需要差异原因。

首次后端定向测试的一项失败来自用固定顺序判断两个批次成员，改为按发货单 ID 核对后通过。新增前端状态投影测试的首次失败来自旧表格 stub 传空行，使用真实测试行后通过。没有放松业务、权限或生产保护条件。
