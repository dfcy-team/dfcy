# 供应链协同第四阶段交付说明

第四阶段完成集货发运批次、批次物流三状态、按目的国家选仓生成入库草稿、实收核对及内部收货流水。本候选版沿用前三阶段数据和权限，尚未发布到正式系统。

## 采购如何操作

1. 进入“供应链协同 → 集货发运与入库”，选择已提交的供应商发货单。已经标记和没有标记“集货到仓”的发货单均可选择；同批次必须属于同一目的国家，每张发货单仅有一个有效发运归属。
2. 填写货运公司、货运单号及备注，创建发运批次。批次号自动生成，唛头使用创建时的档案快照。未标记开船时可以修改货运信息；本阶段不提供批次成员改组、撤销或开船后的物流信息回改。
3. 在批次上依次标记“开船 → 到港 → 到仓”，分别填写实际发生时间。时间不能倒序；“未标记”仅为初始值。系统自动在批次下全部发货单展示相同物流状态和日期，采购与供应商都能查看，不在发货单上单独修改。
4. 批次到仓后，选择目的国家对应的有效仓库，点击“生成入库草稿”。只标记到仓不会自动生成入库；生成草稿和保存核对不会记账。同一批次仅生成一张入库单，已有单据时进入查看。
5. 逐行核对应收与实收。系统按来源发货行保留明细，同 SKU 来自不同发货单时不混为一条。实收初始为空，需要采购明确录入；也可主动点击“按应收数量填入”。支持短收、超收和零实收，数量不同必须填写差异原因。
6. 保存核对后，点击“确认入库并记账”。确认时创建一张不可变内部收货凭证及各来源行记录，显示凭证编号与仓库，保存确认人及时间。确认后数量、仓库不可回改，重复点击或相同请求重试不会增加收货记录。

发货单上的“集货到仓”表示国内集货环节的简单标识；批次上的“到仓”表示目的仓物流状态。目的仓到仓与实际确认入库分别记录。

## 库存口径与后续边界

现有 `WarehouseMaster` 是租户范围的仓库与国家档案，可直接复用。原 `InventorySnapshot` 是极风 WMS 回传的只读库存快照，`InboundRecord` 也要求外部同步运行来源；仓库适配器目前只声明读取能力，没有受支持的入库写接口。因此本阶段新增 `InternalStockReceipt` 和 `InternalStockReceiptLine`，作为本模块确认收货的权威事实记录，不能伪装外部同步或覆盖第三方仓快照。

页面明确提示“本模块入库流水已记账；第三方仓库存以其回传为准”。本阶段没有外部 WMS 写入、总体可用库存余额或出库扣减。收货流水可追溯到入库来源行、发货明细、采购单和 SKU，后续库存对接须采用正式写契约并处理外部回执，不能直接把本地入库量累加到定时回传的库存快照上。

清货费用和方数的数据位置继续预留；全链费用维护、分摊、结算与成本版本属于第五阶段。自动外部群投递仍未通过真实验证，本阶段不会调用旧群发接口、WorkTool 或发送真实消息。历史业务数据和旧集货、发运入口仍保留；正式切换和历史映射尚未执行。

## 权限和数据一致性

只有采购内部账号可操作批次和入库，继续使用 `supply.v2.view / supply.v2.manage`。供应商只读取本供应商发货单的派生物流状态及箱号附件，没有批次列表、其他供应商明细或入库写接口。

批次与入库使用全批次授权口径：批次包含任何不在当前 VIEW 或 MANAGE 范围的来源订单时，该批次对应读取或写操作不可访问。维护时校验租户、国家、仓库启用状态、单据版本和幂等键。创建批次还验证选中发货单的当前版本，防止使用过期选择结果。已集货后的发货价格按钮关闭，后台继续拒绝直接改价。

确认入库在同一数据库事务中完成收货凭证、来源行、状态与事件写入。任何步骤失败全部回滚；单据一对一凭证及来源行一对一流水约束防止重复记账。核对差异仍留在对应来源行，不因为短收自动修改采购或发货数量，也不自动计算成本。

新增菜单 `menu.supply.supply_chain_logistics.view` 只注册不授予现有账号。迁移 `0007` 增加入库确认字段，`0008` 增加内部流水，`0009` 注册菜单；迁移不清空或导入旧业务数据。

## 验收结果

后端 113 项和前端 58 项测试通过，相关后端 15 项、状态投影 1 项及前端 6 项定向复核也通过；复核不重复计入总数。Django 检查、迁移漂移、权限清单及完整前端构建通过。权限清单为 407 项、3184 个接口方法，前端 111 个菜单、144 条路由、367 项权限引用。

真实浏览器使用关闭 Mock 的前后端和独立测试库，完成两张发货单集货：一张未标记集货到仓、一张已标记；共 28 件，按三状态跟踪后选美国测试仓。四条实收来源行中短收 1 件，未填写差异原因时拒绝保存，补充原因后保存草稿仍无收货凭证，确认后产生 1 张凭证、4 条来源记录、共 27 件。第三方库存与外部入库记录未变化。采购和供应商均实际查看了发货单的物流日期；供应商页面没有内部调价或入库按钮。

390px 窄屏检查页面文档宽度仍为 390px，商品明细在自身容器滚动。截图、数据库检查摘要和测试 XML 随交付保留。浏览器记录的一次授权版本轮询 401 对应测试访问令牌到期，后续刷新和业务请求继续成功，无新增框架警告；CLI 点击一次选择框被占位层拦截，改点可见选择框容器后正常完成操作。构建仅保留既有 VueUse 的两条 PURE 注释提示。

## 技术入口与交付

前端入口：`/supply-chain/logistics`。API 均在 `/api/internal/supply-chain/v2/` 下：

| 功能 | 路径 |
|---|---|
| 可集货发货单、国家货运及仓库选项 | `dispatch-candidates/`、`dispatch-options/` |
| 批次列表、创建、读取、开船前信息修改 | `dispatch-batches/`、`dispatch-batches/{id}/` |
| 物流标记、选仓生成草稿 | `dispatch-batches/{id}/stage/`、`dispatch-batches/{id}/inbound/` |
| 入库列表、读取、核对保存、确认 | `inbound-orders/`、`inbound-orders/{id}/`、`inbound-orders/{id}/confirm/` |

候选源代码包是以父源码 `e63cd14783e0bc99a82097dd776df5e3b7e71001` 为基准的累计改动覆盖包，并非完整独立项目。另附以第三阶段索引树 `758ecd8a6a923018bb9fa57496382387845208b8` 为基准的第四阶段增量补丁。两个补丁均在独立临时索引重建核对；测试库、会话文件和真实凭证不进入包。

部署前需在目标数据库备份并执行迁移，给采购角色按需授予新菜单，再以实际数据库验证并发批次抢占和重复确认。当前回归使用独立 SQLite 文件库；MySQL 行锁并发、生产迁移和正式发布尚未验收。需要重新测试时重新创建回归库，避免事务测试清空权限种子后复用产生测试准备失败。
