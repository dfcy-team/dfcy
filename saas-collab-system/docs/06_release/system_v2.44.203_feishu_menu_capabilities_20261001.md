## 报表口径与审批边界

综合报表调用系统既有六类权限约束查询：订单销售、SKU销售、退款退货、平台流水费用、库存快照、库存估值。汇总实际数值；不同币种分列，不将跨SKU去重订单数相加，不将流水净额/库存货值称为利润。数据源无权限、暂无数据、不可用、截断分别标明。只有所有数据源均无权限才返回权限拒绝，所有源失败返回数据源不可用。

日报默认北京时间昨日，周报默认前7天，月报默认上月；日期最多31天。库存与成本按截止日期快照，不按日期差额伪造出入库。每次生成关闭报表结果缓存，重新校验收件人当前角色和数据范围。CSV仅聚合结果，UTF-8 BOM并中和公式单元格，不输出人员明细。

审批通知只来源于已保存的系统ApprovalRequest及其状态变更，事务提交后入队。待办排除申请人，并检查审批查看/审核权限及类型范围；执行时再次检查状态和权限，过期待办不会发送。通知打开`/workflow/approvals/<id>`，登录后原系统鉴权仍有效。扫码前仅暂存该固定格式的本地详情路径，5分钟过期、回调一次消费，拒绝外部地址和带参数路径；不改OAuth认证及绑定机制。

现有审批数据/业务提交入口不因飞书通知变为新的采购、财务等高风险执行入口。本批补充通知和既有简易审批界面，不承诺自动执行申请对应的业务交易。

## 投递、安全与运维

新增`integrations.0037_feishu_delivery`，依赖202的0036。仅创建持久化投递表，不改写业务或身份数据。幂等键按规则/事件/接收人隔离；飞书消息使用稳定UUID，成功不重发，最多3次受控尝试，超出45分钟的不确定发送停止重试。执行前复核规则配置摘要、绑定、账号、应用及规则配置人权限。未绑定记录为跳过，不冒充成功。

每分钟Celery Beat扫描排程并处理队列。畸形旧报表规则产生独立失败记录，不阻塞其他投递。新增规则前后端默认停用；旧不兼容规则需管理员编辑迁移后再启用，不把旧Approval Code发给飞书。

消息与CSV均走现有HTTPS域名白名单和有界网络通道；不放开任意外连。事件仅允许启用且配置Verification Token的连接；可选Encrypt Key开启AES解密、5分钟签名时效校验，schema2的app_id必须一致。只记录事件类型、原始体哈希和business_write=false，不记录消息正文或个人资料。事件订阅配置后方可验收实际接收，不能用模拟请求冒充线上订阅已打通。

新增非敏感配置`FEISHU_SYSTEM_BASE_URL`，不得混用环境：

- VM：`https://192.168.2.10:8443`
- 阿里云：`https://xtsy.dingfengchuangyu.com`

必须同时加载到backend/worker/beat；不传App Secret环境变量。回调采用`/api/feishu/events/<租户ID>/`，在正式部署后从系统页面复制。平台只能登记一个实际可达正式事件接收地址；VM私网地址不作为公共飞书事件订阅URL。
