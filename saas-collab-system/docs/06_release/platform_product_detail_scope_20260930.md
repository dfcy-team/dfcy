# 平台商品明细数据范围兼容修复候选（2026-09-30）

## 范围契约

平台商品明细含租户、平台、站点和店铺引用。`all` 只覆盖当前租户；`custom` 支持 `platform_ids`、`site_ids`、`store_ids`，并继续只读兼容历史字符串字段 `platforms`。同一角色的维度取交集，不同授予该操作权限的角色取并集。空列表不授予数据，缺失或非法范围拒绝访问。`warehouse_ids`、`supplier_ids` 不能直接映射到平台商品明细，任何包含这些字段的历史页面范围都拒绝访问并提示整改；角色保存时拒绝新增该组合。

页面附带的商品映射状态遵守独立的映射权限和范围。平台 ID 可通过已绑定店铺的平台引用安全过滤映射；站点等无法安全映射的范围仍隐藏映射内容，不阻断已获授权的商品明细，主动按映射状态筛选会拒绝并提示单独配置映射范围。

## 阿里云历史配置整改候选

2026-09-30 18:07（Asia/Shanghai）只读复查：目标账号可用页面权限来自共享业务角色，其范围只有三个仓库；页面 GET 仍返回 `403 DATA_SCOPE_INVALID`。该角色关联多个在用账号，不能从仓库范围推断其平台、站点或店铺可见范围。

管理员需先确定页面应显示的具体平台、站点或店铺，再从原仓库角色移除此页面的菜单与查看操作权限，保留原角色的仓库范围及其他权限；另建只授予本页面权限、范围为已确认平台/站点/店铺的角色，按实际需要分配给账号。若页面还需商品映射状态，应单独确认可用的映射授权范围。涉及共享角色的变更应核对其余成员的访问需求。此候选没有更改生产角色或数据库，也没有部署阿里云。

业务后续确认：共享角色 5 位在用账号需相同页面权限，范围为 Shopee 全部店铺（含停用）。只读档案核对显示 Shopee 平台 ID 为 6，当前有 27 家店铺、约 20,050 条平台明细。使用 `platform_ids: [6]` 表达该范围，未来新增到此平台的店铺也会落入授权范围；生产变更仍须在代码发布后按受控步骤执行并验收。

生产角色拆分的待审核差异：角色 36 保留 `warehouse_ids: [2, 3, 4]` 和其他现有授权，仅移除 `menu.listings.products_platform_details.view` 与 `listings.product_detail.view`；它原有的 `integrations.product_mapping.view` 显式授权也保留。新建独立角色授予上述页面菜单和查看操作，数据范围为 `custom {"platform_ids": [6]}`，分配给原角色的 5 位在用账号。映射查看会通过新角色的平台范围筛选已绑定店铺；原仓库范围不被丢弃或扩大。部署与线上角色变更后，分别验证 5 位账号的页面与映射状态、角色原有仓库权限，以及其他平台和租户不可见。
