# 运营补货的组合商品需求

运营订货单和采购单仍仅选择普通商品。补货依据纳入组合商品销售消耗：普通商品合计需求件数 = 普通商品直接销量 + 组合售出套数 × 历史构成中的组成件数量。例如组合含A×2、B×1，售出10套，则分别向A和B增加20件和10件需求。

国家参考清单、所选平台分析、最终建议预览共用折算口径。平台占比以折算后的需求件数计算，国家库存、按期到货及开放运营需求仍只扣减一次。页面分别展示直接销量、组合折算、合计需求；历史快照没有拆分字段时明确提示重新计算。

采用销售订单已保存的组合构成快照，不使用当前配方覆盖历史。缺少、无效、跨租户或嵌套组合构成不得默认为零消耗；提示待核对并停止输出相关范围的可下单建议。无法确定组成商品的缺失构成采用保守处理，可能阻止本次参考范围中其他商品的建议，需先修复源数据。

组合库存不换算为可用散件：虚拟组合不能额外增加库存；实体已包装组合尚无拆包换算流程，本次也不将其计入普通商品库存。金额和退款金额保留原商品原币口径，不虚构向组成件分配金额；退款继续单列，不自动抵减补货需求。

新建议记录计算口径版本。此前仅按直接销量生成的周期／季节草稿须重新计算、复核并保存后提交；仍可取消。历史已提交单据和人工新品订货保持原流程。

本次无数据库迁移。尚未部署虚拟机，不自动修改真实订单或历史构成。

验证：后端组合补货、国家库存决策、国家参考及运营订货共49项测试通过；前端需求依据、参考清单及运营订货共19项测试通过；前端生产构建、权限清单校验及CI guard通过。覆盖多组件、历史配方不变、缺失/重复构成、重映射、生效时间异常、嵌套组件、旧口径预览和草稿拦截、平台一致性、金额不分摊及组合库存不重复折算。

性能：组合订单按500条分块校验快照及组件，不逐订单或逐SKU查询；测试验证同一分块内1条与10条组合订单的查询数一致。尚未进行真实大数据压测或浏览器端到端验收，不能将查询数检查视为上线响应时间承诺。
