## 页面操作

入口：API 数据接入 → 同步任务 → Shopee 历史补采 → 对应批次的「调整补采范围」。销售订单、退货退款和财务流水均适用；调整的是历史补采日期，不是日常同步频率。

运行中的批次先「暂停」，待在途执行结束并刷新后调整。已暂停、已完成或失败的批次在满足安全条件时可调整。弹窗预填原起止日期，并显示不可裁掉的保护区间。新范围可向前或向后扩大，也可缩小未提交、未执行部分；不能排除已经提交或带断点的分段。

日期按北京时间计算，包含结束日，不允许未来日期；起止日期间隔最多 3660 天。结束日为今天时，只规划到提交当时的秒数，不声称覆盖未来时间或平台不再保留的数据。

确认弹窗展示旧范围与新范围。调整成功后批次保持暂停，原结果、失败分段、分页游标和检查点保留；需要再点击「继续」，不会自动执行、重试或重置日常同步策略。旧页面数据变化时拒绝提交，须关闭弹窗、刷新并重新打开。

## 后端安全规则

复用 POST `/api/internal/integrations/history-batches/{id}/action/`，参数仅允许 `action=adjust_range`、`start_date`、`end_date`、`expected_revision`。

事务按任务主键顺序加锁，再锁批次和分段。批次须已暂停或结束；有在途运行、执行锁或相同任务的其他未结束批次时拒绝。日期及分段版本标识由服务器重新验证，防止旧页面覆盖新进度。

非 pending、非首次 attempt、曾提交、存在运行记录或 history 游标的分段都受保护，分段 ID、原始查询范围和断点保持不变；仅替换未提交且无运行/游标的 pending 分段。各任务新范围减去保护分段后，按最长 15 天重新切分，连续且无重叠；新增分段使用未占用的序号。已有分段仍优先按原序号执行，新增区间不会抢占既有断点。

不删除 SyncRun、SyncCursor、SyncCheckpoint 或已采集业务行，不更新普通任务的 query、定时规则或增量水位。保留原创建幂等键及请求指纹，原创建请求重试仍定位同一批次，不重建旧范围。调整不触发平台请求、队列投递、令牌轮换或平台写入。

## 角色权限登记

- 查看：`integrations.history.view`，只显示当前租户和可见店铺范围。
- 调整：同时具备 `integrations.history.manage` 和 `integrations.run_live_readonly`，且批次的全部店铺均在这两个权限的数据范围内。
- 前端隐藏无管理权限的入口；后端独立检查，局部店铺可见不代表可修改整个批次。
- `permissions.0051_history_range_permission_description` 仅补充现有权限描述；不新增授权、不分配角色、不放宽数据范围。权限目录、接口清单及前端权限引用清单已同步。

每个任务生成 `history_sync_adjust_range` 集成审计，登记操作者、批次与任务、旧新日期、保留分段数、替换 pending 数、新 pending 数、旧版本指纹及 `auto_resumed=false`、`platform_write=false`，不保存 Token 或 Secret。
