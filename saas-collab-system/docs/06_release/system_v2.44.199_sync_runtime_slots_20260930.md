# V2.44.199 同步排程与分段续跑

登记日期：2026-09-30。父基线：V2.44.198 / `08f8872f859943838601d0a68560be3bd347badc`。用户已授权实施，并要求先验证虚拟机、再增量发布阿里云，保障任务仍可运行。

## 修改

业务消费者保留两个 prefork 进程，消费 `sync,celery`；新增一个独立控制消费者处理 `sync-control`，执行每分钟派发、失联运行回收和续跑巡检。两类消费者 prefetch 均为 1，保留 Redis 和既有默认队列，不增加云资源。库存派发使用 Redis 优先级 0，其余同步任务优先级 5。已经执行中的任务不会被优先级抢占。

同步策略新增 `execution_budget_seconds`，允许 0（关闭）或 60～720 秒，可单项或批量修改。预算用尽时完成当前页，将数据、计数、下一页游标和续跑待办一起提交，释放锁及执行名额；一分钟后由控制消费者提交续跑。同一采集保留运行编号和原始查询边界，重复续跑消息按序号拦截。全部页面完成才记录成功并推进检查点。

软超时直接记录失败并释放锁，不继续重试至强制终止；独立巡检也回收零数据的失联任务。默认强制回收阈值 960 秒，按每段实际开始时间判断。每分钟调度的错过容差提高至 180 秒。

运行详情展示单段预算、续跑序号及等待状态。每日时间选择支持分钟精度。

## 现有排程调整

阿里云快照包含 42 个每日任务和 3 个每 120 分钟库存任务。每日任务保留原始频率、采集范围、启停及错过策略，按近七日成功耗时估算分配到两条逻辑排程通道，增加一分钟间隔并预留奇数小时 :20～:26 库存窗口。逻辑通道用于错峰计算，实际由空闲进程消费，不绑定操作系统进程。

库存 #3、#4 调整至奇数小时 :20:40，#5 至 :23:40，保持每 120 分钟执行，并设为恢复后补跑一次。单段预算按估计耗时设置，最多 480 秒；库存预算分别为 120、240、120 秒。部署现场先核对快照漂移及活动任务，以事务仅更新计划字段并保存前后证据。

时间预算是分页让出的目标，当前页可能超出预算。平台错误仍会按原有错误处理和重试策略记录，不能将平台失败标为成功。低样本任务使用默认估值，后续可在界面调整。
