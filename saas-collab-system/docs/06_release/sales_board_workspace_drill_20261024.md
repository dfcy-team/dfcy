# 大屏商品下钻与库存映射排查（2026-10-24）

## 交付边界

基于 PR #378 的独立“实时数据大屏”菜单继续开发。大屏下降商品可携带日期、国家、平台、店铺、币种和平台商品 ID 进入销售工作台，定位该商品并打开原因详情；返回路径固定为大屏，恢复原筛选和下降分析视图。保留现有权限交集和按需查询，不增加大屏轮询。

本批不包含人民币历史汇率换算、库存自动回填或生产数据修改。生产部署仍需独立发布验收。

## 库存映射代码调查

以下是代码机制，尚不能当作生产样本根因：

- `backend/apps/sales_management/services.py` 的订单行 upsert 保存平台商品、规格和 seller_sku，但不回填 internal_sku / internal_spu。
- `backend/apps/sales_management/board_products.py` 的系统商品维度依赖订单行同租户 internal_sku；缺失归入未映射，不能作为零库存。
- `backend/apps/integrations/product_mapping_service.py` 的商品映射更新平台商品明细与映射记录，不同时回填历史订单。
- `backend/apps/integrations/order_product_gaps.py` 已有平台目录缺口聚合分类；其 Shopee 零规格规范化规则必须与诊断保持一致。
- `backend/apps/commerce/management/commands/link_sales_skus.py` 有唯一匹配回填工具，但即使预览也使用 select_for_update 并读取租户全量候选。不可直接拿来充当线上无锁只读诊断。

## 下一步生产只读核实口径

限定已授权租户、单店铺及日期窗口，设置查询超时；数据库执行聚合，不把完整订单或 SKU 字典交给模型。

1. 统计订单行数、internal_sku / internal_spu 空值数、平台商品与规格身份缺失数。
2. 按同租户、平台、店铺、商品、规范化规格精确关联平台明细，区分目录缺失、规格缺失、身份冲突、明细无内部 SKU、明细有 SKU 但订单未回填。
3. 仅对未解决组检查 SKU 主码、旧码和有效别名的唯一/零/多目标命中。保留店铺和生效时间约束，禁止按标题猜测。
4. 输出聚合计数及每类最多 20 条脱敏异常；确认缺口后再定义独立修复批次。未映射、未观测和零库存保持区分。

## 验收重点

精确商品过滤在数据库分页之前执行；非法参数不得退化为全量查询。路由复用时重新读取筛选，旧请求不得覆盖新范围。无工作台权限时不显示跳转。返回大屏不接受外部 URL。前后端定向测试、构建和权限清单检查结果以本批最终交付记录为准。
