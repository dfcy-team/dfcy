# V2.44.102 达人管理刷新性能优化

日期：2026-09-14。发布基线：V2.44.101，`56e7e2d88b7d994769021605c1c5b9c3002a8c6b`。

## 优化内容

- 达人档案、建联任务、送样履约默认使用无精确总数快速分页，不再为每次刷新执行全量 `COUNT(*)`；旧接口默认行为保持兼容。
- 建联任务列表按当前页批量聚合达人、送样状态和视频数量，不再加载每个任务下的完整关联对象。
- 送样履约列表使用 `include_items=false` 时仅返回首个 SKU 预览及主表汇总字段；完整商品明细仅在详情或编辑时读取。
- BD 绩效按租户、日期范围、归因规则、币种和订单数据版本缓存 30 秒；生产环境复用现有 Redis。
- 前端分页改为明确的上一页/下一页导航，不展示未经计算的虚假总数。

## 兼容性

- 列表接口未传 `include_count=false` 时仍返回精确 `count` 和原分页行为。
- 送样接口未传 `include_items=false` 时仍返回完整 `items`，保持旧调用方兼容。
- 快速分页返回 `count=null`、`count_exact=false`、`has_next`、`next` 和 `previous`。
- 送样详情接口继续返回完整 `items` 和 `video_matches`；创建、编辑和导出契约不变。

## 验收口径

- 快速分页 SQL 中不存在精确 `COUNT(*)`，且下一页判断不漏数据。
- 建联任务列表序列化过程中不产生逐任务查询，汇总字段与原实现一致。
- 送样列表不预取完整 `items`，编辑前按需拉取详情。
- 相同条件的连续 BD 绩效请求只执行一次事实聚合，缓存最长 30 秒自动失效。
- 相关后端测试、前端测试、生产构建和 Django production check 全部通过。
