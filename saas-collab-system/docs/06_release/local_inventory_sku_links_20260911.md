## 当前整体映射逻辑（代码核对）

1. 内部商品主档：ProductSKU 的主键是实际关联目标，sku_code 是内部编码；legacy_sku_code 和 ProductLegacyItem.generated_sku 提供旧编码到主档的对应。
2. 平台商品：`listings/platform_product_details.py` 将编码做 NFKC 规范化、移除 Cf 格式字符、去首尾空白、casefold。新编码查内部 sku_code；旧编码查上述两类旧编码来源。同一目标去重后必须唯一。新旧编码同时提供时必须指向同一个 SKU；只提供普通平台 SKU 时查新旧编码候选的并集，不能靠新编码优先覆盖旧编码冲突。
3. 平台商品 API 入库：`integrations/platform_product_ingestion.py` 使用上述解析器，结合店铺、平台商品/变体身份核验建立规范商品明细和映射。满足确定性匹配及状态条件时可记录 api_exact_match；未知编码保持待处理、多个候选或不一致标记冲突。普通建议不会直接变成已确认映射，已有确认不会被新同步静默替换。
4. 仓库库存：`commerce/services.py` 以租户、站点、仓库、source_sku、snapshot_at_utc 识别同一快照，保存平台库存原始数量。本次已回填的 965 条通过 internal_sku 指向商品主档。同一快照更新不清除该关联，但新时间点的快照尚未接入自动 SKU 解析或继承。
5. 订单/退款：当前 `sales_management/services.py` 的规范化写入并没有自动填充内部 SKU；平台商品映射与库存回填不等于这些事实明细也已经完成关联。

因此当前不是一套已经全链路贯通的自动映射：商品解析已有规则，本地库存是显式回填。此次操作未扩大到订单、退款，也未修改未来同步行为。
