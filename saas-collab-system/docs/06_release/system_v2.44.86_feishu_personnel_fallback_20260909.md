# System V2.44.86 飞书历史人员归属兼容

## 目标

V2.44.86 为 `feishu_full` 全量历史达人数据提供受控人员归属兼容：当来源负责人或调度人在租户 1 中没有唯一合格的启用内部 BD 账号时，只对“零匹配”使用既有账号 `liyejun`；来源原始姓名保存在业务记录的专用只读快照字段中。

## 安全边界

- 唯一合格账号仍按真实账号归属；多匹配继续阻断，不能自动选择。
- 回退账号必须是租户 1 中唯一、启用、内部 BD 的 `liyejun`；账号不再合格时导入 fail closed。
- 任务保存来源负责人、来源调度人快照；送样保存来源负责人快照。原文不截断，超过字段上限时阻断。
- 专用快照只能由固定来源 `feishu_full_20260908` 的受控导入服务写入；普通创建、编辑及伪造来源的 API 请求均不能写入。
- OperationLog 同时保存来源姓名、实际用户 ID、解析原因和固定策略版本；相同来源批次重放不得升版或重复产生日志。
- 既有冻结 BD 归因不重写；实际业务 owner/dispatcher 使用解析后的账号。

## 发布与导入顺序

1. 合并并发布本版本，完成严格以 V2.44.85 为父版本的双账本登记。
2. 在新导入作业准备完成后，归档旧 V2.44.84 检查失败标记和旧审批；不删除证据、不复用旧执行令牌。
3. 对固定脚本、固定数据文件和固定镜像只做一次 check-only，确认人员回退统计、隔离统计、旧业务号收养及手工冲突别名均符合预期。
4. 进入连续维护窗口，暂停前端与异步写入，创建完整 MySQL 备份并在一次性隔离数据库中恢复验证；备份成功后保持维护状态。
5. 对同一脚本、同一数据哈希和同一审批升级为 apply，一次执行；完成只读 post 指纹、同批次幂等重放和既有归因保护核验后才恢复写入服务。
