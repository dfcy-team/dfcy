## 问题与修复

兰鑫、詹志强的运营角色同时包含店铺、平台、仓库范围；广告数据集原先仅检查通用 analytics_summary 报表类型，无法解析上述混合业务范围。单独增加 report_types 仍会失败。

新增 reports.advertising 资源（仅 store_ids 维度），复用已存在的报表资源适配器。入口校验通过后，广告查询仍需同时满足原 analytics.view、租户、日期/筛选和新广告报表店铺范围；飞书再与实时店铺负责人/组长关系取交集。无显式新资源时保留原有效旧授权。不得放宽通用 permission_scope_configs 或授予全部报表。

本候选不改数据库结构，不自动授权用户，不更改消息任务、不补发历史消息。前端资源目录通过现有接口返回新增资源，不增加独立菜单。

## 发布后的授权配置

使用现有权限管理接口/页面及具备委派权限的管理员。用户已在本对话批准两人现有店铺范围内的广告报表查看授权。执行前重新核对账号、租户、当前店铺关系、有效广告数据权限，保存原角色绑定、资源策略和推送规则；出现变化时重算范围，禁止直接套用旧快照。

分别创建两个专用自定义角色（建议 code: feishu-ads-report-lanx / feishu-ads-report-zhanzq），仅授予 action reports.view，不增加菜单、字段、导出、管理权限。通用范围设置 CUSTOM store_ids；资源策略只设置 reports.advertising / permission_code=* / CUSTOM store_ids，两个 store_ids 列表相同。列表取该用户执行时既有广告数据可见范围与负责人/组长关系的交集，空集停止授权。不要使用 ALL、不要改共享 operations-Shopee 角色。

分别追加绑定到 lanx(id59)、zhanzq(id60)，不得替换原角色绑定。其他用户不绑定。现有预览/应用接口的 transfer 会替换指定 source 下全部 tenant 绑定，并非追加接口。仅在该用户 source=position、context_key=tenant 的绑定完全为空时，使用 transfer / replace_source=position 提交该用户的新专用角色；其他 source 原绑定保持不动。若已有任意 position 租户级绑定，停止此步骤，另行制定保留其状态、有效期和完整角色集合的方案，不得只提交新角色覆盖。预览必须显示无移除权限，应用后核对原绑定逐项未变，并保存角色ID、绑定ID和前后范围回执。

注意：此处 store_ids 是显式授权上限。后续负责人/组长变动会实时收紧飞书推送；新增负责店铺需要按权限管理流程同步调整专用角色范围，不会自动扩大授权。
