## 完成内容

复用 Shopee 平台商品只读任务，增加 `product_order_backfill` 策略：

| 值 | 页面名称 | 行为 |
| --- | --- | --- |
| `catalog_and_order_missing` | 常规同步后补齐订单缺失商品 ID（默认） | 常规目录完成后，按本店订单缺口定向读取商品基础信息和变体 |
| `order_missing_only` | 仅补齐订单缺失商品 ID | 不扫描常规列表，不按月或日期过滤，针对已落库订单的缺口补采 |
| `catalog_only` | 仅常规商品同步 | 保持原有目录采集，不进入订单缺口阶段 |

已有 Shopee 商品任务未保存策略时，部署本候选后默认采用第一种策略。不会变更任务启停、定时规则或主动派发任务。Lazada、TikTok 和其他资源任务不启用此补采能力。

任务配置抽屉新增手动“只读预览当前缺口”：显示源明细行数、去重关联对、已关联、缺少商品/变体、身份冲突、无效 ID、零变体及最多 20 条样本。任务列表摘要与采集范围同步体现所选策略。预览与保存都不会触发采集；仅补齐模式隐藏不适用的日期范围。

## 关联与安全边界

- 仅校验同租户、平台、店铺、生产/试运行环境的已落库销售订单；同时验证订单来源配置、运行记录和销售订单任务范围。
- 使用平台商品 ID + 变体 ID 的真实身份，不按名称或相似 SKU 猜测。订单 `model_id=0/空值` 按 `item_id` 单变体身份校验，历史订单不改写。
- 每页最多 50 个有效数字商品 ID。水位与商品 ID 游标冻结一次采集范围，支持同次运行断点续跑；后来新到订单由下一次采集处理。
- 复用授权、只读准入、PRODUCT 能力、出站域名、运行互斥与幂等落库。默认单段预算 240 秒，复用现有自动续跑机制。
- 所有 Shopee 商品模式均防止已有变体被改挂到另一商品，包括尚未关联内部 SKU 的变体；冲突跳过且保留审计结果。
- 平台未返回或已删除的商品、空模型结果继续保留缺口，不生成伪平台商品，不声明历史覆盖完整。运行结果记录前后差集、尝试商品数、平台未返回数量和冲突。
- 缺口预览仅返回聚合与有界样本；合并统计/样本查询避免重复扫描，常规目录完成后用聚合结果判断是否进入补采。
