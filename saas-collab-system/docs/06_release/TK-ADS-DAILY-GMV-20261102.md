## 实现

- 新增 `backend/apps/integrations/gmv_max_schedule.py`：7天窗口、逐日执行和脱敏失败结果。
- 新增管理命令 `sync_tiktok_gmv_max_recent --tenant-id 1 --actor-id 1 --commit`。
- 不带commit只做本地配置预检查和计划输出，不调用平台、不入库，也不声称已核验官方GMV Max归属。
- 复用现有 `gmv_max_sync.run_day`，保留权限、共享租约、分页完整性、币种时区及提交前再次校验。单日失败继续其他日期/广告户，最终失败退出，不将部分成功当成全部成功。
- 外层flock防重复批次，内层原有Ads租约与其他广告采集互斥；不抢锁、不自动重试、不重启服务。
- 继续写入经过验证的广告RAW快照及成功审计，展示服务按观察时间选每广告户/店铺/日期最新事实，不累加历史快照。不是新增财务、销售或视频表数据。
- 空报表不作为零消耗。失败记录在systemd journal中，仅输出受控错误代码和异常类型，不输出凭证或原始异常URL。
- timer为Persistent=true，关机错过执行时只补触发一次滚动7天任务，不按停机天数重复调度。
