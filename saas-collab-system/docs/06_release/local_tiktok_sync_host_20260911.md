# TikTok 同步域名读取修复（本地）

## 原因

任务 5（订单）和 7（退款退货）已启用且能力就绪，但请求客户端读取接入配置的旧 `platform_config.api_host`。该字段为空；已批准的生产配置中已有域名。运行在发出 HTTP 请求前失败，随后被通用重试处理包装为 `MAX_RETRY_EXCEEDED`。

## 修改

- TikTok 只读客户端从 `get_runtime_platform_config('tiktok')` 读取 API 域名，不回退到旧租户元数据。
- 域名缺失检查前移至预检查，缺失或占位符配置在入队前返回明确中文说明，不读取凭据、不访问平台。
- 增加专用 `ReadonlyConfigurationError`；如果运行中出现该配置错误，立即结束并释放锁，记录 `SYNC_CONFIGURATION_MISSING`，不重试。不改变其他异常的既有重试行为。
- 保持授权、能力、审批、白名单和禁止写回检查不变。

## 验证

- 77 项测试通过（SQLite 隔离、禁网络、`--nomigrations`）。覆盖旧域名存在/缺失、生产域名优先、配置缺失不读凭据、不发请求、配置错误零重试、瞬时异常继续重试、失败锁释放、检查点不推进及既有授权保护。
- 对真实任务 5、7 做只读预检查，两项通过；凭据后端和 HTTP 请求均被测试替身阻断，确认没有创建运行或修改任务。
- 本地后端与专用手动同步 worker 已重启；8002 端口监听和 worker ping 正常。未启动 Beat。
- 未发起真实同步，未更改生产配置、授权、任务开关或历史失败事件。实际平台请求及数据同步结果需用户执行一次真实同步后验证。

历史失败记录保留；修复不会把旧运行改为成功。
