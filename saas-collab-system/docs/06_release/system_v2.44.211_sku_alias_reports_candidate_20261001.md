登记预留日期：2026-10-01；界面验收日期：2026-10-02。权限基线为已在虚拟机及阿里云登记部署的 V2.44.210，提交 `497223d6004a77d5b7aec0d6191ca4e30aee7bf9`。代码基线已集成主分支 `d42fdf766373dd0c54c8019423d8261692592601` 的库存报表仓库范围修正（PR #278）；该修正的 V2.44.212 独立发布登记保持归原任务所有。

## 用户可见变化

商品明细编辑页提供历史 SKU 别名记录，含来源旧码、有效期间、原因、来源和版本。新增与结束生效期沿用商品主数据读写权限，服务端按稳定 SKU 及资源范围校验；操作写入审计，结束生效期要求记录版本一致。每次商品重编码自动记录之前的内部码，保留稳定商品 ID。

销售 SKU、订单及退款穿透、库存工作台、库存分析和 BI 支持 `related`（同商品关联编码）与 `source`（原始来源编码）两种口径。可通过映射核对日期选择生效期间；保留当前内部码与来源码。旧兼容模式保留原行为。手工别名支持租户、店铺或仓库来源范围，歧义编码拒绝自动选择。

演示验收口径：OLD001 销量 8、NEW001 销量 2，已确认同一稳定 SKU 时关联查询为 10，OLD001 原码核对为 8。库存按站点、仓库及稳定 SKU 取最新快照；同批次多来源码不能推定改码，关联查询拒绝自动累计，可用原码查询核对。历史来源事实和现有成本版本不因别名变化改写。

BI 的字段拖动、透视与看板复用这些筛选。库存穿透使用已应用的查询条件，并传递成功查询时的“包含虚拟商品”状态，修改中的草稿不改变穿透条件；其他穿透保留查询条件及来源行约束；自助导出保留已查询配置、指标版本和映射版本。销售明细文件导出支持相同编码口径，仍导出命中订单的商品行。文件授权和已签发下载令牌均再次核对来源权限快照，策略变化后需重新导出。

报表目录收敛为“报表目录、已保存报表、自助分析、组合看板”四个页签；我的报表和团队共享在已保存报表中切换，待接入清单折叠。自助分析默认显示常用筛选和结果，字段拖动、图表和排序按需展开。组合看板默认用于阅读，点击“调整看板”才展开组件库及布局操作；日期和编码口径为常用条件，其余筛选折叠并显示已选项。库存工作台按“查询”应用条件，输入变化不立即读取数据。

报表状态、费用分类、错误、导出类型、时间和仓储来源说明统一为中文；保留 SKU、币种和来源业务编码。店铺、仓库结果优先显示名称，查询和穿透仍使用原始编号。经营分析、销售、库存、财务和广告占位复用一致的标题、常用条件、折叠说明和结果层级。广告保留待接入状态，说明当前可查看内容及后续开放条件。

## 与 V2.44.210 权限模型衔接

新增范围适配器，不增加操作授予：

| 资源 | 支持维度 | 使用位置 |
| --- | --- | --- |
| `products.master` | SKU、SPU | 商品主数据及别名读写 |
| `products.cost` | SKU、SPU、仓库 | 成本及库存货值读取 |
| `sales_management.sales` | 店铺 | 销售、退款、BI 和销售导出 |
| `commerce.inventory` | 仓库、SKU、SPU | 库存查询及库存 BI，按请求业务上下文解析 |

同一资源策略各维度取交集，不同有效角色取并集；操作级策略优先于资源通配策略；未配置策略继续使用现有角色基础范围。沿用有效角色、组织上下文、绑定到期及权限生命周期规则。商品目录授权与销售事实授权各自校验，配置商品目录范围不会隐式改变独立的销售授予。

资源策略编辑器提供 SKU/SPU 中文选项和当前编码标签。按需读取商品选项，每类搜索结果最多 100 条，加上最多 100 个已选项，总计不超过 200 条；租户及角色管理权限保持校验。销售资源本次只支持店铺范围，不开放混合 SKU 订单的 SKU 级授权，避免把订单金额和商品行的授权粒度混为一体。

## 菜单归属

复用现有入口，没有新增菜单或改变稳定编码。菜单快照 108 项，路由快照 142 项；组合看板是报表中心内的能力，业务页提供带模块上下文的看板入口。

| 模块 | 菜单及路径 | 本次覆盖 |
| --- | --- | --- |
| 销售管理 | SKU 销售 `/sales-management/skus`、销售订单 `/sales-management/orders`、退款退货 `/sales-management/returns` | 编码口径、查询和销售展示 |
| 库存管理 | 库存工作台 `/inventory/workbench` | 常用筛选、显式查询、库存结果 |
| 经营分析 | 销售分析 `/analytics/sales`、库存分析 `/analytics/inventory`、广告总览 `/analytics/advertising-overview`、广告投放分析 `/analytics/advertising-performance` | 分析层级和广告占位 |
| 财务中心 | 财务分析 `/finance/analytics`、广告费用对账 `/finance/advertising-reconciliation` | 流水费用、库存估值和广告对账占位 |
| 报表中心 | 基础报表 `/reports/basic`、报表导出 `/reports/exports` | 目录、保存视图、自助分析、组合看板及导出审计 |
| 基础档案 / 系统管理 | 商品主数据、商品明细 / 角色权限 | SKU 别名及资源范围配置 |

目录中的销售、库存、财务标签表示业务归属。目录查看报表进入报表中心分析区；“穿透”进入可核对事实的明细页面。SKU 销售穿透到订单核对商品行；库存估值归财务分析，进一步核对历史库存快照和成本时进入经营分析的库存分析页。穿透位置与报表所属模块分别按业务职责确定，跳转仍校验目标页面权限。

## 数据和读取效率

新增 `products.0027_productskualias`，仅添加别名表、索引与有效期间/范围/版本约束，不执行业务回填。与已部署 `permissions.0049` 分属不同应用，无依赖冲突。

别名通过租户和编码 SHA256 索引解析，再在已授权事实内确定稳定商品；不逐行连接全部别名。批量库存入库每页复用一次别名读取，并按事实时间匹配。历史销售及库存回填命令保留预览、匹配数确认、只写未关联外键和审计规则；本次验收未执行正式数据回填。

库存继续使用窗口函数确定最新身份集合，避免依赖逐行 LIMIT 子查询。BI 缓存包含实际业务资源范围及映射版本；展示布局变化复用同一已授权汇总。MySQL 的原码精确核对在来源字段候选条件后使用 SHA256，避免 `utf8mb4_bin` 的尾部空格折叠。

报表目录只读取一次数据集，保存视图首次打开时再读取，子分析与看板复用已加载目录。明细和指标卡每页 50 条，透视表每页最多 25 行 × 12 列；这些翻页和展开设置均不重复查询。图表最多显示 40 个分组，看板最多 8 个组件、同时读取最多 3 个组件，保留旧请求取消和过期响应拦截。结果名称仅查询已授权结果中出现的店铺、仓库编号，每种维度一次批量读取，不加载全部主数据。查询结果上限仍为 500 个分组，缓存 60 秒；缓存指纹新增报表查看范围，仓库授权收窄后不复用旧结果；缓存命中前在当前授权范围重新验证 SKU 身份，新产生歧义时返回 400。
