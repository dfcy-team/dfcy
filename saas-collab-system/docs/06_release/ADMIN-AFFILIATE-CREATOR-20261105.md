## 未解决问题与正式化要求

- 锁竞争尚未彻底消除；小批次与退避只是运行层缓解，不是应用全局锁逻辑修复。
- API 返回缺少身份字段、页面格式异常、权限/授权异常不能由“按最新数据”授权绕过。TKKJ3MY 9 月 6 日缺 API 身份字段已隔离。
- 最初队列及后续队列均可能因隔离或资源保护结束。启动器 exit code 0 也不表示业务全部成功，必须查 runner_finished.blocked、逐店日期覆盖及 SyncRun。
- 一次性脚本身份修正提交与 BD 重算不是同一事务，进程中断可能留下需补算的记录。后续工程化应采用持久化 outbox/断点；本次不能声称已有完整自动恢复。
- 原 run_sync_job 自身返回 failed 时外层异常退避不一定重试；所有失败需按幂等键与实际已提交结果核对，不得简单换键全量重跑。
- 每日定时任务是否启用须在业务库中独立核查。本 PR 不把手动历史任务改为定时任务。
- 归档脚本含固定租户、店铺范围与历史日期，不是跨租户通用工具。未经检查不得复用，更不能直接纳入发布执行链。
