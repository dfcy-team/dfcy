# V2.44.104 达人管理列表可见性修复

日期：2026-09-14。发布基线：V2.44.102，`918ced69c8ec701f4803f94e62577ff95d08450e`。

## 问题

V2.44.102 上线后，达人档案、建联任务、送样履约和 BD 绩效出现列表无数据。代码检查确认快速分页响应仍包含 `results`，但生产异常发生时未保留完整接口状态码和异常栈，因此不能将问题归因于单一 SQL。

## 修复

- 回退 V2.44.102 中影响四个菜单运行时取数契约的快速分页、批量聚合、送样轻量列表和 BD 缓存。
- 前端恢复使用稳定的精确分页与完整列表字段，避免实验性参数影响生产展示。
- 保留 `0020_influencer_query_efficiency` 空迁移，确保本次发布不会创建索引或再次等待 MySQL metadata lock。
- 保留生产迁移超时与 MySQL metadata lock 等待上限，降低后续发布长时间阻塞风险。
- 增加建联任务非空列表回归测试，并复用现有达人档案、送样履约和 BD 绩效非空/零态接口测试进行验收。

## 验收口径

- 四个达人管理菜单对应接口均返回 HTTP 200，并能返回当前租户已有数据。
- 前端不再发送 `include_count=false` 或 `include_items=false`。
- Django migration check 不生成新迁移，`0020` 不包含表或索引 DDL。
- 后端相关测试、前端测试和生产构建通过后方可发布。
