# 数据读取优化候选发布与回滚

目标是阿里云正式系统。候选分支 `perf/data-read-audit-20261003`，已验证基线 V2.44.215 / `2141d8069ab210d4f5874dd8441622064ed4d423`。本文件不构成上线批准，候选尚未发布。

## 审阅范围

后端修改位于 permissions/ui_p6_scopes、reports 的 datasets/dashboard_config/dataset_views、workflows 的 views/serializers、masterdata/serializers、products 的 views/cost_views；另有相应查询预算及行为测试、项目性能 skill 和验收证据。

候选不包含 schema migration、数据回填、模块开关修改或外部平台调用。四个停用模块的生产代码没有被优化。

## 批准后的发布关卡

1. 使用既有可信发布通道只读复核 current-version 指针、运行容器 revision 和当前模块开关。若正式 SHA 已变化，先整合新基线并完成冲突文件的针对性复验，不能覆盖其他对话的发布。
2. 审阅本候选 diff 和 `docs/05_test/data_read_audit_20261003/README.md`，按现有版本分配流程取得新版本号；本候选未抢占或猜测版本号。
3. 通过现有正式发布流程构建和发布后端候选，保留上一个已知正常 release 指针、镜像及发布清单。无需执行新数据库 migration 或数据修改脚本。
4. 用有授权的正式账号检查报表目录/保存视图、三种工作流列表、仓库列表、商品详情筛选与翻页、商品详情 CSV、成本仓库选项。核对同页结果、汇总、租户隔离、错误状态和导出数量，不以合成速度替代业务验收。
5. 在既有日志/监控能力内比较发布前后同条件请求的错误率和时延；有摘要权限时再读取数据库扫描指标。没有摘要权限时明确记录未测量，勿改权限或编造 P95。

## 回滚

发现权限范围扩大、数据/顺序/汇总不同、分页或导出失败、错误率/时延明显恶化时，使用现有发布回滚流程切回发布前镜像和 release 指针，再核对 runtime revision 和上述读取入口。此候选没有 schema 或数据迁移，不需要数据库逆向变更。产品分页缓存使用 v3 独立 namespace 和 60 秒过期；旧版本回滚使用 v2，不读取候选的页缓存。权限缓存只存在一次请求内。
