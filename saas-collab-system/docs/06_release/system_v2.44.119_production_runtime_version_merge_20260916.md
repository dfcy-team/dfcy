# System V2.44.119 生产运行时配置版本合并修复

## 发布目标

修复“业务模块发布控制”只提交 `modules` 局部节点时，新版本覆盖并丢失生产网络、密钥托管、平台和全球刊登策略的问题。

## 变更内容

- 生产配置版本写入 API 不再将局部 JSON 当作完整版本。
- 任何局部提交先与当前已解析的完整运行时配置深度合并，再校验并存入不可变版本。
- 保留现有双人审批、作用域权限、敏感字段拒绝和生产写入安全门。
- 新增回归测试，覆盖“仅更新 API 接入模块状态时，域名白名单和 OAuth 回调白名单必须原样保留”。

## 数据恢复方案

代码发布并验证后，在阿里云以 V7 完整文档为基础，仅合并 V8 的 `modules` 节点，创建新的待审批版本。不编辑、删除或覆盖 V7/V8 历史记录。新版本由另一名系统管理员审批后生效。

## 发布范围

- 后端代码和测试：3 个文件。
- 发布记录：本文件。
- 无数据库迁移。
- 无菜单、路由、权限目录或中文显示文案变更。
- 无 Compose 结构变更。

## 验收标准

1. `backend/tests/test_production_runtime_settings.py` 全部通过。
2. 局部 `modules` 提交产生的待审批版本包含 `network / connection / custody / listing_write / platforms / modules`。
3. 虚拟机和阿里云运行容器均使用 V2.44.119 同一提交，健康检查通过。
4. 阿里云新建完整待审批配置版本，V7/V8 审计链保留，未进行自审批。
