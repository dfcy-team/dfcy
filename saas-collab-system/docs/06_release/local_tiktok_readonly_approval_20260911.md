# TikTok 订单/退款审批来源修复（本地）

## 原因与改动

本地 TikTok 的正式运行配置 `contract_approved=true`，ORDER 和 RETURN_REFUND 能力均已启用，但只读客户端在订单/退款预检查时读取接入配置的旧字段；该字段缺失，导致误报 `Platform readonly contract is not approved.`。

`readonly_clients.py` 将 TikTok 纳入版本化生产审批读取范围，与 Shopee 一致。不把审批复制到租户配置，不关闭审批检查，不改变其他平台行为。商品审批依然独立；生产审批缺失或拒绝时，旧字段为 true 也不能放行。

## 验证与边界

- 新增 19 项 TikTok 测试，覆盖生产审批放行、旧配置不能覆盖正式拒绝、商品与订单退款审批隔离，以及网络/只读/环境/状态检查。
- TikTok 与 Shopee 只读审批专项合计 26 项通过。
- 完整迁移回归首次 47 通过、1 条旧审批夹具失败；将令牌过期测试改为正式运行审批后，全部 48 项通过（重跑使用隔离 SQLite、跳过迁移）。过期拒绝与不隐式刷新断言保留。
- 真实本地任务 5（销售订单）与 7（退货退款）预检查通过。验证时禁止 HTTP 请求，使用不可读取凭据的替身；真实配置、主体授权和能力检查未替换。
- 未修改审批、能力矩阵或任务开关，未创建 SyncRun，未调用真实平台。

用户刷新本地同步任务页后可重新点击“启用任务”；启用不等于执行，真实同步仍需单独触发并通过运行时校验。

本地后端及专用只读 worker 已重启加载修复，未部署到虚拟机或云端。
