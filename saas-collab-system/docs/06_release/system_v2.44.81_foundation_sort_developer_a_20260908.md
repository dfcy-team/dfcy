# V2.44.81 基础档案排序与开发 A 授权增量发布说明

本版本以已部署 V2.44.80 / `54b29fea04beba390595ebda403e5678fc761b45` 为唯一父基线，
合并两组已核定、未登记的净增量。不以开发工作区或旧候选 ZIP 整体覆盖主线。

## 发布范围

1. 基础档案商品排序：
   - SPU 列表按最近更新时间、ID 倒序。
   - 商品明细将旧明细与未链接 SKU 合并后先按最近更新时间排序、再分页；已生成映射取同租户 legacy/SKU 中较新的时间。
   - 保留 V2.44.80 的数据范围、链接去重、筛选、越界页纠正及“仅序列化当前页”性能边界。
   - 跨租户脏关联不得用外租户 SKU 时间影响排序，也不得回传其编码、名称、价格或图片。

2. 开发 A 已审核且完成 A1/A2/B1 整改的两项功能：
   - 极风 WMS 仓库级 OMS Email、一次性 Token 托管、首次授权、刷新、只读校验和库存同步就绪门禁。
   - Shopee/TikTok/Lazada 店铺授权的手动回填 HTTPS 回调地址入口，并与自动回调共用当前用户、租户、店铺、接入配置及数据范围复核。
   - 同一仓库授权请求重放不再重置 OAuth/一次性 Token；同 key 不同载荷拒绝且不变更原授权。
   - 错店铺、错配置或授权后权限收窄的回调均失败关闭，撤销新换取但未落库的托管引用，不更改旧授权。

开发 A 净增量来自已审核本地提交
`c492ecabe1c402118a457803a9f0a35d18c18da1`（父提交 V2.44.79），共35个文件。
该提交与 V2.44.80 的17个变更路径无交集；重放到 V2.44.80 时文本无冲突，并对35个目标 blob 逐一校验一致。

## 数据库与发布边界

- 新增唯一迁移 `integrations.0025_warehouse_credentials`，依赖 `0024_platform_product_readonly_sync`。
- 迁移只扩展仓库授权字段并放宽既有 `token_id` 为空；不删除历史授权数据。
- 本版本不更改菜单、前端路由或权限目录；后端仅注册上述已审核的授权与回调端点。不启用新的对外网络白名单，不发起真实店铺或 WMS 授权，不导入业务数据。
- 真实极风联通验收仍受生产网络白名单、公共配置和仓库一次性 Token 约束；代码上线不等于已完成真实授权。
- 回退时使用 V2.44.80 不可变前后端镜像；新增字段保留，不自动反向删除授权与托管引用。

## 验证要求

- 后端需通过商品统一排序、极风仓库凭据、幂等重放、手动/自动回调及租户/数据范围反例。
- 前端需通过极风仓库表单、API 接入弹窗、手动回调敏感输入清理、授权状态及既有全量回归和生产构建。
- 发布前需通过仓库基线、凭据扫描、菜单权限快照、Compose 配置、迁移漂移及安全检查。
- 生产发布使用精确合并 SHA 构建不可变镜像，先备份 MySQL，再执行迁移、切换、健康检查和双账本登记。
