## 3. 缺陷清单

### D01 [P0] 新增预览隐藏原有同步任务主体

- 位置：`frontend/src/views/integrations/SyncJobList.vue:13`，尤其第 14–15 行。
- 分类：功能/状态渲染。
- 证据：`AppState v-if` 与其原有 `template v-else` 之间插入 `MissingSyncJobsPreview v-if`。`v-else` 改为绑定预览条件。当前有 `integrations.manage` 且不在商品同步上下文时，只渲染预览，健康摘要、事件与任务主体不再显示。刷新可重复出现。
- 影响：管理员不能从该入口查看原有任务、健康和事件；是上一批本地增量引入的回归，不是数据库为空造成。
- 建议：将独立预览放到原有条件分支之外，保留 AppState 与主体分支对应；增加整页 ready/empty/error、管理员/普通权限、商品同步上下文渲染测试，不能只测子组件。
- 复测：未修复，待复测。建议 `$impeccable harden`。

### D02 [P1] 无销售数据仍显示质量评分满分

- 位置：`backend/apps/sales_management/views.py:666`；`frontend/src/views/sales-management/SalesWorkspace.vue:31`。
- 分类：数据可信度/错误反馈。
- 证据：无 checked_rows 时后端评分为 100；页面同时显示“等待首批数据”“尚无成功数据”与“100/100”。
- 影响：用户可能把没有样本理解为数据已经校验且质量优秀。
- 建议：无样本返回不可评分/null，页面显示“待评估”，保留样本数；分别测试 0 样本、部分异常、完整样本。建议 `$impeccable clarify`。

### D03 [P1] 1024 宽度下平台商品筛选区溢出

- 位置：`frontend/src/views/masterdata/PlatformProductDetailList.vue:1015` 附近 `.resource-toolbar`；窄屏断点为 960px。
- 分类：响应式/布局。
- 证据：工具栏固定最小列宽 `220 + 170 + 190 + 160 + auto`；页面同时保留应用侧栏和分类栏。1024×768 时主区域宽 761、scrollWidth 1340；内层内容 clientWidth 453、scrollWidth 1053。截图可见下拉延伸出内容卡片，并非单纯表格内横向滚动。
- 影响：查询、重置等操作需额外横向寻找；中等屏幕和放大场景不能稳定操作。
- 建议：依据内容可用宽度折行，限定表格自身滚动；复测 1024/1366/1440 和真正 200% 缩放。建议 `$impeccable adapt`。

### D04 [P1] 首页辅助文字对比度不足

- 位置：`frontend/src/views/dashboard/Index.vue:97` 附近 `.context-grid small`。
- 分类：可访问性；对应 WCAG 1.4.3 小字号文本对比度。
- 证据：浏览器实际计算色 #718096、父背景 #FFFFFF、11px；对比度约 4.02:1，低于 4.5:1。
- 影响：认证、租户和数据范围说明较难辨认，不能因其是辅助文字而忽略。
- 建议：使用满足对比度的现有深色文本值/语义 token；复测相关背景。建议 `$impeccable polish`。

### D05 [P1] 平台商品筛选下拉没有可访问名称

- 位置：`frontend/src/views/masterdata/PlatformProductDetailList.vue:105` 附近三处 `el-select`。
- 分类：可访问性；对应 WCAG 3.3.2、4.1.2。
- 证据：DOM 中三个 combobox 没有名称；只通过“全部平台/全部店铺/全部销售状态”占位展示用途，源码没有关联标签。
- 影响：读屏无法可靠辨识字段用途，选值后也缺少持续的字段标签。
- 建议：补可见标签及正确关联，验证空值和选中状态的可访问名称、Tab 顺序。建议 `$impeccable harden`。

### D06 [P2] 租户管理员首页被财务权限优先匹配

- 位置：`frontend/src/utils/workspace.js:6`。
- 分类：角色定位/信息架构。
- 证据：非 superuser 只要包含 finance.* 权限就优先返回财务工作台；当前页面用户标记为租户管理员。
- 影响：管理员得到偏财务的标题和任务引导，与跨模块职责不一致。
- 建议：先核定多角色首页优先级，再调整匹配规则并测试组合权限；不要单凭权限字符串推断岗位。建议 `$impeccable clarify`。

### D07 [P2] “可用入口 8”实际是前八个快捷入口

- 位置：`frontend/src/views/dashboard/Index.vue:26`、`:67`。
- 分类：文案/统计范围。
- 证据：数字取 shortcuts.length，而 shortcuts 在菜单展开后 `.slice(0, 8)`。
- 影响：把快捷入口数量误认为整个权限范围可访问的页面数。
- 建议：改为“常用入口”或另算总数；避免改变菜单权限。建议 `$impeccable clarify`。

### D08 [P1] 首页“已连接”没有对应连接检查依据

- 位置：`frontend/src/views/dashboard/Index.vue:6`。
- 分类：状态真实性。
- 证据：仅由 `useMock ? 'mock' : 'connected'` 决定。当前没有店铺/仓库授权关系，仍显示已连接。
- 影响：用户容易误解为平台已连通；本地真实 API 模式和平台连接健康是不同事实。
- 建议：显示“本地 API 模式”等准确运行模式；实际连接状态需来源、对象、检查时间和结果。不因本地 API 200 推断平台连通。建议 `$impeccable clarify`。

### D09 [P2] 档案摘要混用总结果与当前页统计

- 位置：`frontend/src/components/AdminResourcePage.vue:275`、`:276`。
- 分类：统计口径/文案。
- 证据：结果数使用后端总数，启用/停用数由本页 rows 计算。店铺页面显示结果 59、启用 20、停用 0，未说明后两者仅当前页。没有据此推断全库只有 20 家启用店铺。
- 影响：用户可能据此作错误业务判断，换页后摘要也会变化。
- 建议：标明“本页启用/停用”，或由后端提供与查询相同范围的汇总；两种方案二选一。建议 `$impeccable clarify`。

### D10 [P2] 无授权关系时预览只提示“没有缺失任务”

- 位置：`frontend/src/components/MissingSyncJobsPreview.vue:7`，`backend/apps/integrations/missing_jobs.py`。
- 分类：前置条件/空态。
- 证据：库内店铺和仓库授权均为 0，预览返回空数组，页面显示“当前权限范围内没有缺失任务；已有停用任务不重复列出”。
- 影响：不能区分“没有可检查的授权主体”和“授权主体的任务已齐全”，容易过早判定接入配置完成。
- 建议：保留只读性质，返回可见授权主体数/排除原因摘要；空主体时引导去店铺或仓库完成配置。不要读取或展示其他租户的授权。建议 `$impeccable onboard`。

以上缺陷均尚未修复、尚未复测。本轮没有新增可确定的数据泄漏或越权证据；这不等于已通过安全验收。
