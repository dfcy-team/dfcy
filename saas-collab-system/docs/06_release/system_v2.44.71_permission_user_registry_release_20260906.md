## 核定增量

1. 角色数据范围的新写入仅允许“租户内全部数据”和“按业务范围限制”；`department`、`department_tree`、`own` 仅兼容读取历史记录，重新保存前必须明确选择新范围，系统不自动扩大访问边界。
2. 业务范围支持当前租户的平台、国家/站点、店铺、仓库和供应商；服务端逐项校验对象归属，拒绝跨租户引用和空的自定义范围。
3. 角色权限矩阵按菜单、操作、字段、数据范围分层展示；保留快速分配和高级配置、未触及模块原授权、高风险权限二次确认及普通管理员的可委派权限边界。
4. 前端 `menu.js` 为菜单权限登记源，生成并随代码提交 `backend/apps/permissions/menu_registry.json`；后端运行时只读取静态快照，不依赖 Node.js 或执行前端源码。
5. `sync_permissions --dry-run` 与 `--check` 为只读门禁；正式同步幂等创建或修复菜单权限，将已移除菜单标为停用但不删除权限、不撤销历史授权，并按既有操作权限增量补授对应菜单权限。
6. 系统管理页面补充中文角色、权限、部门和租户显示；不更改业务稳定编码。
