# V2.44.107 调度审核阻断修复（待复审，未部署）

对应 PR #129 的审核意见 4011447693、4011447704。本修复不表示已解除生产发布门禁，不改菜单、权限或生产任务状态。

## 高优先级：Worker 启动窗口中断

- 派发写入 running 后、执行锁/SyncRun 创建前发生进程退出，旧逻辑会永久阻塞后续计划。
- 每轮派发检查启动超过 5 分钟且没有关联运行的 running 派发；在同一任务行锁下确认没有活动任务/有效租约/运行记录，记录 failed、完成时间和可读原因。
- 不重复派发原时点，后续计划继续遵守既有漏跑策略。
- run_sync_job 取得相同任务行锁后重读派发状态和启动期限，拒绝已回收或超时的迟到 Worker；异常处理不得覆盖已回收记录。

## 中优先级：Mock 计划策略不一致

- 仅 environment=mock 且 resource_type=mock_record 的定时派发可使用现有受控 Mock 校验和适配器。
- 手动真实队列入口以及其他环境/业务资源保持 live_only=True；不允许把生产请求失败变为模拟成功。
- 不 mock 校验器的测试验证独立 Mock 定时任务完成，运行标记仍为 simulation。

## 验证

- 76 项隔离回归通过（禁用外部网络和数据库访问）。
- 模拟 SystemExit 发生于 Worker 声明 running 与取得任务锁之间，验证超时回收、审计原因、迟到拒绝及后续计划恢复。
- 验证有效租约不回收、重复消息不重复执行、Mock 实际校验通过、业务资源/生产配置不能借 Mock 路径执行。
- git diff --check 通过；菜单、路由和权限目录无差异。
- 尚待 CI 全量检查及原审核人复审；未触发部署、未处理或改写生产派发记录。
