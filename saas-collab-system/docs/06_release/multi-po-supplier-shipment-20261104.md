# 同供应商跨采购单发货改造（待发布）

## 行为

一张供应商发货单允许包含同供应商、同目的国家的多张已确认采购订单。每条发货明细保留准确采购来源、数量、四位单价；同 SKU 不同采购来源不自动合并。表头 order 保留为兼容锚点，真实来源以活动明细为准；采购单外商品仍归入锚点采购单。

内部与供应商页面可添加来源采购单、选择具体采购明细，列表和详情展示来源。按任一来源采购单筛选可找到同一发货单。数量进度、集货与入库追溯按各来源明细统计。国内运费属于整张发货单，不能按采购来源重复登记。

定金只可来自实际来源采购单，受各来源金额、各笔定金余额和整张发货单剩余应付共同约束。所有来源采购单必须有访问权限，才可读取或操作整张发货单及相关批次。采购单自己的进度仅统计其所属明细；详情权限独立校验。

现有数据结构已具备 ShipmentLine.purchase_line，故无需新增数据库字段或迁移。兼容单采购单及已导入历史拆分单。没有执行历史业务数据变更，没有部署到虚拟机或阿里云；版本号待定。候选基于 b5aecf43，包含此前月份付款状态修复；正式发布时需核对目标基线，不直接覆盖已有热修。

## 源数据后续处理顺序

1. 代码验收并在虚拟机部署后，先备份并只读重建“租户＋供应商＋源发货单号→系统发货单＋采购来源明细”映射。此前复核有150张跨采购单源单，数量仅作历史参考，执行前重新统计。
2. 对每组比较供应商、国家、账期、业务日期、发货方式、商品来源、四位单价、数量、国内运费、付款及转账凭证。只合并同一真实源单，不能按供应商或同 SKU 直接合并。发货单自身账期不一致或来源不明确的组隔离。
3. 先输出可处理清单、隔离清单及合并前后数量金额对照，演练事务回滚。迁移必须保留旧系统编号、源编号、旧新主键映射、付款与抵扣原始审计；付款不重新登记为新的现金支出。
4. 已有集货分配、入库、费用版本、合同、历史结算、定金抵扣、付款凭证的单据，逐类明确引用迁移方案；无法完整迁移的保持原状，不能仅合并表头或删除旧单。国内运费确认只保留一次，来源不明不擅自抵销。
5. 校验源/目标有效单数与明细覆盖、采购来源、数量和金额四位精度、付款/抵扣守恒、凭证哈希及引用完整性，再执行可回放且幂等的虚拟机演练。历史成本不重算、库存不凭合单增减。正式系统另行安排。

## 2026-11-04 账期归属更正

账期属于供应商发货单，不属于采购单。新建发货单从供应商档案冻结账期天数及提醒天数，起算日为供应商发货日，保存到本单PaymentTermsRecord/Revision。采购确认不再生成账期快照；既有PO快照保留审计但不参与到期日、提醒或跨PO发货兼容性判断。采购单界面移除账期展示。已有发货单自己的账期及调整记录保持不变；缺失自身记录的历史单据为待确认，不从PO或当前供应商档案猜测补齐。

剩余25张历史源单的发货单自身账期已核对一致。5组11条采购单外商品由保留其原采购归属的发货单作为主单承接，不伪造采购明细、不更改单价或数量。
