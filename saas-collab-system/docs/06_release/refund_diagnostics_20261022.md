# 退款请求诊断改进（2026-10-22）

基线：生产V2.44.278，提交b84040488e3391996142103fb9df76c08f5d7113。

## 问题与证据

8号店退款历史段5027、5028多次失败，运行记录仅有MAX_RETRY_EXCEEDED和Platform request timed out，无法区分列表/详情。2026-10-22按生产第0页只读复测：原范围page_size=100超时27.95秒（含HTTP重试），page_size=20成功3.89秒，20条、more=true。此为单次对照，不能据此承诺性能倍率或全月成功。

此前使用page_no=1对不同page_size的返回进行比较不构成分页一致性证据：不同页大小的第1页对应不同偏移。9月1日第0页复测page20返回10条、page1返回1条且首条时间一致。原“上游分页不一致”判断已撤回，审计原文保留并加更正说明。本次不加入基于该误判的空页拦截。

## 改动目标

仅为Shopee退款的列表与详情请求失败补充阶段、页号、页大小和耗时，让现有SyncRun.masked_error_message持久化可用诊断。保留错误类型、受控错误码与重试分类，诊断字段不包含URL、凭据、退款/订单号、买家信息或原始异常文本。

不修改分页协议、游标、已有历史分段、详情断点、超时、重试次数、并发、生产配置或数据。无迁移、菜单、路由、权限变更。

## 后续分页优化边界

后续可评估将新建退款补采计划的每页数量定为20。已开始的任务不能直接把100改为20：相同页号对应的记录偏移会改变；已有详情断点还校验scope指纹。既有失败段需要检查是否有分页进度、详情断点和已归档页，设计带审计的恢复/替代分段能力后再处理。该功能不包含在本批补丁。
