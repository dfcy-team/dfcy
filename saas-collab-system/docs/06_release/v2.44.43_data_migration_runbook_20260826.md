# v2.44.43 数据迁移执行与回退方案

日期：2026-08-26
状态：候选审核材料，未在生产执行
基线：`v2.44.42-deployed`

## 1. 控制边界

- 本文只提供审核所需的校验、快照和回退步骤；生产 SQL、Django migration 和恢复动作均由架构员执行。
- 执行前必须取得数据库一致性备份，并在同版本副本完成恢复演练。
- 下列快照表名为本次发布专用；若目标库已经存在同名表，应停止并由架构员重新命名，不能覆盖。
- 数据回退必须先完成，再反向执行会删除字段的 schema migration。

## 2. 影响范围与规模

| 迁移 | 写入或更新范围 | 最大写入规模 | 自动反向 |
|---|---|---:|---|
| `masterdata.0004_country_information_fields` | 所有国家档案的空币种及空/UTC 时区 | 当前国家档案总数 | 否，使用发布前快照恢复 |
| `masterdata.0005_seed_country_sites` | 每租户 `PH`、`TH`、`MY` 三条国家档案 | 租户数 × 3 | 否，使用发布前快照恢复 |
| `masterdata.0006_add_lazada_temu_platforms` | 每租户 `lazada`、`temu` 两条平台档案 | 租户数 × 2 | 否，使用发布前快照恢复 |
| `permissions.0032_seed_live_readonly_sync_permission` | 权限码 `integrations.run_live_readonly` 一条 | 1 | 否，使用发布前快照恢复 |

`0005` 的国家种子常量和写入逻辑已冻结在迁移文件内，只通过 `apps.get_model()` 访问历史模型，不再导入当前业务模块。

## 3. 执行前校验与快照 SQL

以下 SQL 以 MySQL 8 为准。执行前应记录每个查询结果、开始时间和目标数据库标识。

```sql
SELECT COUNT(*) AS tenant_count FROM tenants_tenant;
SELECT COUNT(*) AS country_count FROM masterdata_countrysitemaster;
SELECT COUNT(*) AS affected_country_count
FROM masterdata_countrysitemaster
WHERE currency = '' OR currency IS NULL OR timezone = '' OR timezone IS NULL OR timezone = 'UTC';
SELECT COUNT(*) AS seeded_country_count
FROM masterdata_countrysitemaster
WHERE code IN ('PH', 'TH', 'MY');
SELECT COUNT(*) AS seeded_platform_count
FROM masterdata_platformmaster
WHERE code IN ('lazada', 'temu');
SELECT COUNT(*) AS readonly_permission_count
FROM permissions_permission
WHERE code = 'integrations.run_live_readonly';
```

```sql
CREATE TABLE rollback_v24443_country LIKE masterdata_countrysitemaster;
INSERT INTO rollback_v24443_country
SELECT * FROM masterdata_countrysitemaster;

CREATE TABLE rollback_v24443_platform LIKE masterdata_platformmaster;
INSERT INTO rollback_v24443_platform

WHERE code IN ('lazada', 'temu');

CREATE TABLE rollback_v24443_permission LIKE permissions_permission;
INSERT INTO rollback_v24443_permission
```

## 4. 执行后校验 SQL

```sql
SELECT tenant_id, code, COUNT(*) AS row_count
FROM masterdata_countrysitemaster
WHERE code IN ('PH', 'TH', 'MY')
GROUP BY tenant_id, code
HAVING COUNT(*) <> 1;

SELECT tenant_id, code, name, country_code, currency, timezone, status
FROM masterdata_countrysitemaster
WHERE code IN ('PH', 'TH', 'MY')
  AND (
    currency = '' OR currency IS NULL OR
    timezone = '' OR timezone IS NULL OR
    status <> 'active'
  );

SELECT tenant_id, code, COUNT(*) AS row_count
FROM masterdata_platformmaster
WHERE code IN ('lazada', 'temu')
GROUP BY tenant_id, code
HAVING COUNT(*) <> 1;

SELECT code, name, module, action
FROM permissions_permission
WHERE code = 'integrations.run_live_readonly';
```

预期：两个 `HAVING` 查询均返回零行；国家档案异常查询返回零行；只读同步权限恰好返回一行。

## 5. 可执行数据回退 SQL

回退前停止同步任务与写入流量，并再次备份当前状态。以下 SQL 依赖第 3 节创建的发布前快照。

```sql
START TRANSACTION;

DELETE current_row
FROM masterdata_countrysitemaster AS current_row
LEFT JOIN rollback_v24443_country AS previous_row ON previous_row.id = current_row.id
WHERE previous_row.id IS NULL
  AND current_row.code IN ('PH', 'TH', 'MY');

UPDATE masterdata_countrysitemaster AS current_row
JOIN rollback_v24443_country AS previous_row ON previous_row.id = current_row.id
SET
  current_row.code = previous_row.code,
  current_row.name = previous_row.name,
  current_row.country_code = previous_row.country_code,
  current_row.platform = previous_row.platform,
  current_row.status = previous_row.status,
  current_row.currency = previous_row.currency,
  current_row.timezone = previous_row.timezone,
  current_row.updated_at = previous_row.updated_at;

DELETE current_row
FROM masterdata_platformmaster AS current_row
LEFT JOIN rollback_v24443_platform AS previous_row ON previous_row.id = current_row.id
WHERE previous_row.id IS NULL
  AND current_row.code IN ('lazada', 'temu');

UPDATE masterdata_platformmaster AS current_row
JOIN rollback_v24443_platform AS previous_row ON previous_row.id = current_row.id
SET
  current_row.name = previous_row.name,
  current_row.platform_type = previous_row.platform_type,
  current_row.status = previous_row.status,
  current_row.updated_at = previous_row.updated_at;

DELETE current_row
FROM permissions_permission AS current_row
LEFT JOIN rollback_v24443_permission AS previous_row ON previous_row.id = current_row.id
WHERE previous_row.id IS NULL
  AND current_row.code = 'integrations.run_live_readonly';

UPDATE permissions_permission AS current_row
JOIN rollback_v24443_permission AS previous_row ON previous_row.id = current_row.id
SET
  current_row.name = previous_row.name,
  current_row.module = previous_row.module,
  current_row.action = previous_row.action,
  current_row.description = previous_row.description;

COMMIT;
```

如果新权限已经关联角色，删除前必须先检查中间表引用并由架构员决定是否撤销授权；不得依赖级联删除作为默认回退。

## 6. 数据量、耗时和锁风险

- `0004` 按国家档案逐行读取并按主键更新，预计写入量等于第 3 节 `affected_country_count`。
- `0005` 最多执行 `tenant_count × 3` 次唯一键查询和写入。
- `0006` 最多执行 `tenant_count × 2` 次唯一键查询和写入。
- `permissions.0032` 只更新或创建一条权限记录。
- 迁移均为短事务的唯一键/主键行操作，不包含全表 DDL 重建；主要风险是大量租户下的逐行往返和热点唯一键等待。
- 架构员应在生产副本记录实际耗时。若预计写入超过 10,000 行或演练超过维护窗口的 50%，应改为分批前滚脚本，不直接运行本候选迁移。

## 7. 完成条件

只有备份可恢复、执行前后 SQL 已留档、异常查询为零、迁移计划与实际一致，才可把数据库门禁标记为通过。快照表在发布稳定并完成审计前不得删除。
