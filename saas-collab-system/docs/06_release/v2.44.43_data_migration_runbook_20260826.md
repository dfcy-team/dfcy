# v2.44.43 数据迁移执行与回退手册

日期：2026-08-26
状态：架构员执行手册；候选版本未发布、未在生产执行
基线：`v2.44.42-deployed`

## 1. 适用范围与执行边界

本手册按当前应用层虚拟机的只读证据整理。所有数据库检查、备份、迁移、恢复和发布动作由架构员执行并留存日志；开发A不得直接执行生产DDL、Docker操作或虚拟机发布。

当前证据结论：

| 范围 | 当前状态 | 本次处理 |
|---|---|---|
| `masterdata.0003`–`masterdata.0008` | 已在当前VM的 `django_migrations` 登记 | 仅补齐源码迁移链的审计记录；本次不执行、不重复登记、不使用批量 `--fake` |
| `permissions.0032_seed_live_readonly_sync_permission` | 真正待执行项 | 按下文单独核对、演练和执行 |
| `reports.0007_real_export_files` | 真正待执行项 | 在报告表仍为0行且4个字段缺失的前提下执行 |
| `reports_reportexportrequest` | 当前只读证据为0行 | 执行前后都必须复核为0行；若不为0行立即停止 |
| 报告表字段 | `file_format`、`storage_key`、`file_sha256`、`expires_at` 4个字段缺失 | 只由 `reports.0007` 增量补齐，禁止手工先建字段 |
| 国家档案 | 当前代码口径为 `country-*`；业务国家由 `country_code` 表达 | 所有校验按 `country_code`，不得按旧的 `code='PH'` 等假设校验 |

迁移前先确认计划只有上述两个真正待执行迁移。若计划出现其它迁移、任何 `masterdata.0003`–`0008`、手工DDL或全量 `--fake`，必须停止并重新生成候选基线。

## 2. 前置条件与只读核对

### 2.1 发布与权限前置

架构员在候选镜像和源码完全一致的工作目录执行，并记录提交SHA、镜像ID、digest、数据库标识和UTC时间。执行前必须满足：

- 已获得可恢复的全库一致性备份，并在同版本副本完成恢复演练。
- 应用写流量、Celery迁移任务和导出任务已排空或暂停；数据库连接和锁等待处于可控范围。
- `dev_a` 不拥有生产 `CREATE`、`ALTER`、`DROP`、`INDEX` 权限；执行账户由架构员单独提供。
- `LIVE_READONLY_SYNC_ENABLED=false`、`LIVE_CUSTODY_BACKEND=refuse`，真实平台网络保持关闭。
- 只读核对未发现任何结构或迁移记录漂移。

### 2.2 迁移记录核对（只读）

```sql
SELECT app, name, applied
FROM django_migrations
WHERE (app = 'masterdata' AND name IN (
  '0003_countrysitemaster',
  '0004_country_information_fields',
  '0005_seed_country_sites',
  '0006_add_lazada_temu_platforms',
  '0007_store_archive_fields',
  '0008_merge_country_and_store_branches'
))
   OR (app = 'permissions' AND name = '0032_seed_live_readonly_sync_permission')
   OR (app = 'reports' AND name = '0007_real_export_files')
ORDER BY app, name;
```

预期：`masterdata.0003`–`0008` 均有登记；两个真正待执行项在执行前没有登记。该查询只读，不得用它的结果批量伪造迁移记录。

```bash
python manage.py showmigrations masterdata permissions reports
python manage.py migrate --plan
```

`migrate --plan` 必须只显示 `permissions.0032_seed_live_readonly_sync_permission` 和 `reports.0007_real_export_files`（以及它们已满足的依赖）。若显示其它待执行项，停止。

### 2.3 当前结构与数据核对（只读）

先确认目标数据库和表存在，再执行以下查询。`DATABASE()` 由当前连接解析，不要把查询改成未知数据库名。

```sql
SELECT DATABASE() AS database_name;

SELECT table_name
FROM information_schema.tables
WHERE table_schema = DATABASE()
  AND table_name IN (
    'masterdata_countrysitemaster',
    'reports_reportexportrequest',
    'permissions_permission'
  )
ORDER BY table_name;

SELECT column_name, column_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_schema = DATABASE()
  AND table_name = 'reports_reportexportrequest'
ORDER BY ordinal_position;

SELECT COUNT(*) AS report_export_request_count
FROM reports_reportexportrequest;

SELECT country_code, COUNT(*) AS row_count
FROM masterdata_countrysitemaster
WHERE country_code IN ('PH', 'TH', 'MY')
GROUP BY country_code
ORDER BY country_code;

SELECT tenant_id, country_code, COUNT(*) AS row_count
FROM masterdata_countrysitemaster
WHERE country_code IN ('PH', 'TH', 'MY')
GROUP BY tenant_id, country_code
HAVING COUNT(*) > 1;
```

当前证据下，报告表行数必须为0；报告表的4个字段必须缺失；国家校验只看 `country_code`，不得把 `code` 当作国家代码。若实际结构已包含任一报告字段，或报告表已有数据，停止并由架构员重新评估迁移路径。

## 3. 备份

### 3.1 全库一致性备份

架构员使用批准的MySQL账号执行全库备份，记录文件SHA-256、数据库版本、GTID/binlog位置和备份完成时间。命令中的账号、密码和路径由架构员在受控终端注入，不写入仓库或聊天记录。

```bash
mysqldump --single-transaction --routines --triggers --events \
  --set-gtid-purged=OFF "$DB_NAME" > v24443-pre-migrate.sql
sha256sum v24443-pre-migrate.sql
```

若数据库包含不能由 `--single-transaction` 一致读取的非事务表，必须改用经批准的锁定/快照方案；无法证明一致性时停止。

### 3.2 迁移对象快照

全库备份之外，架构员可在同一一致性窗口保留下列审计查询结果和表副本。副本名称须包含执行批次，不得覆盖既有副本；创建副本本身是DDL，开发A不得执行。

```sql
CREATE TABLE rollback_v24443_permissions_20260826 LIKE permissions_permission;
INSERT INTO rollback_v24443_permissions_20260826
SELECT * FROM permissions_permission
WHERE code = 'integrations.run_live_readonly';

CREATE TABLE rollback_v24443_reports_20260826 LIKE reports_reportexportrequest;
INSERT INTO rollback_v24443_reports_20260826
SELECT * FROM reports_reportexportrequest;
```

记录副本行数，并确认报告副本仍为0行。若副本已存在、插入行数与只读核对不一致或任何备份校验失败，停止。

## 4. 同版本副本恢复演练

在执行生产迁移前，将 `v24443-pre-migrate.sql` 恢复到隔离副本，使用候选版本完全相同的应用镜像执行下列步骤：

1. 核对 `django_migrations`、报告表0行、报告表4字段缺失，以及 `country_code` 查询结果与生产快照一致。
2. 执行第5节的两条迁移命令，不追加其它迁移、不使用 `--fake`。
3. 执行第6节全部验证 SQL，确认报告4字段出现、权限记录恰好一条、既有国家数据未被错误改写。
4. 在副本上按第7节演练回退，并再次验证应用可启动、迁移记录和结构一致。

恢复、迁移或回退任一步骤无法重现、耗时超过维护窗口50%、锁等待不可控或产生额外迁移，禁止进入生产。

## 5. 生产执行（仅架构员）

执行前再次确认应用写流量已停止、备份SHA已记录，且第2节计划只剩两个目标。每条命令单独记录完整输出和开始/结束时间：

```bash
python manage.py migrate permissions 0032_seed_live_readonly_sync_permission --noinput
python manage.py migrate reports 0007_real_export_files --noinput
```

禁止以下做法：

- `python manage.py migrate --fake`、按应用整批 `--fake` 或把未执行迁移统一标记为已执行；
- 手工 `ALTER TABLE` 预建 `reports.0007` 的4个字段后再伪造迁移；
- 重复执行已登记的 `masterdata.0003`–`0008`；
- 使用开发A账号执行生产DDL、Docker或虚拟机发布。

任一命令报错、迁移计划变化、出现重复字段/表、出现锁超时或权限异常，立即停止，不继续执行下一条；保留现场日志并通知架构员进行回退评估。

## 6. 执行后验证

### 6.1 迁移记录与报告结构

```sql
SELECT app, name, applied
FROM django_migrations
WHERE (app = 'permissions' AND name = '0032_seed_live_readonly_sync_permission')
   OR (app = 'reports' AND name = '0007_real_export_files')
ORDER BY app, name;

SELECT column_name, column_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_schema = DATABASE()
  AND table_name = 'reports_reportexportrequest'
  AND column_name IN ('file_format', 'storage_key', 'file_sha256', 'expires_at')
ORDER BY column_name;

SELECT COUNT(*) AS report_export_request_count
FROM reports_reportexportrequest;
```

预期：两个目标迁移各一条登记；4个字段各一条结构记录；报告表仍为0行。

### 6.2 权限与国家档案

```sql
SELECT code, name, module, action
FROM permissions_permission
WHERE code = 'integrations.run_live_readonly';

SELECT tenant_id, country_code, COUNT(*) AS row_count
FROM masterdata_countrysitemaster
WHERE country_code IN ('PH', 'TH', 'MY')
GROUP BY tenant_id, country_code
HAVING COUNT(*) <> 1;

SELECT tenant_id, country_code, currency, timezone, status
FROM masterdata_countrysitemaster
WHERE country_code IN ('PH', 'TH', 'MY')
  AND (currency IS NULL OR currency = '' OR timezone IS NULL OR timezone = '' OR status <> 'active');
```

预期：只读权限恰好一条；两个国家档案异常查询均返回0行。国家代码判断必须继续使用 `country_code`，不根据 `code` 的显示格式推断结果。

### 6.3 应用级检查

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
git diff --check
```

同时核对候选镜像未发生漂移、应用仍保持只读安全默认值，敏感凭据扫描无新增命中。验证结果、SQL输出和审计人写入发布记录；未完成全部验证不得放行版本。

## 7. 回退方案

MySQL DDL可能产生隐式提交，因此首选恢复已验证的全库备份，而不是把一串逆向SQL当作原子事务。回退由架构员决定并执行，开发A不得操作生产库。

### 7.1 回退前停止条件

停止应用写流量和同步任务，重新获取当前数据库快照。确认没有后续迁移依赖 `permissions.0032` 或 `reports.0007`，并确认报告表仍为0行、4个字段没有业务数据。任一条件不满足时，只能使用经过演练的全库/存储快照恢复。

### 7.2 优先恢复备份

在隔离环境先恢复 `v24443-pre-migrate.sql`，执行第6节验证，确认数据、迁移记录和结构均回到迁移前状态，再按批准的维护流程恢复目标库。恢复后不得直接接受线上流量，直到应用健康检查和只读核对完成。

### 7.3 仅在明确可逆且无后续依赖时

若架构员已确认无后续依赖且副本演练通过，可分别回退报告结构和权限数据；不得用整批 `--fake` 隐藏状态：

```bash
python manage.py migrate reports 0006_sales_details_export --noinput
```

`permissions.0032` 的代码回退操作是 `RunPython.noop`，不会自动删除已种子的权限。是否删除该权限必须由架构员依据角色关联审计决定；存在角色关联时先撤销/迁移授权，再使用带批次审计的精确SQL删除目标权限。删除前后均需核对 `permissions_permission`、关联中间表和审计日志。

回退完成后重新执行第2节和第6节的结构/迁移核对，确认应用可启动且线上真实接入仍关闭。

## 8. 必须停止并升级架构员的情形

- `masterdata.0003`–`0008` 任一未登记、登记记录与源码不一致或有人要求重复执行；
- `migrate --plan` 显示除 `permissions.0032`、`reports.0007` 之外的待执行项；
- 报告表不再是0行，或4个字段已由其它路径出现；
- `country_code` 查询发现重复、缺失、非法币种/时区/状态，或有人改用 `code` 判断国家；
- 备份无法恢复、校验不一致、没有副本演练或无法记录binlog/GTID；
- 需要开发A账号执行生产DDL、Docker、虚拟机发布或修改安全镜像；
- `dev_a` 仍具有生产DDL权限；
- 出现真实凭据、真实平台网络或 `LIVE_READONLY_SYNC_ENABLED=true`；
- 迁移产生额外DDL、锁等待/超时、重复对象或任何未解释的结构漂移。

本手册只定义受控增量迁移的证据和执行边界，不代表已批准发布 `v2.44.43`。
