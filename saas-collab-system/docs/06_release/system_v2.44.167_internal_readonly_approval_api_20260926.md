## 发布范围

1. “API 数据接入 → 内部系统数据接口”增加审核状态、审核/驳回操作及实时能力目录。85 个配置目录数据块仍可选择，但只有服务端目录标记的首批 8 个基础档案数据块可读取。
2. 新增 `GET /api/internal-readonly/v1/capabilities/` 和 `GET /api/internal-readonly/v1/<resource>/`。首批资源为商品 SPU、SKU、分类、平台、国家、供应商、店铺、仓库。查询强制校验 Basic 凭据、租户、数据块、审批、启用、有效期、来源 CIDR、分钟限流与分页；服务端固定投影可读字段，不提供业务写入。
3. 新建或修改调用方后为待审核且停用；另一位具有 `integrations.internal_api_client.approve` 权限的本租户管理员审批，通过后再由管理员单独启用。拒绝填写原因。配置操作写入不可变审计。
4. 新增可信代理 CIDR 配置 `INTERNAL_READONLY_TRUSTED_PROXY_CIDRS`；未配置时只以 `REMOTE_ADDR` 判定来源。详见 `docs/01_architecture/internal_readonly_api_v1.md`。

## 数据库与运行影响

- 新增迁移 `integrations.0033_internal_api_client_approval`：审批字段与数据库分钟限流表；**所有现存调用方会被统一设为 `disabled` + `pending`**，必须由不同管理员复审后重新启用。此为主动收紧权限，发布前通知现有调用方并确认窗口。
- 新增迁移 `permissions.0048_register_internal_api_client_approval`：注册审批权限并赋予现有有效 administrator 角色。审批人仍不能审核本人创建或最后修改的配置。
- 部署前核对应用的直接来源 IP 与网关拓扑。若反向代理使 `REMOTE_ADDR` 只显示代理地址，必须在受控环境配置可信代理 CIDR，并确保网关正确追加/覆盖转发地址；不得将公网段作为可信代理。仅经 HTTPS 对调用方传送 Basic 密钥。
- 失败或回滚时不得自动逆向审批迁移来恢复旧调用方的 active 状态；应用回退和凭据恢复需按生产备份与安全评估另行处理。
