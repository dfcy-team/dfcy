# 本地接入与授权流程优化

日期：2026-09-09。范围：现有 Django + Vue 主系统，V2.44.83 / 338085e 及工作区已有增量。仅本地修改和验证，未提交、未同步虚拟机、未写入或发布阿里云。

## 本轮交付

1. **区分登录失效和平台授权拒绝。** 请求层仅对本系统 AUTH_REQUIRED（或无标准响应体的兼容 401）尝试登录续期。平台返回 API_SYNC_FAILED / 401 不再刷新本系统 JWT、重发一次性回调或清除本地登录。
2. **手动回调返回可识别且脱敏的原因。** 保留原有 HTTP 状态、统一错误码和 state 一次性消费机制，补充 data.reason_code。只返回受控错误码，不透传第三方异常详情。已消费回调仍为 409，不用已有授权推断本次成功。
3. **持续、明确的回填结果。** 区分已消费、过期、平台拒绝、平台限流和保存失败；已消费时重新读取授权状态，但不会重换 Token 或提示新授权成功。敏感输入在请求结束后清空；重复点击和重复查询参数在前端拒绝，后端原有校验保留。
4. **纠正回调流程说明。** 登记回调地址与携带 state / code 的实际回调地址不同。主系统早已通过当前页面配置的后端 POST 手动回填接口处理参数，不访问粘贴站点，不需要改成 Cookie 跳转机制。
5. **纠正凭据存储说明。** 公共配置、店铺和仓库页面不再宣称密钥“加密写入 SaaS MySQL”，明确托管服务与数据库引用的区别；生产须使用加密托管，本地文件托管只适合合成测试。
6. **安全的任务创建默认值。** 从店铺和仓库授权弹窗手动创建的新同步任务默认停用、手动调度；成功提示引导到任务页核对后启用。未新增授权后自动创建任务，也不修改既有任务。

使用 impeccable 的 product/harden 指引补充持续状态、错误恢复和清晰文案；保留现有组件、布局和样式，不做品牌改版。

## 保持不变

- 当前登录用户、权限与租户/主体/配置范围验证。
- 数据库 state 一次性消费和失败留痕；不把已经失败或消费的 state 重新设为 pending。
- 主系统外部托管引用格式，不复制独立项目的 AES 密文到 credential_mask。
- 极风 Email、一次性 Token、授权 key、Access Token 和 userId 的角色区分。
- 仓库凭据留空保留、换绑幂等、变更后待校验等原有行为。
- 不引入第二套调度器，不自动采购、写平台业务数据或发布。

## 真实联调的剩余条件

**更正此前判断：公网转发可达不是主系统手动回填的必要条件。** 用户可在平台授权后，将完整回调地址粘回本地页面，由本地后端校验同一个 state。自动回调仍需要实际路由可达。手动回填也不能撤销已由另一环境完成的兑换，必须从本地发起本地所属会话。

真实联调还需要加密、认证且目标明确的凭据托管，以及当前本地环境的回调登记白名单和平台准入设置。这些门禁没有在优化中绕过；未导入用户真实密钥、发起真实授权或执行只读采集。

极风在一次性 Token 已消费后出现托管/落库失败时，当前服务会拒绝自动重试；后续如要实现自动恢复，仍需定义可核对的托管凭据恢复协议。本轮没有引入未经验证的补偿流程。
