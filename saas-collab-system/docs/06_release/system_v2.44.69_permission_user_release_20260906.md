## 变更范围

1. 角色快速分配：四档模块权限包仍展开为唯一 canonical Role.permissions；高风险操作需明确勾选确认，保留未调整模块已有授权。
2. 身份与角色：平台超级管理员单独显示，租户管理员为内置可分配角色且保持保护；角色增加类型、保护标识及说明字段，修复指定内置角色中文名称。
3. 组织和用户：租户隔离的部门树、人员计数、主/兼任部门调整，直属/包含下级/未分配筛选；新增 department_tree 数据范围选项，原 department 含义不变。
4. 既有角色权限矩阵、组织架构和用户管理页面承载增量；不新增、移动、删除菜单，不改变菜单顺序、页面路由或导航 CSS。
5. MainLayout 仅增加当前身份中文显示优先级；公共列表的可选侧栏服务于组织树，不使用侧栏的页面保持既有表现。
6. 新后端只读入口：`/api/internal/system/permission-packages/`、`/api/internal/system/departments/tree/`；沿用既有管理权限，不增加新 permission code。

## 发布复审补强

- 快速分配的高风险权限不能通过普通分类字段夹带；高级配置保留既有显式权限保存契约，新增高风险授权在页面二次确认，取消不提交。
- 普通角色管理员新增委派仅限本人已获全部数据范围的权限；不得借修改数据范围扩大其不能委派的既有权限。平台超级管理员和租户管理员沿用原授权边界。
- 创建用户时的角色绑定复用既有可委派角色范围校验，与单独调整用户角色一致。
- `department_tree` 只允许已接入该语义的 system 模块，禁止与其他业务模块混用；角色权限管理要求全部数据范围，不使用该部门树范围。页面与后端同时说明、校验，原 `department`/`own`/`custom`/`all` 语义不变。
- 内置业务角色的权限仍可配置，不因保护标识全部锁死；租户管理员权限继续由既有目录机制维护。

## 数据库及授权保护

- 新增 `permissions.0042_role_metadata_and_display_names`、`permissions.0043_datascope_department_tree`，不改历史迁移。
- 发布前实际目录 `sync_permissions --check` 通过：243 项权限、25 个角色、665 条角色授权、17 条用户角色关系、25 条数据范围（所有租户）。
- 角色 ID/code/status/时间戳及 Permission/Role.permissions/UserRole/DataScope 的既有数据摘要必须保持；角色 name/description/type/protected 仅允许本版规范化变更。
- 当前四个内置 code（administrator、operations、product_developer、002）在租户 1/2 各有一条；预期更新这 8 条角色元信息。不是业务授权扩充。
- 不在生产创建测试角色/用户，不执行未核对的写入式 sync_permissions，不自动把普通角色扩展为管理员。
- 在 MySQL 8.4.10 隔离备份库演练迁移，核对业务行数、稳定授权、角色元数据及只读权限目录检查后才可部署。

## 回退和使用边界

- 发布前创建正式数据库备份；保留 V2.44.68 不可变镜像及 Beat 持久化配置。
- 即时应用回退可保留新增角色列；若上线后已使用 department_tree，旧应用不具备该语义，回退前必须核对并审批数据范围兼容处理，禁止自动扩大范围。
- 不自动反向迁移内置显示名，也不直接恢复覆盖有后续业务写入的数据库；必要恢复由负责人核定备份后差异。
- 本文件记录核定范围，不把本地通过当作上线成功；执行结果补充到发布控制复核记录及 VM 双账本。
