# 库存同步自动 SKU 关联（本地，2026-09-11）

## 生效范围

仅极风库存事实入库：`JifengInventoryAdapter.persist_record` → `upsert_inventory_snapshot`。不修改订单、退款或平台商品解析，不新增调度，不触发额外外部 API 调用。

## 解析顺序

1. 同一快照已有内部 SKU：保留，不自动覆盖。
2. seller_sku 非空且与来源 SKU 不一致：不自动关联。
3. 同租户、同仓库、同站点、相同来源 SKU 的历史库存关联，去重后只有一个目标时继承。存在多个不同目标则保持未关联，不再降级猜测。
4. 没有历史关联时，合并同租户内部 SKU 编码、SKU 的旧编码、已生成旧商品记录的编码候选。同一内部 SKU 去重后必须唯一。
5. 比较大小写严格相等，不做名称、相似度或规格推测；MySQL 候选查询后再次在 Python 中严格比较，避免数据库排序规则忽略大小写。

因此，之前人工确认的 5 条大小写差异通过历史关联继承，而不是放宽所有未知编码的匹配规则。

## 数据与审计

- 数量和原始数据摘要不因关联而改写，写入的只是 internal_sku 引用。
- 未匹配/冲突保留库存事实，新增快照在集成审计中记录原因；不把未关联当作库存同步失败。
- 自动关联审计标记 automatic 和 configuration_owner，不伪装成人工确认。关联和审计在同一事务中；审计失败整体回滚。
- 同仓库入库使用仓库行锁串行化；同一快照重复提交不会重复创建或替换关联。
- 已有未关联快照在商品建档后再次正常同步，可以补上唯一关联，并计为 updated；关联与原数据均未变化的重放才计为 skipped。

## 验证

- 17 项自动关联专项测试通过：新旧编码、旧档别名、5 条所用的历史继承路径、大小写差异、跨租户/仓库、多个候选、已有绑定保护、幂等、失败回滚和真实适配器入库路径。
- 本地 965 条库存只读解析均继承到原有内部 SKU，0 条不一致；未执行平台同步或修改现有快照。
- 完整迁移下的库存、回填、事实模型、交接示例与只读适配器回归合计 78 项通过。本地后端与专用 worker 已更新，未启动 Beat 或新增同步任务。

后续新快照会自动执行以上规则。新来源编码没有唯一匹配时仍需要业务核对，不会创建不存在的商品。
