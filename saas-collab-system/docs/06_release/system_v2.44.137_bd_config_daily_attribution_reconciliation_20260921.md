## 增量能力

- 新增 `influencers.bd.performance` 租户配置，支持默认币种、默认归因方式、默认指标视图和每日归因补偿开关。
- 新增 BD 配置入口，并复用配置中心的查看、管理、审批和回滚权限。
- Celery Beat 每日按租户调度严格归因与兜底归因刷新；关闭开关的租户不进入队列。
- 最近 7 天订单持续增量归因；超过 7 天的历史订单使用现有 `AffiliateImportState` 保存游标，按每批 5000 条渐进补偿。
- 两种归因模式成功完成后才推进历史游标；扫描到底后游标归零并在下一周期重新校准。
- 新增到期配置版本激活任务，每分钟处理已审批且达到生效时间的版本。
- 不修改原始订单快照、寄样履约事实或既有归因输入记录。

## 发布门禁

- PR 必须保持 `MERGEABLE`，并基于父版本 `V2.44.136` 的受保护 `main`。
- Phase 2 与 Phase 3 共 10 项 CI 必须全部通过，且对应包含本登记文件的最终候选提交。
- 历史补偿边界测试必须覆盖超过 30 天的遗漏订单、游标推进、扫描到底归零及下一周期重扫。
- 合并前确认 `git diff --check`、Django 系统检查、迁移检查、后端完整测试和前端构建全部通过。
- 本登记不授权自动合并或部署；只能在 CI 全绿后交由“虚拟机功能发布通道”执行受控发布。

## 部署与验收

- 部署应用后执行上述三项迁移，并确认 Celery Worker 与 Celery Beat 均加载新任务。
- 核验配置中心 BD 菜单、租户权限、默认参数和定时生效状态。
- 对具备历史订单的测试租户运行一次补偿任务，确认最近增量和历史游标批次均成功，且任务重试不会重复生成归因结果。
- 核验后端、前端、Celery、Celery Beat、Redis 和 HTTPS 健康状态；记录固定镜像摘要、最终合并 SHA、备份、迁移结果和回滚点。
