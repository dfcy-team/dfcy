# 历史补采容量配置

基线：97da33175d225c05177f484a4ddab84f73726f04。本批仅改后端派发准入、设置和测试，无数据库迁移、菜单或前端修改。

新增环境变量 SYNC_DAILY_LANE_CAPACITY、SYNC_HISTORY_LANE_CAPACITY，默认均为2，表示执行加排队的在途名额，不是worker并发。有效范围1至16，非法值回退2，越界值截断。历史每轮派发上限跟随历史容量，同时受调用limit限制。

夜间4并发的部署配套：控制调度进程配置 SYNC_DAILY_LANE_CAPACITY=2、SYNC_HISTORY_LANE_CAPACITY=4；所有调度实例必须一致。历史sync-history消费者设置concurrency=4、prefetch_multiplier=1，保留日常消费者配置。可按需把历史名额设为5以容纳一个等待任务，但初次验证建议4。环境变量需由现有部署配置显式传入，重建控制进程后生效，不能只写入未被Compose引用的env文件。

本批没有修改部署文件或启动4个worker；生产仍需架构员审阅、受控构建发布及配套配置。先核对应用服务器内存与worker单进程占用。现有历史窗口和逐页门禁保持有效，不提供跨午夜窗口、自动降级或严格全局同店铺锁。

保留现有同主体准入检查、任务锁、序列围栏与消息证据；同一次准入快照内同店铺任务不可重复领取。不同通道及多调度器之间不增加新的分布式主体锁，因此应保留单控制调度器部署，不能据此声称任意多调度器全局互斥。

上线前观察单worker基线，再试2并发和4并发，比较每小时成功落库及完整日期覆盖、限流超时、数据库CPU/锁等待、应用内存。切片等待不是活跃耗时。不能用分段数量直接比较不同日期范围吞吐。

回退：历史worker恢复concurrency=1，SYNC_HISTORY_LANE_CAPACITY恢复2，日常保持2；使用温和退出完成当前页/切片，不清理队列、游标或已落库数据。窗口结束不等于强杀在途请求。
