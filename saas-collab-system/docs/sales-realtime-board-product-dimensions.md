# 实时数据大屏：商品维度切换

2026-10-22，基于虚拟机V278隔离整合分支继续开发，尚未部署。

商品排行提供店铺SPU、店铺SKU、商品SPU、商品SKU、商品分类五个维度，默认商品SKU；每个维度均支持销售额、销量。后台分别计算各维度、各币种、各指标的完整范围TOP10，前端切换只选择已有响应，不增加网络请求。原有菜单动态导入、隐藏暂停、卸载清理和不重叠请求保持。

| 维度 | 口径 |
|---|---|
| 店铺SPU | 店铺ID与平台商品ID；不同店铺不合并 |
| 店铺SKU | 店铺ID、平台商品及规格身份；缺少规格ID时采用可确认的卖家SKU，无可靠编码时保守分开 |
| 商品SPU | 销售事实映射的系统SPU；可从已映射系统SKU所属SPU取得 |
| 商品SKU | 销售事实映射的系统SKU ID；不同店铺销售合并 |
| 商品分类 | 系统SPU关联的ProductCategory节点，显示系统分类树完整路径 |

分类按节点ID区分，同名但不同节点不合并；不使用平台分类、旧自由文本或模型推断。未映射商品与已映射但未设置分类的商品分别列出。分类节点汇总不等于同时重复统计各级祖先分类。商品销售金额采用非取消订单明细金额，可能与包含运费、税费的订单总金额不同。

只有系统商品SKU行允许使用后台返回的系统SKU ID进行订单下钻，避免平台卖家编码与另一商品系统编码相同而混入订单。订单页显示可取消的系统SKU限定，查询仍限定当前租户和授权订单范围。店铺SKU、SPU及分类汇总暂不提供订单下钻，不使用其中任意一个SKU代替整组跳转。

库存仍来自当前同站点授权仓的共享快照。SKU能唯一对应系统SKU、销售站点明确时可查看；SPU、分类等跨SKU汇总暂不计算库存，显示不可计算原因，避免相同共享仓SKU重复累计。未实现库存覆盖天数。

## MySQL只读兼容检查

虚拟机MySQL 8.4.10独立进程中加载本轮三个候选模块，连接设置并验证SESSION TRANSACTION READ ONLY。没有覆盖容器源码、切换服务、迁移、角色或业务写入。五种聚合SQL均执行成功：当天无记录时23条SQL、约394.26ms；现有单条销售记录日期为22条SQL，三次约104.76、97.82、94.42ms，五种维度各返回1行；库存空表探针1条SQL。已取得复杂SELECT执行计划摘要。

证据文件为交付目录中的vm-readonly-dimensions-result.json，包含源码SHA256。该结果只证明当前小样本的MySQL兼容，不是HTTP、P95、大数据或并发性能结论。精确ID下钻在本地API测试通过，未覆盖运行中的VM接口。
