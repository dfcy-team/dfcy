# 供应链微信小程序 Android / iPhone 兼容性基线

- 编号：`SC-MINIAPP-COMPAT-0`
- 日期：2026-08-08
- 状态：`BASELINE_FROZEN_FOR_INDEPENDENT_REVIEW`
- 架构：现有原生微信小程序 + 现有 Django/DRF API + 现有 JWT 小程序认证合同

## 1. 目标与边界

本基线用于保证供应链功能在 Android 微信客户端与 iPhone 微信客户端行为一致。它不允许切换为 Taro、Supabase 或另建小程序认证体系，也不允许用开发者工具模拟结果代替真机验收。

## 2. 当前必须整改的兼容风险

1. `project.config.json` 使用 `libVersion: trial`，构建结果不可重复；必须冻结经过审核的基础库最低版本与构建版本。版本不得使用 `trial`、`latest` 等漂移值。
2. `urlCheck: false` 只能用于本地调试；真机联调必须使用合法 HTTPS 域名、有效证书和微信域名白名单。
3. 全局 `box-sizing` 未完整覆盖 `input`、`textarea` 等表单组件，存在 iPhone/Android 宽度和内边距差异。
4. 页面直接使用 `gap` 时必须提供等价间距回退，不能假定所有目标基础库和客户端一致支持。
5. 底部操作区必须处理 `constant(safe-area-inset-bottom)` 与 `env(safe-area-inset-bottom)`，并提供零值回退。
6. 输入框和多行文本必须验证键盘顶起、光标、默认内边距、最大长度和页面滚动；禁止按钮被键盘或安全区遮挡。
7. 当前开发运行配置包含临时地址；仓库默认配置必须安全失败，各环境地址通过受控构建配置注入，禁止把临时隧道当作验收地址。
8. 媒体与 PDF 适配器尚未完成，不能直接把开发者工具中的选择/预览成功视为双端可用。

## 3. 编码合同

### 3.1 JavaScript 与日期

- 只使用已冻结最低基础库及构建链明确支持的语法；可选链、对象展开和 async/await 必须通过目标构建验证。
- API 时间统一使用带时区的 ISO 8601；客户端禁止解析依赖系统区域设置的日期字符串。
- 金额、数量、重量和体积由后端返回确定精度的字符串，客户端不得依赖浮点计算生成权威结果。
- 页面状态必须覆盖请求中、空数据、失败、无权限、对象版本冲突和弱网重试。

### 3.2 布局与交互

- `view`、`text`、`button`、`input`、`textarea`、`picker` 等统一使用可预测盒模型。
- 固定底栏、弹窗、标签预览和拍照页必须适配刘海屏、灵动岛、底部手势区及 Android 全面屏。
- 禁止仅使用颜色表达状态；点击目标、字号、对比度和错误提示须可读。
- 长供应商名、长 SKU、中文地址、英文/数字混排及系统字体放大不得截断关键动作。

### 3.3 媒体上传

- 优先使用运行时支持的媒体选择能力，并为低版本提供能力检测与回退。
- 图片进入后端前校验格式、大小、文件签名和哈希；后端统一处理 EXIF 方向、压缩及 HEIC 等非通用格式。
- 上传使用小程序专用上传适配器，支持进度、取消、超时、失败重试和幂等，不得把本地临时路径持久化为业务附件地址。
- 交接证据必须携带租户、供应商绑定、业务对象、附件类型和对象版本；服务端重新执行权限与状态检查。

### 3.4 中文标签与 PDF

- PDF/标签由后端权威渲染，使用已准入的四文件中文字体资产，客户端不参与排版计算。
- 小程序通过下载与文档打开能力预览，覆盖中文文件名、超时、重复打开、缓存和临时文件清理。
- Android 与 iPhone 的预览失败必须给出可恢复提示，不允许因预览失败重复生成业务标签版本。

### 3.5 认证与隐私

- 继续使用现有小程序登录、JWT、租户成员/外部供应商绑定合同。
- AppSecret、openid、会话密钥和内部权限信息不得写入小程序包。
- 相机、相册和隐私数据必须在用途告知/用户同意后调用；拒绝授权时提供重新授权或替代路径。
- 小程序页面隐藏按钮仅用于体验，后端仍须执行 Permission、DataScope、供应商绑定和对象状态校验。

## 4. 真机验收矩阵

最低矩阵必须同时覆盖：

| 维度 | Android | iPhone |
| --- | --- | --- |
| 客户端 | 当前受支持微信版本及一个较低受支持版本 | 当前受支持微信版本及一个较低受支持版本 |
| 屏幕 | 小屏、主流全面屏 | 小屏、刘海/灵动岛机型 |
| 网络 | 正常、弱网、断网恢复、请求超时 | 正常、弱网、断网恢复、请求超时 |
| 媒体 | 拍照、相册、方向旋转、大图、失败重试 | 拍照、相册、HEIC/方向旋转、大图、失败重试 |
| 文档 | 中文 PDF 下载、预览、重复打开、清理 | 中文 PDF 下载、预览、重复打开、清理 |
| 表单 | 输入法、textarea、滚动、键盘遮挡 | 输入法、textarea、滚动、安全区/键盘遮挡 |

具体机型、微信版本和基础库版本在执行时记录，不在本文件中写死“最新版本”。选择版本前须按执行当日微信官方文档和开发者工具进行复核。

每次候选构建必须生成版本清单，至少包含：Git 提交、开发者工具版本、`libVersion`、最低基础库、微信客户端版本、操作系统、机型、API 域名配置摘要及构建时间。缺少清单的真机证据无效。若官方资料无法访问，必须记录阻断，不得以非官方博客或记忆值代替版本决定。

## 5. 供应链主流程验收

两类真机都必须完成：

1. 供应商登录并只能看到绑定供应商的订单。
2. 对订单部分数量创建第一装箱批次，再创建第二批次。
3. 编辑箱明细、处理版本冲突、完成批次并打开中文标签 PDF。
4. 查看采购分配的区域、集货地点、截止时间和交接要求。
5. 拍照或从相册选择交接证据，完成上传、失败重试和重复提交验证。
6. 内部授权账号查看对应 DataScope；越权对象和接口均被拒绝。

## 6. 自动化与人工证据

- 静态门禁：页面注册、语法构建、WXSS 兼容规则、敏感信息、运行配置和域名配置检查。
- API/组件测试：认证过期、403、409、幂等重放、分页、弱网和上传异常。
- 真机证据：机型、系统、微信版本、基础库、构建提交、操作步骤、关键截图/录屏和缺陷编号。
- 自动化不能替代相机、键盘、安全区、PDF 预览和系统权限弹窗的真机人工验收。

## 7. 发布门禁

以下任一项未完成均不得进入供应链正式小程序发布：

- 未冻结可重复构建的基础库和环境配置；
- Android 或 iPhone 任一平台无完整主流程证据；
- 仍依赖临时隧道、关闭域名校验或测试密钥；
- 媒体/PDF 无失败恢复和临时文件治理；
- 权限、DataScope 或供应商绑定只在客户端实现；
- P1 缺陷未关闭，或 P2 未形成明确接受/延期决定。

## 8. 下一步

本基线与 `SCM-REQ-V2` 一并进入独立审核；审核通过后，先做公共运行时、布局、上传和 PDF 适配器，再开发多批次与散货集货页面，避免每个业务页面重复修补平台差异。
