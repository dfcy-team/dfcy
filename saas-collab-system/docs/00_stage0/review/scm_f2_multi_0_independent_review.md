# SC-F2-MULTI-0 多批次、多次发货领域契约独立审核

- 日期：2026-08-08
- 审核对象：`scm_f2_multi_0_domain_contract.md`
- 审核方式：本机静态审核，对照现有 purchasing/packing 模型、服务和 API 合同
- 结论：`PASS_WITH_P1_REMEDIATED_LOCALLY`
- 限制：未执行模型、迁移或服务编码

## 1. 审核发现

### SC-F2-MULTI-0-R1-P1-001 订单级生产进度不能安全回填到订单明细

- 问题：当前存在订单级 `completed_quantity`，不能把部分累计量无依据地分摊到 SKU 明细。
- 整改：只有整单完成可按各明细订购量回填，零完成按零回填；部分完成订单进入人工明细分配清单并阻断新装箱，不按比例猜测。
- 状态：`CLOSED`

### SC-F2-MULTI-0-R1-P1-002 集货与发运会形成同一箱两个活动消费者

- 问题：散货箱先进入集货单、后进入发运单；若分别创建消费记录，会违反整箱唯一消费约束。
- 整改：新增原子消费权转移合同，旧集货消费结束后才建立发运消费，历史用 `transferred_from_id` 关联。
- 状态：`CLOSED`

### SC-F2-MULTI-0-R1-P1-003 路线更正与已开始装箱之间缺少硬边界

- 问题：路线变更可能使既有批次和下游单据的路线语义失真。
- 整改：存在任何装箱预留、冻结 allocation 或箱消费时禁止直接更正路线，必须先受控收敛至零占用。
- 状态：`CLOSED`

## 2. P2 处理决定

### SC-F2-MULTI-0-R1-P2-001 多订单供应商批次

- 决定：保留现有一个供应商批次关联多个同供应商订单的能力；创建时必须锁定并验证全部订单、路线及 DataScope。首个编码波次至少覆盖单订单和多订单测试。
- 状态：`ACCEPTED_WITH_TEST_GATE`

### SC-F2-MULTI-0-R1-P2-002 订单摘要缓存

- 决定：首期可保留 `completed_quantity` 兼容读取，但新履约阶段不得继续添加订单级手写累计字段；统一通过明细投影汇总并提供差异检测。
- 状态：`ACCEPTED_WITH_GUARDRAIL`

### SC-F2-MULTI-0-R1-P2-003 物理拆箱

- 决定：首期不实现已完成批次的拆箱 UI/API；领域合同保留受控重新装箱边界，具体能力延期。
- 状态：`DEFERRED`

## 3. 对现有代码的确认

- `PackingBatchOrder` 当前确有 `(order, active_guard)` 唯一约束，必须分波退役。
- `PackingBoxItem` 已以采购订单明细为数量归属，可作为 allocation 汇总输入。
- 现有事件、expected version、API 幂等和受控写入机制可以复用，但需要扩展到履约投影和箱消费。
- 现有订单级生产进度不能直接满足明细级数量守恒，必须先完成兼容迁移。

## 4. 准入结论

三项 P1 已在契约层关闭，准入 `SC-F2-MULTI-1 本地模型、迁移与领域服务开发`。编码必须按既定模型路由交给 `luna-worker`，文件范围限于契约第 11 节；主代理负责复核，不与子代理重复实现。
