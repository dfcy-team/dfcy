## P1 关闭记录

| 编号 | 原问题 | 整改结果 | 主要验证 |
| --- | --- | --- | --- |
| P1-01 | 可通过直接 ORM `objects.create()` 绕过领域服务，创建非法装箱记录 | 所有装箱领域模型的新建、更新和删除均要求进入领域服务私有写入上下文；伪造旧实例标志也不能绕过 | 直接创建已完成但无箱批次被拒绝；实例写、QuerySet 更新、批量写和批量删除均被拒绝 |
| P1-02 | 幂等重放依赖当前活动对象；对象删除或后续版本变化后无法稳定返回原结果 | 重放返回事件中冻结的响应快照和原对象标识，不再查询可能已删除或已变化的活动对象 | 箱子删除后可重放原新增结果；完成后再审批变更，完成动作仍返回原版本和原箱明细 |
| P1-03 | `packing.0001` 在非空数据下反向迁移先删除受 `PROTECT` 引用的冻结标准，导致回滚失败 | 反向种子步骤改为保留标准，由后续反向建表步骤按依赖顺序移除表结构 | 独立 SQLite 数据库中创建 1 个引用冻结标准的批次后，`migrate packing zero` 成功 |
| P1-04 | MySQL 锁等待超时/死锁未转换为可重试领域错误 | MySQL 1205、1213 统一转换为 `StateConflict`，响应明确要求使用同一幂等键重试；其他数据库错误保持原样抛出 | 两类错误码映射测试通过；真实 MySQL 并发套件通过 |
| P1-05 | 供应商自助装箱/混单能力变更缺少业务审计日志 | 创建和更新能力配置均在同一事务内写入操作日志，记录操作者、对象及前后值 | 创建审计和更新审计断言通过 |
