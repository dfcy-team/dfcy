## 2. 目标

建立一套可审计、可分发、可复现、可回放的简体中文标签字体资产和渲染准入规则，使后续标签能够：

1. 正确显示已冻结字符范围内的中文、英文、数字和标点；
2. 在没有操作系统字体的隔离环境中生成 PDF；
3. 将字体来源、许可证、版本、文件摘要和嵌入规则纳入代码基线；
4. 对缺字、资产缺失、摘要漂移和渲染不确定性安全失败；
5. 保持 `packing-label-v1` 历史 PDF 的逐字节重放能力；
6. 不接触供应链正式线上系统，不影响现有协同系统功能。

## 3. 范围与边界

### 3.1 本专项范围

- 中文无衬线字体的候选、来源和再分发许可核验；
- 静态 Regular、Bold 字重文件及许可证、清单的资产包设计；
- 字体真实 SHA-256、大小、内部名称、版本和嵌入权限冻结；
- 标签字符覆盖、缺字、换行、溢出和确定性渲染门禁；
- 新旧标签渲染版本隔离和历史重放兼容；
- Windows 本机与 Linux 隔离环境的自动化验收；
- 资产异常时的事务回滚、错误语义和审计边界。

### 3.2 明确排除

- 不连接供应链正式线上数据库、对象存储、打印机或发布环境；
- 不修改或迁移正式数据，不双写、不回填、不切流；
- 不在本工作包下载字体或将系统字体复制进仓库；
- 不修改现有 API、权限、DataScope、幂等和领域状态机；
- 不直接替换 ReportLab 内置 Helvetica；
- 不开放标签模板、字体上传或客户端自定义字体能力；
- 不承诺繁体中文、少数民族文字、CJK 扩展 B 及以上、生僻字或 Emoji；
- 不包含打印机驱动、DPI 校准、纸张耗材和现场打印验收。

## 4. 当前实现和兼容基线

当前实现位于 `backend/apps/packing/labels.py`：

| 项目 | 当前冻结值 |
| --- | --- |
| `layout_version` | `packing-label-v1` |
| `renderer_version` | `sc-f2-reportlab-v1` |
| 字体 | ReportLab 内置 `Helvetica`、`Helvetica-Bold` |
| 当前摘要算法 | `SHA-256("Helvetica|Helvetica-Bold")` |
| 快照字段 | `layout_version`、`renderer_version`、`font_bundle_digest` |

现有摘要只是 v1 逻辑标识，不代表真实字体文件摘要。它必须原样保留用于历史快照，不允许把新字体摘要覆盖到旧版本。

SC-F2-2 已冻结以下兼容合同：

- 同一幂等 key 重放必须返回逐字节相同的 PDF、ETag、文件名、批次版本和状态；
- PDF 只能依赖首次事务内保存的标签快照及其冻结渲染资产；
- 新布局必须按快照中的布局、渲染器和字体包版本分派；
- 不允许旧快照隐式使用当前活动字体或操作系统字体。

因此，中文字体只能通过新版本接入。暂定版本命名建议为：

| 项目 | 候选值 | 冻结状态 |
| --- | --- | --- |
| 新布局 | `packing-label-v2-cjk` | 待实现合同审核 |
| 新渲染器 | `sc-f2-reportlab-v2-cjk` | 待实现合同审核 |
| 新字体包 | `sc-f2-label-font-v1` | 待资产取得和摘要冻结 |

上述名称不是实现授权；独立审核可要求调整，但一旦生成首个有效新快照便不得原位改变语义。

## 6. 候选与准入决定

### 6.1 首选方向

首选候选为 Noto Sans SC 的权威发布版静态 Regular 和 Bold 字重。选择理由是标签可读性、中文覆盖方向和开源再分发候选条件；但在取得权威发布包并完成下列证据核验前，不认定其已获准入：

- 权威上游页面、发布标签或不可变提交标识；
- 发布包内原始许可证文件；
- 许可证 SPDX 标识及专项审核结论；
- 原始字体文件的 SHA-256、字节数、内部 family/subfamily/PostScript 名称和版本；
- 字体技术嵌入权限；
- Regular/Bold 字重与渲染库兼容性；
- 覆盖语料缺字报告。

本机 variable font 不得替代权威静态发布资产。若最终只能采用 variable font，必须另行冻结渲染库支持、轴值、实例化方式和实例化后文件摘要。

### 6.2 暂不准入

- 微软雅黑、等线、宋体等系统字体：未提供允许随应用仓库再分发的独立证据；
- 仅由开发者机器安装、没有来源包和许可证的字体；
- 来历不明的网盘、论坛、设计稿或办公文档内嵌字体；
- 仅声明字体家族名、没有真实文件摘要的“逻辑字体包”；
- 运行时从 CDN、操作系统、浏览器或打印机临时解析的字体；
- 同一文件名下可能变化的 `latest` 下载地址。

### 6.3 许可证用途判定合同

字体资产取得后必须形成逐项许可证审核记录。审核不能只填写 SPDX，也不能用字体内部 `EmbeddingRights` 代替法律用途判定。记录至少回答：

| 用途 | 必须形成的结论 |
| --- | --- |
| 仓库 | 原始字体文件能否随应用源代码仓库再分发 |
| 应用/容器 | 字体能否进入离线安装包、应用制品和容器镜像 |
| PDF | 是否允许静态嵌入、动态子集化及分发生成 PDF |
| 子集化 | renderer 子集化是否构成修改，若构成修改须履行何种义务 |
| 名称 | Reserved Font Name 或类似保留名称是否适用 |
| 声明 | LICENSE、copyright notice、attribution 的保留位置和交付方式 |
| 修改 | variable-to-static 实例化、裁剪、格式转换或其他修改是否允许 |
| 改名 | 修改版本是否必须改名，manifest 和 PDF 内部名称如何标识 |

许可证文件必须保留上游原始字节、文件名、字节数和 SHA-256。若网页说明与发布包许可证不一致、用途结论不明确或需要额外商业授权，资产安全失败并保持不准入。

首选方案是未经修改的权威静态发布文件。任何 variable-to-static 实例化、字形裁剪、格式转换或内部名称修改均视为新的资产候选，必须重新执行来源、许可、摘要、覆盖和命名审核。

## 7. 目标资产包合同

通过资产审核后，建议资产包位于：

`backend/apps/packing/assets/fonts/sc-f2-label-font-v1/`

最低内容：

```text
sc-f2-label-font-v1/
├── <regular-static>.ttf
├── <bold-static>.ttf
├── LICENSE.txt
└── manifest.json
```

`manifest.json` 至少冻结：

- `asset_bundle_id` 和 manifest schema 版本；
- 上游项目、权威 URL、release/tag/commit 和获取日期；
- 许可证 SPDX、许可证文件名及许可证文件 SHA-256；
- 每个资产的相对路径、角色、字节数和 SHA-256；
- family、subfamily、PostScript 名称、字体版本和字重；
- 嵌入权限读取结果；
- 覆盖检查工具及版本、验收语料版本和缺字数量；
- 获准使用的 renderer/layout 版本；
- 生成和复核人不进入运行时业务快照。

字体包摘要不得继续使用字体名称字符串计算。应对规范化 manifest 中按相对路径排序的资产记录计算，记录至少包含路径、字节数和文件 SHA-256；具体规范化 JSON 算法在实现合同中冻结，并用固定向量测试保护。

资产加载必须使用仓库内固定相对路径，经解析后的路径必须位于该资产包目录内。禁止读取 `%WINDIR%\Fonts`、用户字体目录或网络路径作为回退。

### 7.1 权威资产取得与二进制安全规程

`SC-F2-LABEL-FONT-2` 必须按以下顺序执行，任何步骤失败均停止，不得把文件放入仓库：

1. 先冻结允许的 HTTPS 权威域名、项目名及不可变 release/tag/commit URL；禁止 `latest`、短链、网盘和非权威镜像；
2. 下载至仓库外新建的专项暂存目录，不安装到 Windows、不注册系统字体、不覆盖正式资产目录；
3. 记录原始 URL、所有重定向后的最终 URL、HTTP 状态、获取 UTC 时间、文件名、Content-Type、字节数和下载文件 SHA-256；
4. 下载响应最大 256 MiB；超过上限、长度未知且流量超过上限或 Content-Type 不符合预期时立即停止；
5. 若为归档，解包前检查最多 128 个条目、单条目最大 64 MiB、解包总量最大 512 MiB、最大压缩比 100:1；
6. 拒绝绝对路径、盘符、`..`、路径规范化后越界、重复规范路径、符号链接、硬链接和 reparse point；
7. 解包后先计算所有文件的相对路径、大小和 SHA-256；保留上游许可证原始字节，禁止人工改写代替；
8. 使用本机启用且签名库有效的安全扫描器扫描下载文件和解包结果，记录扫描器、引擎版本、签名版本、时间和结果；
9. 只有摘要和安全扫描通过后，才允许在无网络、非特权、只读输入、受限 CPU/内存/超时的独立进程中用锁定版本工具解析字体元数据；
10. 解析阶段不得执行字体安装、调用外部 URL、写入系统字体目录或修改原始文件；
11. 任何来源漂移、文件增减、摘要变化、扫描异常、解析崩溃、超时或资源超限均安全失败；
12. 资产准入审核通过前只保留仓库外暂存及证据记录；只有审核批准的精确文件才允许复制到目标资产目录。

取得证据必须同时记录原始下载文件摘要与最终候选字体摘要。若上游只提供单个原始字体文件，则两者可以相同，但不得省略两个语义字段。

## 8. 字符覆盖与排版门禁

### 8.1 初始验收语料

机器可判定的 v1 语料冻结在：

`docs/00_stage0/review/assets/scm_f2_label_font_corpus_v1.json`

该文件合同为：

| 项目 | 冻结值 |
| --- | --- |
| schema | `sc-f2-label-font-corpus-v1` |
| 编码 | UTF-8、无 BOM |
| Unicode 规范化 | 输入先做 NFC |
| 正向 code point 数 | 105 |
| 正向清单摘要 | `18817beaf1ec51db9464fa3225ae1c1d4631801a29237c87b3bc727273975232` |
| 摘要输入 | code point 数值升序；每行 `U+XXXX` 或 `U+XXXXXX`；ASCII；LF 结尾 |
| 重复规则 | NFC 后按 Unicode scalar value 去重 |

覆盖工具必须先校验 corpus schema、文件约束、code point 数量和清单摘要，再检查字体 cmap；输出必须包含 corpus schema、corpus 文件 SHA-256、code point 清单摘要、字体文件 SHA-256、工具及精确版本。

`positive_samples` 必须零缺字。`normalization_cases` 必须得到冻结的 NFC 结果后再进入覆盖和布局。`negative_samples` 必须按各自 `expected_reason` 拒绝，禁止送入 renderer。

零宽字符、控制字符、变体选择符、私用区、CJK 扩展 B 及以上和 Emoji 在 v1 范围内明确拒绝。该语料只定义专项初始承诺，不等价于 GB18030、全部简体中文或全部 CJK；新增字符必须升级语料版本和摘要，不得静默扩展原版本。

专项必须建立版本化语料文件，至少包含：

- 标签固定字段的中文名称；
- 常用简体中文商品名、颜色、材质、规格和包装描述；
- ASCII 大小写、数字、连字符、斜杠、括号；
- 中文全角标点、人民币符号、度量单位和乘号；
- 中英文混排、空格、长数字、批次号和箱号；
- 长文本、无空格文本、组合标点和边界长度；
- 已知不支持字符的负向样本。

“支持中文”不得只由一张人工截图证明。覆盖检查必须枚举实际 Unicode code point，并报告缺失 glyph。零宽字符、变体选择符、组合字符和代理项须由规范化规则显式处理。

Emoji、私用区、CJK 扩展 B 及以上和未冻结生僻字默认不支持。输入含未支持字符时必须在保存标签成功快照前返回明确、稳定的业务错误并回滚事件、审计日志和幂等结果；禁止静默输出方框、问号或切换系统字体。

### 8.2 布局规则

中文 v2 布局实现前必须独立冻结：

- 各字段字体角色、字号、行高、最大宽度和最大行数；
- 按字体实际 advance width 计算换行，不使用 Python 字符数截断；
- Unicode 安全的省略规则，不拆分组合字符；
- 一箱一页、箱序固定和明细顺序固定；
- 超长内容的拒绝或确定性省略策略；
- 二维码、正文和页边距的不可重叠边界；
- A4 页面和打印缩放下的最低可读性门禁。

现有 `text[:95]` 只能保留在 v1 兼容路径，不得作为中文 v2 的宽度算法。

## 9. 确定性和历史兼容策略

1. v1 renderer、Helvetica 名称摘要算法和全部历史重放测试必须保留。
2. v2 只能显式注册仓库字体资产，禁止字体发现和系统 fallback。
3. PDF 必须嵌入实际使用字体；若渲染库生成字体子集，必须锁定渲染库、字体文件、字符顺序和子集行为，并验证相同快照输出相同字节。
4. Linux 锁定依赖的隔离环境是权威生成环境；Windows 本机用于开发时不得改变产物语义。
5. snapshot 必须冻结新 layout、renderer、font bundle digest；渲染分派对未知组合安全失败。
6. 同一历史 key 在升级前后必须保持 PDF 字节和强 ETag 完全一致。
7. 不同 key 可以使用当时活动的新版本生成新快照，但不得重新解释旧快照。
8. 字体文件缺失、大小或摘要不符时应用必须在健康检查或首次使用前安全失败，不允许自动降级。

### 9.1 首次生成与历史重放原子策略

首次生成和重放使用不同但明确的事务路径：

**首次生成**

1. 当前身份、通道、permission、DataScope、供应商绑定和能力检查通过后进入最外层 `transaction.atomic()`；
2. 在事务内完成幂等记录抢占/加锁、领域读取、标签快照构造、`PackingEvent`、`OperationLog` 和待提交的 `PackingApiIdempotencyRecord`；
3. 在退出该事务前，必须使用将要保存的同一份快照和冻结 renderer 真实生成完整 PDF 字节并计算强 ETag；
4. 只有真实渲染成功，事务才允许提交；响应字节保存在进程内存中，PDF 二进制不得写入数据库；
5. 字体缺失、摘要漂移、缺字、注册、布局、子集化、二维码绘制、PDF 保存或 ETag 计算的任何异常均传播到事务外并回滚本次事件、日志和幂等记录；
6. 不允许用只做字体预检、随后在提交后再次渲染的方式替代事务内真实渲染。

**历史重放**

1. 每次重放仍先执行当前授权和能力检查；
2. 命中已提交 label 记录后不得创建事件、日志或第二条幂等记录；
3. 只使用冻结快照对应的 renderer 和字体资产重新生成 PDF；
4. renderer 异常不得修改、删除或重新解释历史记录；修复资产后相同 key 仍按原快照重放；
5. 重放结果必须与首次内存响应逐字节一致并具有相同 ETag。

实现阶段必须增加：renderer 注入异常、字体缺失、字体摘要漂移、缺字、PDF 保存异常和 ETag 计算异常的首次回滚测试，以及重放异常零写入测试。事务内渲染的锁持有时间纳入 P2 性能预算，但不能以性能理由放宽原子合同。

## 10. 自动化验收矩阵

| 类别 | 最低验收 |
| --- | --- |
| 来源与许可 | 权威来源、不可变版本、随包许可证、SPDX 和审核记录一致 |
| 资产完整性 | Regular/Bold、LICENSE、manifest 的 SHA-256 和大小逐项复核 |
| 内部元数据 | family、subfamily、PostScript、版本、字重、嵌入权限与 manifest 一致 |
| 字符覆盖 | 版本化正向语料零缺字；负向语料稳定拒绝且无 tofu/fallback |
| PDF 嵌入 | PDF 检查工具确认所用字体已嵌入，不引用系统字体 |
| 文本可检索 | PDF 文本提取覆盖中文、英文、数字和标点样本 |
| 视觉回归 | 标签逐页栅格化，检查截断、重叠、越界、二维码和最小字号 |
| 排版边界 | 中英文混排、长商品名、无空格串、最大明细数和多箱顺序 |
| 确定性 | 相同快照多次、跨进程输出相同 PDF SHA-256 和 ETag |
| 隔离环境 | 无本机字体的 Linux 环境生成成功；删除仓库字体后安全失败 |
| 历史回放 | v1 固定向量在 v2 合入前后逐字节一致 |
| 版本分派 | v1/v2 正确选择；未知 layout/renderer/font digest 明确失败 |
| 原子失败 | 缺字、字体缺失和渲染异常不留下事件、日志或成功幂等快照 |
| 安全 | manifest 路径穿越、字体替换、摘要漂移和恶意文件负向测试 |
| 性能 | 首次加载、稳态生成、PDF 大小和内存上限形成基线 |

验收工具和版本必须锁定。若使用 `fontTools`、`pdffonts`、`pdftotext` 或 PDF 栅格化工具，须加入本地/CI 可复现依赖说明，不允许依赖未记录的全局安装。

### 10.1 P2 强门禁决定

#### SC-F2-LABEL-FONT-R1-P2-001：依赖与大文件存储

状态冻结为：

`ACCEPTED_DEFERRED_WITH_PRE_ASSET_COMMIT_GATE`

不阻断仓库外权威资产取得，但阻断任何字体文件进入 Git 和 renderer 实现。资产提交前必须单独冻结并审核：

#### SC-F2-LABEL-FONT-R1-P2-002：缺字与资产异常 API 错误映射

状态冻结为：

`ACCEPTED_DEFERRED_WITH_PRE_RENDERER_CONTRACT_GATE`

不阻断仓库外权威资产取得，但阻断 renderer 实现。renderer 合同审核前必须冻结：

- 用户业务文本经 NFC 后含不支持字符的 HTTP 状态、错误码和稳定消息；
- 服务器字体缺失、大小/摘要漂移、许可证/manifest 不匹配、解析或注册失败属于服务配置或资产完整性故障，不得伪装为用户输入错误；

- 历史记录已存在但重放 renderer 失败时不得改写记录，其恢复和告警语义；
- 新错误不得破坏 SC-F2-2 已冻结的 400/409/422/500 分类，若需新增业务错误码必须先修订 API 合同并独立审核。
