# SC-F2 中文标签字体资产专项立项与审核基线

## 1. 专项标识与结论

| 项目 | 冻结值 |
| --- | --- |
| 专项编号 | `SC-F2-LABEL-FONT` |
| 当前工作包 | `SC-F2-LABEL-FONT-0` |
| 父基线 | `8cc18ae`（SC-F2-2 最终本地 API 审核归档） |
| 分支 | `codex/scm-f2-packing-local` |
| 当前阶段 | 立项、资产准入与审核基线冻结 |
| 当前结论 | `PASS_FOR_SC_F2_LABEL_FONT_ASSET_INDEPENDENT_REVIEW` |
| 实现授权 | 无 |
| 客户端融合授权 | 无 |
| 生产发布授权 | 无 |

本专项用于关闭 `SC-F2-2-R2-P2-002`。本基线只授权进入独立审核，不授权下载、复制、入库、替换、发布或部署任何字体，不改变现有标签 PDF 行为。

## 2. 目标

建立一套可审计、可分发、可复现、可回放的简体中文标签字体资产和渲染准入规则，使后续标签能够：

1. 正确显示已冻结字符范围内的中文、英文、数字和标点；
2. 在没有操作系统字体的隔离环境中生成 PDF；
3. 将字体来源、许可证、版本、文件摘要和嵌入规则纳入代码基线；
4. 对缺字、资产缺失、摘要漂移和渲染不确定性安全失败；
5. 保持 `packing-label-v1` 历史 PDF 的逐字节重放能力；
6. 不接触供应链正式线上系统，不影响现有协同系统功能。

## 3. 范围与边界

### 3.1 本专项范围

- 中文无衬线字体的候选、来源和再分发许可核验；
- 静态 Regular、Bold 字重文件及许可证、清单的资产包设计；
- 字体真实 SHA-256、大小、内部名称、版本和嵌入权限冻结；
- 标签字符覆盖、缺字、换行、溢出和确定性渲染门禁；
- 新旧标签渲染版本隔离和历史重放兼容；
- Windows 本机与 Linux 隔离环境的自动化验收；
- 资产异常时的事务回滚、错误语义和审计边界。

### 3.2 明确排除

- 不连接供应链正式线上数据库、对象存储、打印机或发布环境；
- 不修改或迁移正式数据，不双写、不回填、不切流；
- 不在本工作包下载字体或将系统字体复制进仓库；
- 不修改现有 API、权限、DataScope、幂等和领域状态机；
- 不直接替换 ReportLab 内置 Helvetica；
- 不开放标签模板、字体上传或客户端自定义字体能力；
- 不承诺繁体中文、少数民族文字、CJK 扩展 B 及以上、生僻字或 Emoji；
- 不包含打印机驱动、DPI 校准、纸张耗材和现场打印验收。

## 4. 当前实现和兼容基线

当前实现位于 `backend/apps/packing/labels.py`：

| 项目 | 当前冻结值 |
| --- | --- |
| `layout_version` | `packing-label-v1` |
| `renderer_version` | `sc-f2-reportlab-v1` |
| 字体 | ReportLab 内置 `Helvetica`、`Helvetica-Bold` |
| 当前摘要算法 | `SHA-256("Helvetica|Helvetica-Bold")` |
| 快照字段 | `layout_version`、`renderer_version`、`font_bundle_digest` |

现有摘要只是 v1 逻辑标识，不代表真实字体文件摘要。它必须原样保留用于历史快照，不允许把新字体摘要覆盖到旧版本。

SC-F2-2 已冻结以下兼容合同：

- 同一幂等 key 重放必须返回逐字节相同的 PDF、ETag、文件名、批次版本和状态；
- PDF 只能依赖首次事务内保存的标签快照及其冻结渲染资产；
- 新布局必须按快照中的布局、渲染器和字体包版本分派；
- 不允许旧快照隐式使用当前活动字体或操作系统字体。

因此，中文字体只能通过新版本接入。暂定版本命名建议为：

| 项目 | 候选值 | 冻结状态 |
| --- | --- | --- |
| 新布局 | `packing-label-v2-cjk` | 待实现合同审核 |
| 新渲染器 | `sc-f2-reportlab-v2-cjk` | 待实现合同审核 |
| 新字体包 | `sc-f2-label-font-v1` | 待资产取得和摘要冻结 |

上述名称不是实现授权；独立审核可要求调整，但一旦生成首个有效新快照便不得原位改变语义。

## 6. 候选与准入决定

### 6.1 首选方向

首选候选为 Noto Sans SC 的权威发布版静态 Regular 和 Bold 字重。选择理由是标签可读性、中文覆盖方向和开源再分发候选条件；但在取得权威发布包并完成下列证据核验前，不认定其已获准入：

- 权威上游页面、发布标签或不可变提交标识；
- 发布包内原始许可证文件；
- 许可证 SPDX 标识及专项审核结论；
- 原始字体文件的 SHA-256、字节数、内部 family/subfamily/PostScript 名称和版本；
- 字体技术嵌入权限；
- Regular/Bold 字重与渲染库兼容性；
- 覆盖语料缺字报告。

本机 variable font 不得替代权威静态发布资产。若最终只能采用 variable font，必须另行冻结渲染库支持、轴值、实例化方式和实例化后文件摘要。

### 6.2 暂不准入

- 微软雅黑、等线、宋体等系统字体：未提供允许随应用仓库再分发的独立证据；
- 仅由开发者机器安装、没有来源包和许可证的字体；
- 来历不明的网盘、论坛、设计稿或办公文档内嵌字体；
- 仅声明字体家族名、没有真实文件摘要的“逻辑字体包”；
- 运行时从 CDN、操作系统、浏览器或打印机临时解析的字体；
- 同一文件名下可能变化的 `latest` 下载地址。

## 7. 目标资产包合同

通过资产审核后，建议资产包位于：

`backend/apps/packing/assets/fonts/sc-f2-label-font-v1/`

最低内容：

```text
sc-f2-label-font-v1/
├── <regular-static>.ttf
├── <bold-static>.ttf
├── LICENSE.txt
└── manifest.json
```

`manifest.json` 至少冻结：

- `asset_bundle_id` 和 manifest schema 版本；
- 上游项目、权威 URL、release/tag/commit 和获取日期；
- 许可证 SPDX、许可证文件名及许可证文件 SHA-256；
- 每个资产的相对路径、角色、字节数和 SHA-256；
- family、subfamily、PostScript 名称、字体版本和字重；
- 嵌入权限读取结果；
- 覆盖检查工具及版本、验收语料版本和缺字数量；
- 获准使用的 renderer/layout 版本；
- 生成和复核人不进入运行时业务快照。

字体包摘要不得继续使用字体名称字符串计算。应对规范化 manifest 中按相对路径排序的资产记录计算，记录至少包含路径、字节数和文件 SHA-256；具体规范化 JSON 算法在实现合同中冻结，并用固定向量测试保护。

资产加载必须使用仓库内固定相对路径，经解析后的路径必须位于该资产包目录内。禁止读取 `%WINDIR%\Fonts`、用户字体目录或网络路径作为回退。

## 8. 字符覆盖与排版门禁

### 8.1 初始验收语料

专项必须建立版本化语料文件，至少包含：

- 标签固定字段的中文名称；
- 常用简体中文商品名、颜色、材质、规格和包装描述；
- ASCII 大小写、数字、连字符、斜杠、括号；
- 中文全角标点、人民币符号、度量单位和乘号；
- 中英文混排、空格、长数字、批次号和箱号；
- 长文本、无空格文本、组合标点和边界长度；
- 已知不支持字符的负向样本。

“支持中文”不得只由一张人工截图证明。覆盖检查必须枚举实际 Unicode code point，并报告缺失 glyph。零宽字符、变体选择符、组合字符和代理项须由规范化规则显式处理。

Emoji、私用区、CJK 扩展 B 及以上和未冻结生僻字默认不支持。输入含未支持字符时必须在保存标签成功快照前返回明确、稳定的业务错误并回滚事件、审计日志和幂等结果；禁止静默输出方框、问号或切换系统字体。

### 8.2 布局规则

中文 v2 布局实现前必须独立冻结：

- 各字段字体角色、字号、行高、最大宽度和最大行数；
- 按字体实际 advance width 计算换行，不使用 Python 字符数截断；
- Unicode 安全的省略规则，不拆分组合字符；
- 一箱一页、箱序固定和明细顺序固定；
- 超长内容的拒绝或确定性省略策略；
- 二维码、正文和页边距的不可重叠边界；
- A4 页面和打印缩放下的最低可读性门禁。

现有 `text[:95]` 只能保留在 v1 兼容路径，不得作为中文 v2 的宽度算法。

## 9. 确定性和历史兼容策略

1. v1 renderer、Helvetica 名称摘要算法和全部历史重放测试必须保留。
2. v2 只能显式注册仓库字体资产，禁止字体发现和系统 fallback。
3. PDF 必须嵌入实际使用字体；若渲染库生成字体子集，必须锁定渲染库、字体文件、字符顺序和子集行为，并验证相同快照输出相同字节。
4. Linux 锁定依赖的隔离环境是权威生成环境；Windows 本机用于开发时不得改变产物语义。
5. snapshot 必须冻结新 layout、renderer、font bundle digest；渲染分派对未知组合安全失败。
6. 同一历史 key 在升级前后必须保持 PDF 字节和强 ETag 完全一致。
7. 不同 key 可以使用当时活动的新版本生成新快照，但不得重新解释旧快照。
8. 字体文件缺失、大小或摘要不符时应用必须在健康检查或首次使用前安全失败，不允许自动降级。

## 10. 自动化验收矩阵

| 类别 | 最低验收 |
| --- | --- |
| 来源与许可 | 权威来源、不可变版本、随包许可证、SPDX 和审核记录一致 |
| 资产完整性 | Regular/Bold、LICENSE、manifest 的 SHA-256 和大小逐项复核 |
| 内部元数据 | family、subfamily、PostScript、版本、字重、嵌入权限与 manifest 一致 |
| 字符覆盖 | 版本化正向语料零缺字；负向语料稳定拒绝且无 tofu/fallback |
| PDF 嵌入 | PDF 检查工具确认所用字体已嵌入，不引用系统字体 |
| 文本可检索 | PDF 文本提取覆盖中文、英文、数字和标点样本 |
| 视觉回归 | 标签逐页栅格化，检查截断、重叠、越界、二维码和最小字号 |
| 排版边界 | 中英文混排、长商品名、无空格串、最大明细数和多箱顺序 |
| 确定性 | 相同快照多次、跨进程输出相同 PDF SHA-256 和 ETag |
| 隔离环境 | 无本机字体的 Linux 环境生成成功；删除仓库字体后安全失败 |
| 历史回放 | v1 固定向量在 v2 合入前后逐字节一致 |
| 版本分派 | v1/v2 正确选择；未知 layout/renderer/font digest 明确失败 |
| 原子失败 | 缺字、字体缺失和渲染异常不留下事件、日志或成功幂等快照 |
| 安全 | manifest 路径穿越、字体替换、摘要漂移和恶意文件负向测试 |
| 性能 | 首次加载、稳态生成、PDF 大小和内存上限形成基线 |

验收工具和版本必须锁定。若使用 `fontTools`、`pdffonts`、`pdftotext` 或 PDF 栅格化工具，须加入本地/CI 可复现依赖说明，不允许依赖未记录的全局安装。

## 12. 生产隔离

专项全过程仅在架构员主机和本地测试环境执行：

- 禁止配置或使用正式 Supabase、MySQL、Redis、对象存储和打印机凭据；
- 禁止向供应链线上系统发送请求或写入数据；
- 禁止部署、发布、切换环境变量或替换线上静态资产；
- 禁止把字体专项通过状态解释为客户验收或生产可用；
- 后续生产启用必须经过独立发布审批、回滚设计和受控环境验证。

## 14. 本轮审核出口

独立审核只能给出以下结论之一：

- `PASS_FOR_SC_F2_LABEL_FONT_ASSET_ACQUISITION`
- `REQUIRES_SC_F2_LABEL_FONT_BASELINE_REMEDIATION`

在获得第一项结论前，禁止下载或复制候选字体到仓库，禁止创建字体资产包，禁止修改标签 renderer，禁止关闭 `SC-F2-2-R2-P2-002`。
