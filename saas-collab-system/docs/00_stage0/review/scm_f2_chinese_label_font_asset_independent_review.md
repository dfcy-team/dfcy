## 4. P1 整改项

### SC-F2-LABEL-FONT-R1-P1-001：首次 PDF 渲染异常与事务回滚合同不可实现

**证据**

- 基线要求缺字、字体缺失和渲染异常不留下事件、日志或成功幂等快照；
- `execute_label_action()` 在 `transaction.atomic()` 内保存 `PackingEvent`、`OperationLog` 和 `PackingApiIdempotencyRecord`；
- 实际 `renderer(record.label_snapshot, ...)` 位于事务退出之后；
- 因此首次请求在 renderer 抛出异常时，成功标签快照和审计写入已经提交。

**风险**

中文字体注册、子集化、布局和 PDF 保存都会增加 renderer 异常点。如果保持现状，客户端可能收到 500，但同 key 已被记为成功；下一次重放仍可能失败或形成“已成功但无可交付 PDF”的记录。

**必须整改**

在基线中冻结首次生成与重放的不同原子策略：

1. 首次请求必须在最外层事务退出前完成真实 PDF 渲染和 ETag 计算；
2. 只有渲染成功后才能提交事件、日志和标签幂等快照；
3. PDF 二进制仍不得持久化，可在事务内生成后以内存响应返回；
4. 首次渲染任何异常必须回滚所有本次写入；
5. 历史重放不产生业务写入，但 renderer 异常须稳定失败，不得改写冻结记录；
6. 增加 renderer 注入异常、字体缺失、摘要漂移和缺字的原子回滚测试。

只做“字体预检”不能证明后续 PDF 保存绝不失败，不能单独关闭本项。

### SC-F2-LABEL-FONT-R1-P1-002：字体二进制取得与解析安全流程未冻结

**证据**

基线要求权威 URL、版本、文件摘要和许可证，但没有冻结下载归档本身的摘要、重定向后的最终来源、暂存隔离、文件大小上限、扫描顺序和字体解析前置条件。

**风险**

字体是由 ReportLab、FreeType 或 fontTools 解析的复杂二进制。若直接下载到运行目录或在摘要和扫描前解析，来源替换、恶意字体、压缩包路径穿越、超大文件和本机字体安装均可能越过资产审核。

**必须整改**

为 `SC-F2-LABEL-FONT-2` 增加不可跳过的取得规程：

1. 只从冻结的 HTTPS 权威域名和不可变 release/tag/commit URL 取得；
2. 记录原始 URL、最终 URL、HTTP 状态、获取时间、归档文件名、字节数和 SHA-256；
3. 下载到仓库外专项暂存目录，禁止安装到 Windows，禁止直接覆盖目标资产目录；
4. 先校验扩展名、文件数量、单文件/总大小和压缩包路径，再解包；
5. 解包后先计算摘要和执行本机安全扫描，再由锁定版本工具读取字体元数据；
6. 保留原始许可证字节及摘要，不从网页摘要或人工改写文本代替；
7. 只有资产准入审核通过后，才能把审核批准的精确文件复制到仓库；
8. 任何来源漂移、文件增减、摘要变化或扫描异常均安全失败。

### SC-F2-LABEL-FONT-R1-P1-003：字符覆盖范围不是机器可判定的冻结输入

**证据**

基线只列出“常用简体中文”“常用符号”“未冻结生僻字”等类别，没有冻结语料文件路径、schema、Unicode 规范化形式、精确 code point 集合、重复项规则或预期正负结果。

**风险**

不同审核人可以用不同样本得出相反的“零缺字”结论；候选字体选择、缺字拒绝和后续客户验收无法重放，`SC-F2-LABEL-FONT-2` 也无法生成具有客观意义的覆盖报告。

**必须整改**

在资产取得前冻结版本化验收语料合同：

1. 指定正向语料、负向语料和固定标签文案文件路径；
2. 文件使用 UTF-8，无 BOM，换行和排序规范固定；
3. 冻结 NFC 等规范化决定及零宽字符、变体选择符、组合字符处理；
4. 生成去重 code point 清单及清单 SHA-256；
5. 每个负向样本冻结预期拒绝原因；
6. 明确“语料零缺字”只代表本阶段承诺范围，不等价于整个 GB18030 或全部 CJK；
7. 覆盖工具输出必须引用语料版本和字体文件摘要。

### SC-F2-LABEL-FONT-R1-P1-004：许可证用途判定缺少子集化与保留名称检查

**证据**

基线要求许可证 SPDX 和“允许仓库分发、PDF 嵌入”，但没有把 ReportLab 可能执行的字体子集化、字体文件是否被修改、Reserved Font Name、版权/许可声明保留和衍生文件命名列为明确审核项。

**风险**

“允许嵌入”不必然等价于允许应用仓库再分发、子集化或以当前名称分发修改版本。只检查 SPDX 名称和字体内部 `EmbeddingRights` 不能覆盖实际使用方式。

**必须整改**

许可证审核记录必须逐项给出：

- 原始字体文件进入仓库的再分发权；
- PDF 嵌入和 renderer 子集化是否允许；
- 子集 PDF 是否构成修改以及对应义务；
- Reserved Font Name 或类似保留名称是否适用；
- LICENSE、copyright notice 和 attribution 的保留位置；
- 若做 variable-to-static 实例化或其他修改，是否必须改名及如何标识；
- 应用分发包、容器镜像和生成 PDF 三种载体的结论。

不接受仅填写 `OFL-1.1` 或仅读取 `EmbeddingRights=Installable` 作为关闭证据。

## 5. P2 处理决定

### SC-F2-LABEL-FONT-R1-P2-001：依赖与大文件存储策略

**现状**

- `reportlab>=4.2,<5.0` 是范围约束，当前本机实际为 `4.5.1`；
- `fontTools` 未安装；
- 仓库没有 `.gitattributes` 或字体大文件管理规则。

**决定**

不阻断资产取得规程整改，但在任何字体文件进入 Git 和 renderer 实现前必须冻结：

- ReportLab、字体检查、PDF 检查和栅格化工具的精确版本及锁文件；
- 字体资产单文件、资产包、容器镜像和生成 PDF 的大小预算；
- 使用普通 Git、Git LFS 或发布制品的决定及离线构建保障；
- CI、开发机和 Linux 权威环境的同一依赖解析结果。

状态：`ACCEPTED_DEFERRED_WITH_PRE_ASSET_COMMIT_GATE`

### SC-F2-LABEL-FONT-R1-P2-002：缺字与资产异常的 API 错误映射

**现状**

基线要求明确、稳定的业务错误，但没有冻结 HTTP 状态、错误码和安全消息；现有 SC-F2-2 合同只冻结通用 400/409/422/500 语义。

**决定**

在 renderer 实现合同审核前确定：

- 用户数据含不支持字符时使用的状态和错误码；
- 服务器字体缺失、摘要漂移或解析失败必须视为服务配置/完整性故障，不能伪装成用户输入错误；
- 错误响应不得回显整段商品名、字体本机路径或内部异常；
- 同 key 修复资产后的重试语义及是否存在成功幂等记录。

状态：`ACCEPTED_DEFERRED_WITH_PRE_RENDERER_CONTRACT_GATE`
