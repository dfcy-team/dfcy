# API 平台分层第六阶段实施说明（2026-09-02）

## 目标与操作员

面向同步值班人员，把第五阶段的异常通知扩展为可确认、可指派、可记录、可解决的事件闭环，并在 Mock/沙箱环境提供一次受控的人工重试。目标是缩短异常归属和恢复时间，同时保证处置不会演变为生产平台写操作。

本阶段仍属于 `[U 通用]` 的 L1 只读运行治理。人工重试只使用 `MockPlatformAdapter`，不调用外部平台 API，不开放生产或 `live_readonly` 重试。

## 已完成

1. 新增 `SyncAlertIncident`，以同步任务为唯一事件主体，记录状态、指派人、确认人、解决人、发生次数、最近失败运行和脱敏错误。
2. 重复失败更新同一事件并累计次数；同步成功后系统自动解决事件并归档对应通知。
3. 新增事件列表、确认、指派、备注、解决和重试预览接口，均继承租户及同步任务数据范围。
4. 事件动作写入操作日志；备注、解决说明和错误内容继续使用敏感文本清理。
5. 同步任务页新增事件工作台、状态筛选、详情抽屉、人员指派、处置备注和解决操作。
6. 工作区摘要新增待处理与已确认事件数量，便于值班人员判断积压。
7. 新增迁移 `0021_sync_alert_incident.py`，事件模型已注册到管理后台。

## 事件生命周期

- `open`：首次失败或已解决事件再次失败；允许确认、指派、备注和受控重试。
- `acknowledged`：值班人员已接手；仍可指派、备注、解决和受控重试。
- `resolved`：人工解决或一次同步成功后系统解决；不再允许重试预览或新重试。
- 同一任务始终只有一个事件记录；再次失败会重新打开并清除旧的确认、解决信息，保留发生次数和最新失败上下文。

## 接口与权限

- `GET /api/internal/integrations/sync-alert-incidents/`：需要 `integrations.view`。
- `POST /api/internal/integrations/sync-alert-incidents/{id}/action/`：确认、指派、备注和解决需要 `integrations.manage`。
- `GET /api/internal/integrations/sync-alert-incidents/{id}/retry/`：查看重试预览需要 `integrations.run`。
- `POST /api/internal/integrations/sync-alert-incidents/{id}/retry/`：确认执行受控重试需要 `integrations.run`。

所有查询先按租户过滤，再复用同步任务的数据范围过滤；跨租户用户、任务、指派人和运行记录均拒绝使用。

## 受控重试契约

重试分为预览和确认两步。预览必须显示环境、执行模式、是否调用外部 API 以及确认要求；确认请求必须显式提交 `confirmed=true` 和 8 至 100 字符的幂等键。

允许条件：

- 事件尚未解决；
- 存在对应的失败运行；
- 配置环境为 `mock` 或 `sandbox`；
- 来源不是 `live_readonly`；
- 同步任务已启用且当前不在运行。

执行时固定注入 `MockPlatformAdapter`，返回 `execution_mode=simulation` 和 `external_api_called=false`。相同事件和幂等键只产生一条运行记录；即使首次重试已解决事件，重复请求仍返回原运行结果，不再次执行。

## 安全与回滚

- 生产环境、真实只读来源、禁用任务和运行中任务全部 fail closed。
- 本阶段没有平台写适配器、写权限或外部网络调用。
- 事件错误、处置备注与审计元数据均经过脱敏，凭据和原始平台响应不会进入事件表。
- 上线顺序：先执行迁移 `0021`，再发布后端，最后发布前端。
- 回滚前先停止新版本应用流量；前端和后端可回退到第五阶段。仅在确认不再有新代码读取事件表后，才反向迁移 `0021`。反向迁移会删除事件处置历史，因此生产环境优先保留表而不是直接回退数据库。

## 两周验证

- 主指标：新事件从产生到确认的中位时间低于 10 分钟，从确认到解决的中位时间低于 4 小时。
- 护栏一：同一任务的活动事件数量不超过 1 条。
- 护栏二：人工重试产生的 `external_api_called=true` 数量必须为 0。
- 护栏三：相同事件与幂等键产生的运行记录数量必须为 1。
- 样本：至少 5 个授权、10 个同步任务、30 次定时或 Mock 运行、10 次事件处置。
- 停止条件：跨租户事件访问、敏感数据进入事件或日志、生产环境允许重试、重复幂等键产生多次运行。
