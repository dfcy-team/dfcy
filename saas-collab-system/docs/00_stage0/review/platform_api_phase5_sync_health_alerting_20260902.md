# API 平台分层第五阶段实施说明（2026-09-02）

## 目标与操作员

面向平台接入和同步值班人员：当定时只读同步出现能力缺失、来源不是首选、重试耗尽、租约过期或队列投递失败时，快速判断阻塞位置并获得一个可持续更新的异常通知，减少重复告警和人工翻查运行日志的时间。

本阶段仍为 `[U 通用]` 的 L1 只读运行治理；不启用平台写接口，不自动切换授权或修改来源优先级。

## 已完成

1. 修复产品 mock 缺失导出，恢复完整前端生产构建。
2. 同步任务页面改为消费现有 `/api/internal/integrations/workspace/?mode=sync-jobs`，展示任务、调度、能力、来源和最近错误状态。
3. 工作区健康计算加入能力门禁状态：`ready`、`capability_missing`、`source_not_selected`、`authorization`、`unsupported`。
4. 工作区摘要加入能力阻塞任务和当前同步告警数量，并按用户数据范围统计。
5. 最终同步失败、租约过期、调度队列投递失败及运行前置校验失败会生成操作员通知。
6. 同一同步任务只保留一个未解决告警；重复失败刷新原告警并重新标为未读，成功运行后归档。
7. 告警内容使用既有敏感文本清理逻辑，不写入凭据、Token 或原始平台响应。

## 决策和处置流程

输入为同步任务、绑定授权、能力矩阵、来源优先级、调度状态和最新运行结果。系统先计算能力及来源状态，再计算任务健康，最终输出阻塞原因、最近错误和通知。

- `capability_missing`：人工核对 OAuth scopes，再到店铺能力矩阵载入或配置只读能力。
- `source_not_selected`：人工核对候选授权及 `source_priority`；系统不自动改绑凭据。
- `retry_exhausted`：检查脱敏错误、授权有效期和查询范围后，由有权限人员决定重试或停用。
- `stale running / LEASE_EXPIRED`：检查 Worker 和锁心跳，不直接删除运行记录。
- `SCHEDULER_ENQUEUE_FAILED`：检查 Celery/队列可用性；原到期时间会恢复，避免静默漏跑。

## 安全与权限边界

- 健康页只复用 `integrations.view` 受控工作区接口，不增加公开接口。
- 告警接收人为集成配置创建者，租户与数据范围保持隔离。
- 未解决告警包括 unread/read；只有成功同步会自动归档。
- 调度失败不会升级为平台写操作，也不会绕过能力门禁、凭据托管或来源选择。
- 页面保留的执行动作仍只有既有 `run-mock` 和内部任务 `disable`。

## 两周验证

- 主指标：同步异常从产生到明确阻塞原因的中位时间低于 10 分钟。
- 护栏一：同一任务同时存在的未解决同步告警不超过 1 条。
- 护栏二：因告警处置触发的平台写操作数量必须为 0。
- 样本：至少 5 个授权、10 个同步任务、30 次定时或 mock 运行。
- 停止条件：跨租户告警、敏感数据进入通知、成功运行未归档告警、或调度失败后到期时间丢失。
