## 1. 目标与边界

本阶段验证采购完工后路线指定、部分装箱、多批次、多次发货、散货区域集货、供应商交接证据、拼柜发运、报关、发货、到岸、到仓和清货的人工业务闭环，以及柜货继续进入既有柜货流程的分流正确性。

UAT 只允许本机合成数据和本地服务，不连接供应链正式系统，不导入生产订单或供应商，不发送真实通知，不启用生产对象存储、下载票据、货代、报关、船司、承运商或微信正式环境。

## 2. 固定验收角色

| 角色 | 身份 | 最小职责 | 权限原则 |
|---|---|---|---|
| UAT采购员 | internal | 完工确认、散货/柜货路线指定、查看采购履约 | 仅采购与路线动作，禁止集货和发运写入 |
| UAT装箱协调员 | internal | 创建和维护部分/多批次装箱 | `supply.packing.*` 所需最小集合 |
| UAT集货员-A | internal | 华南站点集货、收货、异常和转发运 | 仅授权站点/供应商/订单/批次/集货维度的完整 CUSTOM scope |
| UAT发运员 | internal | shipment 创建、分配、报关、分批 dispatch、到岸、到仓、清货 | `supply.shipment.*` 所需最小集合和完整 shipment scope |
| UAT只读审计员 | internal | 查看订单、集货和发运事件 | 只有 view 权限，不授予动作权限 |
| UAT供应商-A/B | external | 查看本人 assignment、提交本人 accepted 交接证据 | supplier binding 与 capability 分开控制；不得查看对方数据 |
| UAT越权主体 | internal/external | 负向权限、跨租户和跨供应商测试 | 不得使用超级管理员代替 |

角色不得共享账号。所有账号使用本地短期密码，验收完成后停用；证据中不得保存密码、Token、Cookie 或 Session。

## 3. 固定合成数据集

| 数据组 | 数量与标识 | 用途 |
|---|---|---|
| Tenant | `SC-UAT-A`、`SC-UAT-B` | 正向与跨租户防枚举 |
| Supplier | A租户 `SUP-A/SUP-B/SUP-C`；B租户 `SUP-X` | 多供应商聚合、绑定和隔离 |
| 区域/站点 | `CN-SOUTH-01`、`CN-EAST-01`；另设未生效站点 | 区域归集、站点有效期和跨站点拒绝 |
| 采购订单 | `PO-L-001..004` 散货候选；`PO-C-001` 柜货候选 | 分流、部分履约、多批次/多次发货 |
| 订单明细 | 每单 2 条，每条数量 10 | 6+4 部分装箱、超量和守恒检查 |
| 装箱批次 | 同订单至少 2 个活动批次 | 多批次、部分完成、取消竞争 |
| 物理箱 | 至少 8 箱 | 多供应商集货、部分 transfer 和同箱唯一消费 |
| 附件 | JPEG/PNG 合成图片；拒绝样本、隔离样本各 1 | 扫描、accepted、release version 和泄露检查 |
| 集货主单 | 华南 2 单、华东 1 单 | 多订单/多供应商归集和分批 ready |
| Shipment | 同一集货来源至少 2 个 shipment | 部分 transfer、多次 dispatch、单次 shipped |

所有业务编号使用 `SC-UAT-` 前缀；文本、地址、图片和联系人均为明显虚构内容。禁止使用真实公司名称、手机号、地址、快递单、报关单或业务截图。

## 4. 数据生成与清理合同

1. 数据必须由后续独立的 `SC-SUPPLY-FLOW-UAT-1` 受控生成器创建，不允许手工 SQL、生产库复制或直接 ORM 绕过领域服务生成业务状态。
2. 生成器必须要求显式环境确认和独立数据库名称，默认拒绝非 SQLite/本机隔离 MySQL；不得读取正式 `.env`。
3. 重复执行必须幂等：相同数据版本只重放，不重复创建；不同 payload 必须冲突停止。
4. 每个对象必须可由 tenant、`SC-UAT-` 编号和数据版本定位；事件和附件账本不得物理删除或篡改。
5. 清理使用独立受控命令，只清理指定 UAT tenant；先停用账号，再按依赖顺序清理可删除数据。不可变事件若因外键保护保留，则停用 tenant 并记录保留原因。
6. 清理前后记录对象计数，不执行模糊匹配、跨 tenant 删除或递归文件系统删除。

## 5. 核心验收场景

| 编号 | 场景 | 预期 |
|---|---|---|
| UAT-01 | 采购下单时不指定路线，完工前尝试指定 | fail-closed，不改变订单 |
| UAT-02 | 完工后采购指定散货，再进行受控更正 | 版本、原因和事件完整；并发仅一个结果 |
| UAT-03 | 完工后指定柜货 | 不进入散货集货模型，继续既有柜货路线 |
| UAT-04 | 同订单明细按 6+4 建两个活动装箱批次 | 数量守恒，允许部分完成 |
| UAT-05 | 超量、同箱双消费、完成/取消竞争 | 整批回滚或单一终态，无重复消费 |
| UAT-06 | 供应商 A/B 分别查看 assignment | 只见本人数据；未知或他人资源返回 404 |
| UAT-07 | capability 关闭时提交交接 | 403/拒绝；开启后仅 accepted 当前 release 证据可提交 |
| UAT-08 | 恶意 MIME、超限、解码失败或扫描异常 | rejected/quarantined，不能用于交接 |
| UAT-09 | 后端采购按区域归集多供应商箱 | 站点有效、scope 完整、快照稳定 |
| UAT-10 | 跨站点箱分配和一好一坏批量分配 | 全部拒绝并回滚 |
| UAT-11 | 分批收货、异常、恢复、ready | ready 只接受全部有效箱 RECEIVED |
| UAT-12 | 同一集货来源部分转入两个 shipment | 箱消费权唯一，不提前增加 shipped |
| UAT-13 | 报关引用为空、超长或状态跳跃 | fail-closed，状态不变 |
| UAT-14 | 两次 dispatch 不同箱集合及同键重放 | 只对本次箱单次增加 shipped，重放不重复计数 |
| UAT-15 | 到岸、到仓、清货顺序 | 严格按状态机推进并保留操作者/时间 |
| UAT-16 | ALL、完整 CUSTOM、残缺 CUSTOM、OWN、DEPARTMENT | 仅 ALL/完整 CUSTOM 准入聚合写动作，其余拒绝 |
| UAT-17 | 跨 tenant、跨 supplier、通道混用 | 404/403 防枚举，Web supplier 与 MiniApp 互斥 |
| UAT-18 | expected_version 过期、Idempotency-Key 同键异 payload | 409/冲突，数据不变 |
| UAT-19 | Android/iPhone 窄屏、中文标签、空/错/离线状态 | 布局可读，错误不伪装成功；上传关闭时明确提示 |
| UAT-20 | 审计复核 | 路线、装箱、附件、集货、转移和发运事件可串联且不可修改 |

## 6. 证据与判定

每项只能记录 `PASS`、`FAIL`、`BLOCKED` 或 `NOT RUN`，证据前缀为 `SC-UAT-{case}-{date}`，并包含 Git SHA、数据版本、角色、环境、步骤、预期、实际、request_id 和脱敏截图。截图不得包含认证材料或真实个人信息。

以下任一项发生即整体 FAIL：跨租户/跨供应商泄露、同箱双消费、提前或重复 shipped、状态跳跃、附件绑定可由客户端伪造、幂等同键异 payload 被接受、真实系统连接、数据无法按版本识别。

## 7. 准入与退出门禁

进入 UAT-1 前必须完成：本合同独立审核通过、固定 Git SHA、生成器设计审核、独立数据库确认、账号/权限矩阵确认和生产连接扫描。UAT-1 只允许实现本地数据生成/清理命令与自动校验，不启动真实用户操作。

完成 UAT 后仍不自动准入 Sandbox、Pilot 或 Production。下一环境必须遵守现有 Sandbox 合同，并另行完成制品、网络、迁移演练、备份恢复、回滚、安全扫描和审批。
