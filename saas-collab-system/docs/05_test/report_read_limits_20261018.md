# 报表读取上限分层与验收

基线：阿里云 V2.44.249，提交 f4acd8bd02663db2097726b9115a6bf4f2ed98df。本文是候选运行规范，不变更现有运行参数。

| 用途 | 限制位置及当前决策 | 超时后行为 | 验收指标 |
| --- | --- | --- | --- |
| 临时生产只读诊断 | 仅诊断连接使用 MySQL SESSION max_execution_time=5000；不 SET GLOBAL | 记录参数化 SQL、执行计划及失败阶段，停止该查询 | 单条 SQL 时间、扫描/返回量；与 HTTP/整次检查时间分开 |
| 筛选目录和分页明细 | 保留现有接口保护；优化后按代表角色/范围测量，再确定接口预算；不统一新增 5 秒 SQL 截止 | 显示明确错误及重试；不返回示例选项、伪空值或扩大范围 | 首次/缓存、P50/P95、查询数、分页正确性、租户和店铺拒绝用例 |
| 默认工作台摘要 | 小范围摘要优先汇总与权限隔离缓存；重查询可转后台 | 各卡片独立状态、显示已查询范围和来源；旧值明确标识 | 首屏、各卡片响应、缓存一致性、汇总与明细口径 |
| 全年/月周/跨平台汇总 | 现有后台分析任务 soft=110s、hard=120s；本候选不改变 | 独立终态，支持取消与恢复；不依靠长 HTTP 连接等待 | 提交/轮询、排队、执行、总完成时间分别统计；并发配额与取消释放 |
| 异步导出 | 现有导出任务 soft=110s、hard=120s；生成与下载分开预算 | 失败不显示已完成；文件过期、鉴权、共享存储分别处理 | 生成耗时/行数/字节、下载完整性、过期和撤权拒绝、大文件代表样本 |

5 秒是诊断保护，不是交互服务 SLO；110/120 秒是现有任务运行限制，也不是所有规模任务均可完成的保证。新增业务时限前须根据数据量、并发、队列和资源测量决定。软时限应允许写入失败终态及清理，硬时限保留收尾余量。用户取消不等于 SQL 已停止，需核对实际 worker 状态。

依据 database-optimizer、django-expert 及项目 .agents/skills/report-read-performance：先测真实调用链和执行计划，逐项修改，保留权限、排序、空值、分页和数据口径；不通过增加超时、猜测索引或全局缓存掩盖慢查询。不套用 PostgreSQL 的 EXPLAIN BUFFERS/CONCURRENTLY 到 MySQL。

当前性能证据仅为受控单次进程内 DRF 调用，不含公网浏览器，也非并发 P95。候选未部署。
