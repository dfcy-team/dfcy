# TK 发起店铺回填候选验证

日期：2026-10-23。候选基于 PR #369 / 9b462a9f5df356fdaf82c59c0b60e8dc9307f62f。

## 流程与范围

授权发起时服务端会话锁定租户、用户、SaaS 店铺和接入配置。回填沿用该会话目标，不接受仅靠客户端店铺编号或名称指定落库目标。

已有可信平台店铺 ID：平台返回身份严格匹配后自动保存。首次绑定：取得有效会话归属证据后查询平台店铺，用户选择并确认才落库；即使只有一个候选也不跳过确认。首次绑定无需预填平台店铺 ID。

缺失 state 且没有可信平台店铺身份的首次绑定仍拒绝。界面隐藏 state 技术说明，不删除后台校验。跨用户/租户、过期、重复提交、身份不匹配及清理保护保持原有约束。

本次完善目标店铺结果展示及闭合字段的失败诊断，复用 PR #369 的后端分阶段诊断。无数据库迁移、无广告授权、菜单、权限和部署配置改动。

## 正式验证步骤（待发布负责人执行部署后）

1. 核对候选包含 PR #369 后端诊断；记录实际前后端版本。不要只部署提示文案。
2. 从 TK1PH / ET Living Store 对应的 SaaS 店铺发起新授权，保留原标签页；不要重用会话 171 或已公开授权码。
3. 在原标签页接收或回填完整新回调。首次绑定核对返回候选的平台店铺身份后确认。
4. 成功时核对显示的目标店铺和后台授权记录；只绑定预期店铺，不以页面成功推断同步已成功。
5. 失败时只保存受控错误码、阶段、分类和诊断编号；不复制 code、Token、密钥或原始回调 URL。先核对状态，不自动重试兑换。
