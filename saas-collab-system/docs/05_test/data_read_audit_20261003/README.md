# 阿里云正式系统数据读取优化验收

本候选针对已核验的阿里云正式系统 V2.44.215，基线与运行容器均为 `2141d8069ab210d4f5874dd8441622064ed4d423`。正式 MySQL 为 8.4.11；本地合成数据验证使用 MySQL 8.4.10。正式系统尚未发布本候选，远端数据库及文件写入为 0。

以 `cloud-scope.json` 的当前模块开关为准，排除 product_development、supply_chain、global_listing、rpa。平台商品明细仍属于启用的基础档案模块，未按 listings 后端应用名错误排除。

`coverage.csv` 保留全部 174 条路由定义，其中 33 条停用范围已明确排除；其余包含 133 条静态数据链路映射、3 条重定向、4 条静态页、1 条布局。静态链路映射不代表已对所有页面完成运行时或正式环境压测。

## 已实施的候选

报表目录和保存视图在一次请求内共用权限解析缓存，下一次请求重新检查授权。工作流先分页，再一次读取本页的审计事件。仓库页批量读取本页最新库存快照、连接状态和按权限过滤的 API 元数据。商品详情在数据库中排序和分页，仅缓存本页键；CSV 按 500 行读取并预取关联对象。成本仓库选项只投影实际需要的四个字段，保留完整选项集合。

没有修改数据库结构、菜单、路由、指标定义或模块开关。

商品详情冷页将回传/缓存的键从整个候选集合缩到 page_size；新测试以 149 个候选验证仅读取 7 个键。MySQL 配对样本中页面查询数和时延没有稳定改善，下一页多 1 次查询；不能把内存改善写成页面时延收益。CSV 的数据库/模型输入分批，但原 HttpResponse 仍缓冲全部输出字节。

`reports-before.json`/`reports-after.json`、`warehouses-before.json`/`warehouses-after.json`、`workflow-mysql-evidence.json`、`product-detail-mysql-evidence.json` 保存实际配对采样。EXPLAIN JSON 位于仓库和商品详情证据中。仓库最新快照仍有排序，商品混合流仍需数据库排序；没有新增猜测索引，也不声称减少了正式数据库扫描行数。

这些是本地合成数据结果。正式账号无 performance_schema 摘要 SELECT 权限（1142），没有调整账号权限；正式 P95、扫描行数、并发容量和上线后收益均未测量。

## 验证与限制

去重后 320 项 MySQL 测试通过；29 项前端定向测试、前端构建、权限快照及 surface 检查通过。Django check 无问题，makemigrations 检查无漂移，项目性能 skill 校验通过。覆盖分页、空集、无效页、混合排序、CSV 字节、同资源 ID 的跨租户事件隔离和下一请求的权限撤回。

扩大成本回归时 34 项 MySQL 通过、1 项跳过、2 项既有夹具无法在该引擎成立：一项依赖 MySQL bulk_create 不提供的主键回填，另一项尝试插入受大小写不敏感唯一约束禁止的 SKU。两个测试都在到达修改接口前失败；SQLite 对照两项通过。没有为消除失败而改动产品约束或这些测试。

本地新建 MySQL 测试库时，既有 development.0002 的 CREATE VIEW/RunPython 原子事务问题使用任务临时 settings 绕过；发布的 migration 源码未改。原始命令日志保留在任务 `.codex-tmp/read-audit-*.log`，汇总为 `qa-summary.json`。

浏览器使用真实本地 API 和合成账号验证报表目录、保存视图打开和查询，接口返回 200，无错误覆盖层。唯一控制台错误为既有 favicon.ico 404。浏览器证据不代表正式环境真实用户验收。

## 保留的观察

销售跨事实合并页需要完整授权组来计算币种汇总和趋势，本候选保留这些统计口径；全面 SQL 合并重写需要独立的逐指标配对验收。达人价格查询存在 `(tenant, listing, external_sku, variant_id)` 唯一约束，前次“无界历史版本”的判断已纠正；完整变体查询和仓库选项不擅自截断。

## 复现入口

项目 skill 位于 `.agents/skills/report-read-performance/SKILL.md`。其 `scripts/` 下四个 probe 仅接受本地 `read_audit` MySQL 数据库，拒绝其他数据库；在 backend 目录运行，设置隔离 MySQL 配置和 Django settings。报告/仓库 probe 的输出文件为命令行参数。工作流/商品 probe 通过 `git show` 在本地进程加载历史基线以做配对比较，这不是永久测试的依赖。正式数据和凭据不得用于这些合成 probe。

发布与回滚步骤见 `docs/06_release/data_read_optimization_20261003.md`。
