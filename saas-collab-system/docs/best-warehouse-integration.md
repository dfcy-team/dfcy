# GLINK 全接口本地交付（2026-11-19）

本节为当前状态；后面的 ECAPI 及分阶段记录保留用于追溯，不代表当前协议。

- 依据用户指定的千易 WMS 文档，目录覆盖全部 30 个唯一服务类型：26 个主动请求（16 个只读、10 个写入），4 类平台回调。订单查询 V2 和批量查询使用同一个服务类型，不重复登记。
- 主动请求均可从「仓库档案 → API 接入 → 百世仓库接口」选择、预览及手动执行；使用服务器托管的凭据签名。工单 ownerCode 和库存快照 whCode 按实际文档转换，客户、仓库及明细归属必须匹配当前授权。
- 写入必须通过服务器写开关、用户权限、人工确认和持久化幂等记录；网络超时保留 unknown，不自动重发。调用能力未开启时页面仅允许预览。接口执行不自动生成本地库存、采购或财务单据。
- 四类回调：入库单反馈、订单反馈、库存调整反馈、工单反馈。接收路径为 `/api/platform/best/glink/<integration_config_id>/`，ID 是接入配置 ID，不是仓库 ID 或授权 ID。
- 回调使用 POST 表单 partnerId、serviceType、bizData、sign；按原始 bizData 的 UTF-8 内容加托管密钥验签，校验当前配置及同租户已验证仓库、业务必填字段和嵌套归属。重复内容去重，只有原始反馈成功持久化后才返回 success=true。凭据字段不进入业务原始记录。
- 反馈收件箱可在仓库页面查看，按租户和仓库数据范围隔离。回调先保留为「已验签接收，未自动入账」，不自动改写真实库存、实收或财务；已有主动查询入库事实链继续适用。
- `BEST_GLINK_CALLBACKS_ENABLED` 默认 false；本轮未开启真实写入或真实回调，也未修改同步计划、客户凭据和仓库绑定。
- 30 个服务类型的覆盖指协议、请求入口与回调接收实现，不能视为所有业务单据自动化或真实平台全量联调通过。真实写接口、真实推送、页面视觉验收仍需单独完成。
- 热修复交接包由主对话按当时云端实际基线合并、构建、发布。共享文件含本地其他改动时必须按补丁合并，禁止用本地整站构建覆盖云端。

## 本地仓库业务链补齐（2026-11-19）

- 世洋仓业务时间由用户明确确认为中国时间，配置 `business_time_zone=Asia/Shanghai`；不带偏移的百世时间按此转换为UTC，仓库国家仍为MY。未确认的其他配置不自动套用。
- 入库只读同步已支持GLINK分页查询。仅将已上架完成且有明确行号、数量、时间的记录写入共享InboundRecord；未完成记录不会当作实收。采购、退货、调拨按实际asnType区分。

- 已核对的出库时间及退货上架时间按已确认口径转换，可进入原有成本日期链。包裹明细空归属继承已验证主记录，明确归属冲突仍拒绝。
- 授权中心增加百世，凭据维护及连接验证进入百世仓库接入，不使用极风Token兑换。
- 仓库费用仍走现有原始文件/格式规则/订单匹配与人工核对流程，不宣称有百世API账单自动同步；实际仓库账单需按原文件验证格式。

# 百世仓配 API（2.0）接入

## 本地入口

基础档案 → 仓库档案：选择“三方仓”，服务平台选择“百世（BEST）”，保存实际仓库后打开“API 接入”。
填写百世提供的 partnerID、partnerKey、客户编码、仓库编码和正式 HTTPS 网关。
密钥交由现有凭据托管服务保存，页面不回显。保存后显示“已配置 · 待验证”，不会启用同步。

## 实现范围

- 使用既有仓库授权、租户及仓库权限、审计和库存快照模型。
- 21 个主动请求操作通过既有仓库业务接口目录、预览、执行入口路由到百世协议客户端；操作名称以 `best_ecapi.OPERATIONS` 为准。
- POST 表单包含 partnerID、serviceType、bizData 和签名；XML 原文加 partnerKey 计算 MD5，签名后才进行表单编码。写请求不自动重试。
- 库存拓展查询按显式 `sku_codes` 范围每批最多 50 个。创建库存同步任务须提供 SKU 列表，修改范围须新建任务。缺少数量、非整数库存和重复 SKU 均报错，不默认为零或截断。
- 本次未实现百世主动推送的回调接收，也未把所有业务响应自动导入采购、出入库等业务单据。不能把协议请求适配等同于完整业务闭环。

## 出库与售后业务适配（2026-11-14）

- 销售订单仓库查询支持百世：按订单日期到当前日期分段查询 `WMS_SO_LIST_QUERY`，完整校验分页后按 `extCode` 精确匹配平台订单号。保留客户、仓库、出库单和包裹归属校验；超过请求上限或分页异常不发布部分结果。
- 包裹商品缺失时调用 `WMS_SO_STATUS_QUERY`，使用返回的实际 SKU 与数量；整单数量不复制到每个包裹。`DELIVERED` 才视为已出库，取消或未发货状态不计算出库成本。
- 售后新增独立“仓库退货单号”，通过 `GET_RMA_STATUS_REQ` 查询经人工核对的百世退货单。平台退货单号、运单号不能自动充当该号码。只有仓库及退货单号唯一匹配才关联实收，重复查询不重复分配数量。
- 实收数量取良品与不良品数量之和，取消单不形成实收；缺失或小数数量报错，不转成零。
- 已确认成本冲回以 `wmsUpdateTime` 上架完成时间为准。当前退货查询只有 `receiveTime`，因此只保存实收数量，不生成成本冲回日期。已收齐数量的单据不会反复查询一个接口未提供的时间字段。
- 百世无时区的时间尚未确认时区，出库成本日期暂不推定。退货推送接收尚未实现，不能宣称已取得上架完成时间。
- 本地启用需迁移 `sales_management.0010_aftersales_warehouse_return_no`。本次没有调用真实百世 API，也不改变云端配置。
- 当前 3001 环境使用独立兼容迁移目录，对应 `local_migration_compat.sales_management.0014_aftersales_warehouse_return_no`，已执行并核实字段存在；不能在该环境直接按源码编号回退迁移。后端及订单仓库查询工作进程已重启。

官方依据：[出库列表](https://open.800best.com/doc/api/63647/64211)、[出库状态](https://open.800best.com/doc/api/63647/64162)、[退货状态查询](https://open.800best.com/doc/api/63647/64279)、[退货状态推送字段](https://open.800best.com/doc/api/63647/63763)。

## 真实联调限制

### 退货上架推送开发状态

已新增 `best_business.putaway_receipt` 业务字段解析与隔离测试。仅接受当前客户及仓库的 `putaway` / `FULFILLED`，取 `wmsUpdateTime` 而不是 `receiveTime`；无时区时间尚未确认解释方式时拒绝用于成本日期。复用实收链路的重复处理测试确认不会重复分配数量，后续无完成时间的主动查询不会清除已保存日期。

此函数不负责验签，不是公网回调接口，当前没有任何 HTTP 路由调用它。官方回调签名规则、成功及失败回执、重试机制、`orderCode` 与查询返回 `rmaCode` 的标识一致性、推送明细是全量还是分批，以及无时区时间均需继续核实。核实前不开放真实回调、不自动写入真实实收或成本。本轮官方原文档标签连接超时，新标签空白，未以查询协议猜测推送协议。

本地 `BEST_ECAPI_ENABLED` 默认关闭，保存配置同时关闭该配置的网络及同步开关。没有真实百世请求或数据补采。
后续真实联调需配置有效凭据及网关、现有网络白名单和托管审批，显式开启运行开关及配置的只读网络权限。
首次检查只允许库存查询；普通业务执行仍要求已验证授权。写操作还受既有写入开关、权限、确认和幂等控制。

验收包括离线签名、表单、XML、权限隔离、凭据不回显、库存分页及数量校验，以及既有极风仓库回归。
真实服务响应、客户与仓库编码、各业务报文字段仍需使用百世实际账户完成联调验证。
