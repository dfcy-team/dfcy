# 权限治理四阶段交付

基线为 V2.44.208（5da096f）。本变更补齐原分析方案的四个阶段，保持历史角色和环境配置独立。

## 第一阶段：生命周期和会话

权限目录支持 active、inactive、retired；停用权限保留角色历史关联，服务端和 `/auth/me` 不再授予。导航隐藏只影响入口，不撤销有效操作。同步检查输出孤儿、历史关联和受影响账户聚合指标，默认只展示20条异常。前端定期核对授权版本，刷新失败暂停敏感操作。

## 第二阶段：岗位和授权工作台

现有 Role 的 template 类型作为可复用岗位模板，内容版本覆盖操作、基础范围与资源策略。有效权限提供授权角色、来源、组织、到期时间和范围解释。调岗与离职先生成十分钟签名预览，再按目标授权和模板版本原子提交。调岗只替换选定来源的租户绑定；离职停用账户及全部绑定，旧访问和刷新令牌失效。变更落 PermissionChange 和操作审计，重复批次幂等。管理员移除共享租户锁并保留至少一名有效管理员。

审批、导出、排队任务及共享 RPA/API 凭据列入离职核对清单；已有下载入口继续重新校验操作者。共享凭据与外部会话须按归属人工交接，系统不会自动删除共有凭据。

## 第三阶段：组织上下文和资源范围

新增 OrgMembership，扩展原 UserRole 为来源、上下文、状态和到期时间绑定；历史行默认 legacy/tenant/active，无需复制角色授予。未选择组织时只使用租户绑定；选择有效组织后叠加该组织岗位。每个请求检查成员所属租户、账户、部门和有效期，下载请求携带同一组织上下文。

RoleResourcePolicy 覆盖平台明细、仓库授权及基础平台/站点/店铺/仓库/供应商；未配置资源继续使用原 DataScope。同一策略内维度取交集，多个有效授权取并集，操作级策略优先于资源通配策略。策略自身不授予操作。范围ID逐项检查同租户，非法或空自定义范围拒绝。平台策略覆盖时基础仓库、供应商限制保留。

## 第四阶段：稳定目录和发布门禁

108个菜单保持原权限编码，新增显式稳定 menuPermissions；142个路由快照不变。98项历史迁移种子操作/字段由可重复本地迁移数据库提取，合入运行目录，避免正式环境已有业务权限被误判孤儿。菜单、操作、字段、接口HTTP方法和前端检查引用均生成版本清单。

`sync_permissions --check --strict-orphans --report-json`、`check_permission_manifest --check`、`npm run permissions:check` 和 `npm run permissions:surface:check` 检查目录/声明/引用漂移。特殊认证、渠道和对象权限保留现有处理器，不将其自动改造成新增业务授予。任何清单变化须同时提供差异并接受代码审查。

## 迁移与发布

唯一新迁移：permissions.0049_authorization_bindings_resource_policies。迁移添加新表及 UserRole 字段、替换唯一约束，不删除历史授予。发布前备份数据库；运行完整CI、检查迁移计划并使用CI不可变镜像摘要。先验收虚拟机，再校对阿里云并发布同一SHA镜像，各环境保留本环境角色、范围及业务记录。

回退应用前暂停新组织/多来源授权写入。旧版代码不能解释新增组织与资源策略；不得直接反向迁移丢失绑定。数据库恢复需使用本次备份和明确恢复范围。
