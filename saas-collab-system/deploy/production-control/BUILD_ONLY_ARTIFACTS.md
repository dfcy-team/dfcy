# Controlled production artifacts without deployment

The separate `Production Artifacts Build Only` manual workflow publishes production-format immutable images and a schema-1 manifest. It does not call a VM/cloud entrypoint, migrate a business database, register a release, or move deployed pointers. The existing production release workflow and recipes remain unchanged.

The exact source must equal the dispatch revision on protected `main`, descend from the registered V2.44.220 commit `87ef1377164a525750a870cb863b28cd03d6d759`, and pass the existing baseline/credential/backend/SQLite migration/frontend gates. Publication additionally requires real MySQL 8.4.11 / Django 5.2.17 / READ-COMMITTED execution of all 9 lock-scope, 131 capability/task/range/credential and 6 expected-preflight rejection regressions with zero failures and zero skips. SQLite-only CI deliberately skips the 9 MySQL-specific cases; it cannot replace the MySQL gate.

The MySQL suite uses an ephemeral synthetic current-model schema (`--nomigrations`). Unchanged `development.0002` view DDL fails a fresh MySQL atomic migration; this workflow explicitly does not certify a fresh MySQL installation. Existing permission migration functions seed only synthetic dictionary fixtures, with no role, grant, or data-scope injection. No production credentials or business data are used.

Builds retain the production Dockerfiles, OCI revision/source labels, maximal provenance and SBOM. Unique SHA/run/attempt tags avoid overwriting previously published tags; release consumers must use the recorded `@sha256` references. The built backend must match the tested Django version and approved migration-tree hash. Redis is unchanged and must equal the approved immutable digest.

The artifact includes `release-manifest.json`, its raw-byte SHA-256 in `build-only-receipt.json`, and MySQL aggregate/JUnit evidence. The identical `git_sha` and `release_sha` fields retain the existing CI format and control-plane metadata compatibility. `compose_sha256=owner-controlled-on-target` is the existing contract, not proof of the target's actual Compose. Subsequent production release must independently verify the target and explicitly pass the source SHA, image digests, `migration_sha256`, and the raw manifest hash to the existing deployment CLI. Building does not authorize that deployment or close a failed production ledger/log gate.
