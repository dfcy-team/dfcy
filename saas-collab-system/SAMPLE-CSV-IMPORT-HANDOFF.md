# 送样 CSV 导入交付说明

## 操作流程

送样履约 → 导入送样 → 上传 CSV → 按订单预览 → 填写达人昵称、送样类型 → 处理异常 → 确认导入。

- 同一订单的多行 SKU 合并展示，展开后查看 SKU、数量、商品与仓库明细。
- 预览不创建达人、送样或成本记录；只有确认导入才写入。
- 送样负责人为当前导入用户，不接受文件指定负责人。
- 本次支持独立送样，不要求建联任务编号。
- 只提供昵称时，唯一匹配现有达人；同名多档案必须选择；没有档案时在确认阶段创建待补全档案，不将昵称伪装为平台账号。

## 校验口径

- 重复订单按样品订单号判断，不按店铺组合；跨权限范围只提示重复，不返回其他租户或用户的记录详情。
- 同一订单多行是明细，不视为重复订单；店铺等订单属性冲突必须修正。
- 首版每个订单仅支持一个商品 ID、一个发货仓库；同商品多 SKU 可合并。多商品或多仓库订单列异常，不擅自拆单或归到第一个商品。
- 同一达人、同一商品在送样日期前 30 天内重复送样，提示异常，由用户明确确认并填写原因；同批次也检查。
- 店铺、国家、SKU、仓库必须符合现有权限和业务校验，不能借导入扩大权限。
- 订单号及商品 ID 按文本处理。异常或不可确认的数字不得猜测修复。
- 成本沿用系统仓库与有效成本版本，不信任文件中的金额。
- 发货状态根据来源状态与时间判定，不能因为有订单号就自动认定已发货。
- 首版仅支持北京时间（UTC+8），用户须明确勾选文件时区确认；其他时区文件先转换后再导入。来源时间保留，不能以导入时间替代实际发货时间。

## 发布边界

本次仅提交代码、测试与说明。不提交真实 CSV、达人数据、导入结果或凭据。

部署需保留线上已有热修，先记录实际文件摘要并备份，再执行范围内增量更新。正式版本号由发布人员统一分配，不复用已发布 PR，也不自行编造版本号。
